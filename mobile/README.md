# Trina AX mobile

An independent Expo SDK 58 wrapper around a team's HTTPS web app. The neutral app asks for a team URL or invitation URL; only the origin is saved in SecureStore. Login, invitations, password changes, attachments and file selection use the existing web UI and its session cookie. The Trina edition (`MYCEL_MOBILE_EDITION=trina`) is the store app `app.trina.ax`; what the owner provides for the stores is in [STORE-SUBMISSION.md](STORE-SUBMISSION.md).

## Development

Install from this directory with `npm ci --ignore-scripts --no-audit --no-fund`. This package has its own `package-lock.json` and `node_modules`; do not add its React Native dependencies to the root workspace. Use Node `^22.18.0 || ^24.3.0 || >=26.0.0`, within React Native 0.88's supported range. Expo's dynamic config imports a TypeScript helper and requires Node's default type stripping; do not disable it. Node 22.22.0 is verified. Node 25 is outside the supported range.

Run `npm run typecheck` and `npm start` from this directory; from the repository root `bun run typecheck:mobile` installs this package's locked dependencies and typechecks it (CI runs it too; the root `bun run typecheck` leaves `mobile/` out). The repository's sanitized test runner can execute the pure bridge tests without starting Expo, contacting a team, or using a provider:

```sh
python3 .validation/run.py mobile-bridge --fixture-id mobile-bridge --timeout 60 bun test tests/unit/mobile-bridge.test.ts tests/unit/mobile-security.test.ts tests/unit/mobile-push.test.ts tests/unit/mobile-photos.test.ts web/test/unit/mobile.test.ts
```

From the repository root, `bun test tests/unit/mobile-*.test.ts web/test/unit/mobile.test.ts` runs the same tests; `tests/unit/push-native.test.ts` covers the server side of push and `tests/unit/push-gateway*.test.ts` the gateway.

### iOS build without Expo's services

No Expo account or EAS project is used. `MYCEL_MOBILE_EDITION=trina npx expo prebuild --platform ios` writes `ios/` (ignored). `scripts/ios-release.sh` does the store build on a Mac with Xcode: prebuild, `xcodebuild archive` with automatic signing and an App Store Connect API key, export for App Store Connect, and with `--upload` `altool --validate-app` and `--upload-app`:

```sh
ASC_KEY_ID=<key id> ASC_ISSUER_ID=<issuer id> ASC_KEY_PATH=<outside the repo>/AuthKey_<key id>.p8 BUILD_NUMBER=<n> scripts/ios-release.sh --upload
```

The key stays where it is; the script only passes its path. `BUILD_NUMBER` must grow with every upload. `eas.json` is optional and unused. A simulator build: with `MYCEL_MOBILE_EDITION=trina` exported (Expo's "Generate app.config" build phase reads it again inside xcodebuild, and the app reads that config at runtime), prebuild, then `xcodebuild -workspace ios/TrinaAX.xcworkspace -scheme TrinaAX -configuration Release -sdk iphonesimulator -derivedDataPath build/sim CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM= build`. Keep it signed (ad hoc): an unsigned build cannot use the keychain, so SecureStore fails to save the team address.

Exact versions are locked in `package.json`/`package-lock.json`. The selected SDK 58 modules match the installed Expo package's `bundledNativeModules.json` compatibility ranges. SDK documentation may recommend a newer patch; this package does not claim to track latest versions automatically.

### Android App Bundle for Google Play

`scripts/android-release.sh` builds the signed `.aab` locally (Android SDK in `ANDROID_HOME`, JDK 17):

```sh
ANDROID_KEYSTORE_PATH=<outside the repo>/upload.jks ANDROID_KEYSTORE_PASSWORD=… ANDROID_KEY_ALIAS=… ANDROID_KEY_PASSWORD=… BUILD_NUMBER=<n> scripts/android-release.sh
```

It exports the edition and build number for the whole run, prebuilds, runs `./gradlew bundleRelease`, and stops unless the bundle's embedded app.config is the edition (name, package, versionCode) and the bundle is signed by that upload key (certificate SHA-256). The signing config comes from `plugins/release-signing.js`, which makes Gradle read the four variables; no key, path or password is written into a file, and the keystore must lie outside the repository. versionName is the app's version (1.0.6, `app.config.ts`), versionCode is `BUILD_NUMBER`, target SDK 36 (compile SDK 37, which the SDK 58 modules require; Gradle downloads that platform if it is missing). Without `MYCEL_MOBILE_GOOGLE_SERVICES` the Android app has no push: no permission prompt, no token request (`pushBuilt()`), nothing else changes.

## Native/web contract

`window.mycelMobile` is installed only in the top document after a trusted page load. Protocol `1` requires both `file-share-v1` and `external-oauth-v1`, an app version, platform, random 256-bit document nonce, and generation. `push-token-v1`, `push-registered-v1`, `push-permission-v1`, `appearance-v1`, `nav-v1`, `share-text-v1`, `photo-pick-v1` and `badge-v1` are optional: an app or page without them keeps working (push off, or the fallbacks below). Unsupported/legacy bridge objects do not grant native capabilities. Web login sends `client: mobile` only when this contract is present.

Every message and acknowledgement carries protocol version, transfer/request ID, nonce and generation. The native receiver additionally checks the WebView event's source URL against the chosen HTTPS origin, and the script that delivers a reply runs only in a document whose bridge has the reply's nonce (`src/bridge.ts` `replyScript`): a page that loaded in the meantime drops it. Page navigation, team changes and logout fence old work immediately. The web adapter captures its session epoch before its first asynchronous wait, so an old operation cannot resume under the next session.

File export uses `file-begin` (name, MIME, declared size, SHA-256), sequential `file-chunk` (`seq`, base64), then `file-end` (`seq`). The web side waits for each acknowledgement. The receiver serializes every native write and verifies actual bytes and SHA-256 before opening the OS share sheet. A transfer is limited to 50 MiB, a chunk to 3 MiB, one active transfer, four reserved queue entries, 200 transfer IDs per document/session, and 60 seconds idle time. Oversized downloads are stopped while streaming even if Content-Length is absent or wrong. Partial/error/expired/finished transfers are removed from app cache. Startup removes leftover app transfer cache.

The team invite message goes to the phone's own share sheet with `share-text` (capability `share-text-v1`: a text of at most 4,000 characters, the same origin, nonce and generation checks; React Native's `Share.share`). Android's WebView has no `navigator.share`, so an app without the capability gets the page's copy button there; the iPhone app's WebView has `navigator.share`, which the page uses until then (`web/src/lib/share.ts`).

The page's 사진 보관함 (the attach sheet's photo library row, `web/src/components/chat/AttachSheet.tsx`) asks the app for the phone's own photo picker with `photo-pick` (capability `photo-pick-v1`, from 1.0.5; `src/photos.ts`, `src/photo-io.ts`, `web/src/lib/mobile.ts` `pickPhotosFromApp`). On the iPhone an input that takes pictures first shows WebKit's small menu (Photo Library / Take Photo / Choose File); the app opens PHPicker instead, and on Android the system photo picker (`expo-image-picker` `launchImageLibraryAsync`, pictures and videos, several, in the order picked, at most what the message box still takes). Neither asks for access; a refusal (an older Android picker) is the reply error `photo_denied` and a short message. The reply names the picked files (safe name, shortened before its extension when long, picture or video type but never SVG, size; never a path or a URL); the page then asks for the bytes with sequential `photo-chunk` (`seq` over the whole pick, file `index`, byte `offset`), each answered with exactly that many base64 bytes (1 MiB chunks, small for `injectJavaScript`), and ends with `photo-done`, which deletes the app's copies. Cancelled is an empty list and no message. Limits: 50 MiB a file (the room upload limit), 200 MiB and 20 files a pick; larger files are left out and named in `tooBig`. One pick at a time. The picker and the share sheet (share-text-v1) open through one gate (`src/sheet.ts`): not while either is up, nor within 1.5 s after one closed, so a page cannot reopen them without a tap. Further, a chunk out of order or of the wrong length ends the pick, 60 seconds without a chunk end it, and page navigation, a session reset or a team change fence it like a file transfer (also when the picker answers after the fence). iOS returns HEIC as JPEG (`preferredAssetRepresentationMode: compatible`) re-encoded at 0.9, which drops location and other metadata; Android sends the original bytes, as the file input did (re-encoding there would turn a GIF or a WebP into a still PNG). Startup empties the picker's cache folder. A file left out for its size in a box that takes bigger files (the AI chat, the side chat; a room takes 50 MB) gets a message whose button opens the page's photo input (WebKit's picker reaches the library and has no such limit). While the bytes come the page counts as busy, so an update does not reload it. An app without the capability: the page clicks its file input, as before.

The cache uses `await File.write(...)`: SDK 58's [FileSystem API](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/) returns a promise. A native write must finish before hashing/sharing. SecureStore's plugin keeps its default [Android backup exclusion](https://docs.expo.dev/versions/v58.0.0/sdk/securestore/).

Back follows the page's screens (`nav-v1`, `src/nav.ts`, `web/src/lib/appNav.ts`). The page sends `nav` (`canGoBack`, `home`) whenever its screen or its top overlay changes, again when the bridge comes and after a session reset: `canGoBack` when a sheet or dialog is open (Back closes it) or its tab's stack has a screen under this one, `home` on the start tab or a page in no tab. The iOS edge swipe (`allowsBackForwardNavigationGestures`) is on only while `canGoBack`. Android's Back goes back in the page while `canGoBack`, at the root of another tab dispatches `mycel:start-tab` (the page shows the start tab, as a tap on it does), and on the start tab's root leaves the app. A notification tapped while the page is loaded dispatches a cancelable `mycel:open` `{path}`: the page opens an id path with its router (no reload, Back returns to where the person was) and cancels it; when nothing cancels it (a server from before nav-v1, or any other path) the same script loads the path. Until the document on screen has sent `nav` (an older server, a page still loading) the app keeps the WebView's own history: the swipe on, Back while the WebView can go back. There is no pull-to-refresh: the page is live, and a pull at the top of a room reloaded the whole app.

WebView navigation permits the selected HTTPS origin. Other HTTPS pages open externally; custom schemes, credentials in URLs, file/data/about top documents and external child frames are refused. Same-origin blob previews are allowed only when identified as child frames. `originWhitelist=['*']` deliberately sends all navigation to this policy: WebView's own default rejection path would otherwise call `Linking.openURL` for an arbitrary unmatched scheme.

## Push notifications

After sign-in (never at first launch) the web page (`web/src/lib/mobile-push.ts`) asks the app what the OS said so far (`push-permission`, capability `push-permission-v1`: `granted`, `undetermined` or `denied`, never a prompt). Granted: it registers without a word. Not asked yet: the page shows its own question above the tab bar ("새 메시지와 @트리나 답을 알림으로 받을까요?" [알림 켜기] [나중에]); [나중에] puts it away for a week and, the second time, for good (Settings › Notifications keeps the button). Denied: Settings › Notifications and the 나 list say so and offer [설정에서 켜기] (`open-settings`, the app's page in the phone's Settings); coming back to the app checks again. An app without that capability (store builds 1 and 2) gets the question until it has given a token once on this phone, then registers quietly at later sign-ins. Only [알림 켜기] (or Settings) sends `push-token`; the app shows the OS permission prompt if the person has not answered yet and replies with `push: { platform, token, environment }` (APNs hex token or FCM token from `getDevicePushTokenAsync`; `sandbox` for development-signed iOS builds, otherwise `production`), or `push_denied` / `push_unavailable`. The reply passes the same origin, nonce and generation checks as file transfers and is dropped after logout or navigation. The page registers the token with its own team (`POST /api/push/devices`, bound to the session; logout removes it with the session). It does not register again by itself after the person turned push off; Settings › Notifications turns it on again. When the app offers `push-registered-v1`, the page then sends `push-registered` with the team's device id and a removal key; on a team switch (also from the cannot-reach screen) the app removes the device from the old team with that key (`POST /api/push/devices/:id/remove`), retrying at later starts if that server is unreachable (`src/device.ts`). The switch also signs out of the old team (`src/leave.ts`): its page clears its web storage and posts `/api/auth/logout` with its own session, then the app clears the WebView's cookies and storage; a sign-out the server did not confirm is remembered and done first on the next visit to that team. The team server sends through a push gateway (`push-gateway/`), never to Apple or Google itself, by default `https://push.trina.app` on Trina servers (the operator can set another or turn it off with `push.gatewayUrl` / `MYCEL_PUSH_GATEWAY`); the gateway's notifications carry generic text only.

The app icon shows the page's one count n (the tab title's and the Mac Dock's number: AI chats that need the person and rooms that want them), from 1.0.5 (`src/badge.ts`). The OS question asks for the badge with alerts and sounds; an iPhone that said yes before 1.0.5 is asked once more, which iOS answers without a dialog (if it keeps Badges off, Settings › Notifications turns it on). While the app is closed a push sets the number (the team server counts it for the recipient at send time; the gateway puts it in `aps.badge`; on Android the launcher counts the notifications in the tray). While the page is open it sends its own count with `badge` (capability `badge-v1`, a whole number 0 to 9999): when it changes, when the bridge comes, after a session reset and every time the app comes to the foreground; the iPhone app sets it with `setBadgeCountAsync`. A sign-out and a team change set 0. Android never sets a number (not even 0): expo-notifications' 0 there only cancels the notifications and never clears Samsung's number, so the launcher's own count of the tray notifications is left alone (QA TC-408, build 11). A number only; nothing about what it counts.

Tapping a notification opens its `path` on the current team only if it is an id path (`/rooms/<id>`; no scheme, host, `//`, `..`, query or fragment), its `device` is the one registered with this team, and it arrived after this team was chosen. Changing team clears delivered notifications, and so does signing out (the page's `session-reset` says `signedOut`: a sign-out, an expired session, the sign-in page at a cold start, or another person's session). In the foreground a notification goes to the list without a banner. Android push needs the owner's `google-services.json` (`MYCEL_MOBILE_GOOGLE_SERVICES=<path>` at build time); without it Android logs one line and push stays off.

### Who and where on the iPhone (1.0.1)

A room push on the iPhone shows who and where ("민준 · #마케팅 › 스레드", a DM "민준"), the same title as a browser push, never the message's text; the gateway never sees a name (docs/DECISIONS.md "아이폰 알림의 이름"). The gateway marks a room push mutable; the notification service extension `<bundle id>.NotificationService` (`plugins/notification-service.js` adds it at prebuild, Swift in `plugins/notification-service/`) asks the saved team `POST /api/push/devices/<device>/label` with a label key, only for a room push of the device this app registered with that team, over https, without cookies or redirects, within 5 s, and otherwise shows what Apple delivered. The key is made on the phone (`src/labels.ts`): the `push-token` reply of an app offering `push-label-v1` carries only its sha256 (`labelHash`), which the page registers with the token. The key, the team's origin and the device id are one keychain item in the group `<team id>.<bundle id>.notifications`, which only the app and the extension have (the app lists its own group first, so its other keychain items are not shared), readable after the phone's first unlock and never backed up. It goes on a team change, a sign-out, a reinstall and at a launch that finds it stale. Only an edition with `appleTeamId` has the extension; Android stays generic.

## Native screens and permissions

The page is drawn edge to edge: it fills the status bar and the home indicator / navigation bar in its own colours and pads itself (`env(safe-area-inset-*)`, plus the `--app-inset-*` CSS variables the app sets before each page loads, because Android's WebView reports no insets; `web/src/index.css` `--safe-top` / `--safe-bottom`). The page tells the app its look (`appearance`, capability `appearance-v1`) and the status bar text follows it; native screens use the web app's light or dark tokens (`src/look.ts`), the page's look once it said, the phone's before. On Android the app lifts the page above the keyboard itself (edge to edge, the window no longer shrinks for it). Setup, offline ("인터넷에 연결되어 있지 않아요") and cannot-reach-team screens use Korean when the phone's first language is Korean and English otherwise (`src/strings.ts`); both have Try again and Change team address. The web app keeps its own locales. iOS has camera, microphone and photo library usage strings in both languages (attachments and voice input in chat; `expo-image-picker`'s config plugin gets the same strings, never its English defaults); the WebView grants camera/microphone only to the team's own host. Android declares CAMERA and RECORD_AUDIO for the same uses: its WebView has no per-origin grant, but only the team's origin is ever a top-level page and a cross-origin frame cannot ask unless the team page delegates it (Permissions Policy). SYSTEM_ALERT_WINDOW is blocked.

## Google Drive connection

The web integration calls `openExternal(url, {purpose: 'google-oauth'})`. The only accepted OAuth destination is `https://accounts.google.com/o/oauth2/v2/auth` without credentials, another port, or fragment. Native opens that HTTPS URL in the system browser with `Linking.openURL`; generic external pages use `WebBrowser.openBrowserAsync`.

The external browser must be signed into the **same Trina AX user** for the server's OAuth callback. WebView and external-browser cookies are not assumed to be shared. After Google consent, the user manually returns to the app; the original app session polls its flow, displays the account and explicitly completes the connection. No code, refresh token or app-return token crosses this bridge. Native app foreground dispatches a focus event to refresh polling. This design does not require an app OAuth callback scheme. [Expo WebBrowser's cookie behavior](https://docs.expo.dev/versions/v58.0.0/sdk/webbrowser/) is why an embedded browser modal is not treated as an authenticated cookie-sharing session.

## Editions and validation boundary

`app.config.ts` accepts only the fields `name`, `accent`, `userAgent`, `scheme`, `bundleId`, `background` and `appleTeamId`, validated by `src/product.ts`, from `editions/<name>/branding/mobile.json` when `MYCEL_MOBILE_EDITION=<name>` is set (otherwise `config.extra.teamAxEdition`), plus the fixed files `icon.png`, `adaptive-icon.png` and `splash-icon.png` in `editions/<name>/branding/mobile/`. Team server URLs, permissions, credentials and executable hooks are not edition settings. Without an edition the source keeps neutral Team AX defaults and the development bundle identifier `app.teamax.mobile.dev`; the default accent is the Trina orange (`#e8521a`, with the button label in warm black, `accentInk()`). The Trina edition is `app.trina.ax`, iPhone only, version 1.0.6 with the build number from `MYCEL_MOBILE_BUILD_NUMBER`. No distribution certificate, API key, store account, medical branding or deployment credential is in the repository.

The focused tests cover serialization, forged/outdated messages, generation reset, cancellation, sequence/size/hash failures, timeout cleanup, navigation policy, streamed download bounds, browser fallback and photo picks (order, exact lengths, limits, cancel, fences, copies deleted). The browser mock covers mobile login classification, file-input upload, CSV bridge bytes and photos from a fake app's picker landing in an AI chat and a room (`web/test/e2e/phone-photo-picker.spec.ts`). These are not actual iOS/Android device tests.

Before distribution, verify on both platforms: a real push from the gateway (permission after sign-in, generic text on Android, on the iPhone the room push's title says who and where with the team on the new release and the generic text with an older one, tap opens the path, logout stops it and clears the notifications), the offline screen, camera/microphone in chat, initial/invite login, cookie persistence and session revocation, uploads through the native picker, 사진 보관함 through the app's photo picker (photo-pick-v1: on the iPhone PHPicker opens at once with no WebKit menu first, on Android the photo picker; several photos and a video over 1 MiB arrive whole in an AI chat, a room, a thread and the side chat; a HEIC photo arrives as a .jpg; cancel adds nothing and says nothing; a video over 50 MB is left out with the short message; a box with files already stops the picker at what it still takes; an iCloud-only photo comes down; against an app before 1.0.5 the row opens the file input as before), at least two download chunks with exact hash, share-sheet cancellation, back/keyboard/safe areas (nav-v1: no edge swipe at a tab's root, Android's Back from 대화's root to the start tab then out of the app, Back closing an open sheet first, a notification tapped with the app open opening without a reload and Back returning to the screen before, no reload when pulling down at the top of a room; and against a server from before nav-v1, the swipe and Back as before and a tapped notification still opening), team changes, external Google consent/cancel/same-user browser login/manual app return, and Android child-frame blob previews. Build/signing/store setup remains separate. Logout cancels pending transfers but cannot retract an already opened OS share sheet or copies the user has shared to another app.
