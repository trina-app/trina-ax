- Fewer cards in a chat that has read a room (the ✦ side chat, or your own chat after "이 방 봐줘"). A connected service's read that the service marks read-only (a Notion or Gmail search) runs with no card, as Drive's reads do; what it sends goes to the service you or your team connected. An HTTP API's read (a GET) still asks, since some APIs change something on a GET. When what it sends holds a web address or a long random-looking string, it asks first as before. A move or copy that would put a skill or instruction file in place is still refused. A connected service's write, a scheduled task, a video, moving or copying files, moving a skill and connecting a service now ask on one card (and Trina's card for posting to a room carries the same line), their own, with the line "여기에 대화방 메시지(다른 사람이 쓴 글)가 들어와서, 무언가를 바꾸기 전에 먼저 물어봐요." on top, instead of the room card and then their own. There a team connection set to send without asking asks too, and so does a move that changes nobody's access; a connection set to refuse still refuses. Rooms, shared and confidential chats and scheduled runs are unchanged. New optional `lead` on the connect_service card. In all five languages.
