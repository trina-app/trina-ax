# 보안과 권한

[English](security-and-permissions.md)

“입사 정책을 요약해 줘”라는 같은 질문이라도 인사 폴더 권한이 있는 사람만 그 파일을 읽을 수 있습니다. 서버가 파일 요청마다 질문한 사람의 접근 권한을 확인합니다. 스킬은 접근할 수 있는 지침일 뿐 권한을 추가하지 않습니다.

소유자는 팀과 AI 연결을 설정합니다. 앱 관리자는 허용된 관리 기능과 작업 기록을 볼 수 있지만 모든 사람의 개인 채팅을 읽는 화면은 없습니다. 서버 OS·저장소를 운영하는 사람은 저장된 파일과 채팅을 읽을 수 있습니다. 호스팅이면 트리나 운영자도 포함됩니다.

질문, 관련 대화 기록, 답변에 쓰는 파일·도구 내용은 선택한 모델 제공사로 전송됩니다. 이미지도 마찬가지입니다. AI가 사진·화면 캡처·스캔한 PDF 페이지를 읽으면 이미지를 직접 봅니다(격리된 변환기에서 디코딩하고 위치 정보 같은 메타데이터는 지움). 관리자가 팀 설정의 "이미지·PDF 페이지·영상 장면을 AI에게 보내기"를 끄면 보내지 않습니다. AI가 읽는 영상(Linux 서버)도 고르게 고른 장면이 같은 길로 갑니다. AI가 읽는 영상·오디오 파일의 소리는 관리자가 허용했을 때만 팀의 음성 제공자가 글로 바꿉니다(팀 설정 › 음성 입력의 "영상 소리를 글로 바꾸기"; 제공자가 이 서버면 기본 켜짐(CPU 코어 2개 이하 서버는 기본 꺼짐), OpenRouter면 기본 꺼짐, 제공자를 바꾸면 그 제공자의 기본값부터 다시 시작). OpenRouter를 쓰면 팀 파일의 소리(회의 녹음, 고객 통화, 교육 영상)가 OpenRouter와 그 제공사로 갑니다. 데이터를 남기지 않도록 요청하지만 제3자에게 하는 요청이라 서버가 강제할 수 없습니다. 기밀 대화에서는 소리를 내보내지 않습니다(서버가 이미 만든 받아쓰기는 쓸 수 있음). 받아쓰기는 서버 데이터 폴더에 내용별로 최대 30일 보관합니다(백업에는 들어가지 않음). 받아쓰기도 파일 속 글처럼 파일 내용이지 사람의 지시가 아닙니다. AI에게 그렇게 알리며, 걸러 내지는 않고, AI가 거기서 알게 된 내용에도 다른 파일과 같은 공유 범위 확인과 연결 검사가 적용됩니다. 기본 연결에서 Claude는 Anthropic, Codex는 OpenAI를 사용하며 실험용 API 엔진은 별도로 설정한 제공사를 사용할 수 있습니다. 외부 연동 요청도 해당 서비스로 갑니다. 직접 설치가 오프라인 AI 처리를 뜻하지는 않습니다. AWS 서울은 팀 서버의 위치이며 제공사의 AI 처리까지 한국 안에서 이루어진다는 보장은 아닙니다. 제공사의 보관·학습 정책을 이 프로젝트가 보장하지 않으므로 허용된 계정·서비스의 조건을 확인하세요.

트리나가 호스팅하는 서버에서는 음성 입력과 영상·오디오 파일의 소리가 기본으로 OpenRouter(미국)를 거쳐 DeepInfra(미국)로, DeepInfra가 안 될 때는 Groq(미국)로 갑니다. 호스팅이 팀에 준 키는 이 두 제공사, 이 음성 모델 하나, 데이터를 남기지 않는 처리(zero data retention)만 허용하고, OpenRouter에 적힌 두 제공사의 정책은 학습에 쓰지 않고 입력을 남기지 않는다는 것입니다. 팀마다 한 달에 소리 10시간까지 포함됩니다. 키는 호스팅의 것이며 팀 서버에 암호화해 두고 보여 주지 않습니다. 팀 서버는 그 키로 보낸 소리의 초만 셉니다(소리나 글은 남기지 않음). 팀이 자기 OpenRouter 키를 넣으면 그 키를 대신 쓰며, 팀의 OpenRouter 계정과 설정을 따릅니다. 관리자는 음성 입력이나 "영상 소리를 글로 바꾸기"를 끌 수 있습니다. 기밀 대화에서는 소리를 보내지 않습니다.

Codex 웹 검색은 검색할 때마다 지금까지의 대화 내용을 OpenAI의 검색 서비스로 보냅니다(ChatGPT 로그인은 chatgpt.com, API 키는 api.openai.com). Claude의 웹 검색이 Anthropic으로 보내는 것과 같습니다. 기밀 채팅과 승인된 템플릿 실행에서는 검색하지 않습니다.

서버는 시작할 때와 30분마다 트리나 업데이트 피드(`https://updates.trina.app/ip`)에 자기 공인 주소를 묻습니다. 그래서 피드는 그때마다 서버의 주소를 봅니다(업데이트 확인 때도 봅니다). 서버 환경 파일에 `MYCEL_EXIT_ADDRESS_CHECK=off`를 넣으면 묻지 않습니다. 그때는 AI가 여는 웹 주소마다 사람에게 묻고, 예약 작업은 웹 주소를 열지 않습니다.

AI는 Claude Code처럼 큰 요청의 일부를 다른 AI(하위 작업, 한 번에 최대 4개)에게 나눠 맡길 수 있습니다. 나눠 맡은 AI도 같은 사람으로 일합니다. 사람에게 묻기·기억·예약·브라우저를 뺀 같은 도구를 쓰고, 파일 요청마다 같은 권한 확인과 같은 확인 카드를 거치며, 작업 기록에도 어느 하위 작업의 호출인지와 함께 남습니다. 관리자는 팀 설정의 "AI가 일을 나눠 맡기기"로 끌 수 있습니다.

서버가 추적한 제한 자료를 더 넓은 대상의 폴더에 쓰려고 하면 확인을 요청합니다. 이는 모든 외부 전송·사람의 복사를 통제하는 기능이 아닙니다. 권한을 회수해도 이전 답변에 인용된 내용은 지워지지 않습니다. 보안 인증이나 무유출을 보장하지 않습니다.

Linux·역할 계정 Mac은 전용 엔진 계정과 OS 격리를 씁니다. 사무실 Mac은 로그인 사용자로 실행되고, 개발 모드는 운영 수준의 계정 격리가 아닙니다. [상세 권한](PERMISSIONS.md) · [IT 안내](for-admins.ko.md).

새 팀의 구독 공유는 기본 켜짐이며 기존 저장 설정은 유지됩니다. 개인 연결이 우선이고 연결별 동의가 필요합니다. 소프트웨어 설정은 제공사 약관상 허가가 아닙니다. 허용된 계정·요금제만 사용하세요.

보안 문제는 [비공개 신고](../SECURITY.md)로 알려 주세요.
