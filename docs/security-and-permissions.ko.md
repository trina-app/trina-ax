# 보안과 권한

[English](security-and-permissions.md)

“입사 정책을 요약해 줘”라는 같은 질문이라도 인사 폴더 권한이 있는 사람만 그 파일을 읽을 수 있습니다. 서버가 파일 요청마다 질문한 사람의 접근 권한을 확인합니다. 스킬은 접근할 수 있는 지침일 뿐 권한을 추가하지 않습니다.

소유자와 앱 관리자는 팀의 AI 연결을 설정합니다(추가·교체할 때 비밀번호는 묻지 않습니다. 연결마다 정해진 제공사 주소로만 가기 때문입니다. 관리자가 바꾸면 소유자에게 알림이 갑니다. 주소를 직접 정하는 팀 API 엔진은 본인 비밀번호를 계속 다시 묻습니다). 업데이트·복원·팀 이름은 소유자만 합니다. 멤버 삭제는 소유자와 관리자가 합니다. 소유자는 자기 말고 누구나, 관리자는 일반 멤버만 지울 수 있고 관리자는 자기 비밀번호를 다시 입력합니다. 지운 멤버의 개인 폴더는 소유자의 개인 폴더로 옮겨져 소유자만 읽습니다(API로는 대신 지울 수 있음: `personalFolder=delete`). 앱 관리자는 허용된 관리 기능과 작업 기록을 볼 수 있지만 모든 사람의 개인 채팅을 읽는 화면은 없습니다. 서버 OS·저장소를 운영하는 사람은 저장된 파일과 채팅을 읽을 수 있습니다. 호스팅이면 트리나 운영자도 포함됩니다.

팀원은 링크로 들어옵니다. 초대 메일은 보내지 않습니다. 1회용 초대 링크는 관리자가 고른 역할과 그룹으로 계정 하나를 엽니다. 팀 초대 링크(관리 › 멤버)는 여러 명이 쓰는 링크 하나로, 단체 대화방에 올리는 용도입니다. 이 링크로 들어온 사람은 모두 멤버이고 팀장이나 관리자가 고른 그룹에 들어갑니다. 정한 인원까지만 받으며(기본은 요금제의 남은 자리, 요금제 인원 한도를 넘을 수 없고 가입할 때마다 빈자리가 있어야 함) 7·14·30일 뒤에 멈춥니다. 링크의 비밀 부분은 주소의 `#` 뒤에 있어서 브라우저가 서버·프록시·다른 사이트로 보내지 않고, 가입 화면은 이를 요청 본문으로만 보냅니다. 한 링크로 하는 가입 시도는 어디서 오든 15분에 30번까지이고, 가입할 때마다 작업 기록과 팀장 알림에 남습니다. 링크를 끄거나 새 링크로 바꾸면, 또는 만든 사람이 더 이상 초대할 수 없게 되면 링크는 멈춥니다. 서버는 링크를 데이터베이스 밖의 열쇠로 암호화해 보관하므로 관리자는 같은 링크를 다시 복사할 수 있고, 데이터베이스 사본만으로는 링크를 열 수 없습니다. 링크에 팀 스킬을 붙일 수 있으며, 새 팀원은 폴더 권한으로 그 스킬을 읽을 수 있을 때만 그 화면으로 바로 갑니다.

질문, 관련 대화 기록, 답변에 쓰는 파일·도구 내용은 선택한 모델 제공사로 전송됩니다. 이미지도 마찬가지입니다. AI가 사진·화면 캡처·스캔한 PDF 페이지를 읽으면 이미지를 직접 봅니다(격리된 변환기에서 디코딩하고 위치 정보 같은 메타데이터는 지움). 관리자가 팀 설정의 "이미지·PDF 페이지·영상 장면을 AI에게 보내기"를 끄면 보내지 않습니다. AI가 읽는 영상(Linux 서버)도 고르게 고른 장면이 같은 길로 갑니다. AI가 읽는 영상·오디오 파일의 소리는 관리자가 허용했을 때만 팀의 음성 제공자가 글로 바꿉니다(팀 설정 › 음성 입력의 "영상 소리를 글로 바꾸기"; 제공자가 이 서버면 기본 켜짐(CPU 코어 2개 이하 서버는 기본 꺼짐), OpenRouter면 기본 꺼짐, 제공자를 바꾸면 그 제공자의 기본값부터 다시 시작). OpenRouter를 쓰면 팀 파일의 소리(회의 녹음, 고객 통화, 교육 영상)가 OpenRouter와 그 제공사로 갑니다. 데이터를 남기지 않도록 요청하지만 제3자에게 하는 요청이라 서버가 강제할 수 없습니다. 기밀 대화에서는 소리를 내보내지 않습니다(서버가 이미 만든 받아쓰기는 쓸 수 있음). 받아쓰기는 서버 데이터 폴더에 내용별로 최대 30일 보관합니다(백업에는 들어가지 않음). 받아쓰기도 파일 속 글처럼 파일 내용이지 사람의 지시가 아닙니다. AI에게 그렇게 알리며, 걸러 내지는 않고, AI가 거기서 알게 된 내용에도 다른 파일과 같은 공유 범위 확인과 연결 검사가 적용됩니다. 기본 연결에서 Claude는 Anthropic, Codex는 OpenAI를 사용하며 실험용 API 엔진은 별도로 설정한 제공사를 사용할 수 있습니다. 외부 연동 요청도 해당 서비스로 갑니다. 직접 설치가 오프라인 AI 처리를 뜻하지는 않습니다. AWS 서울은 팀 서버의 위치이며 제공사의 AI 처리까지 한국 안에서 이루어진다는 보장은 아닙니다. 제공사의 보관·학습 정책을 이 프로젝트가 보장하지 않으므로 허용된 계정·서비스의 조건을 확인하세요.

트리나가 호스팅하는 서버에서는 음성 입력과 영상·오디오 파일의 소리가 기본으로 OpenRouter(미국)를 거쳐 DeepInfra(미국)로, DeepInfra가 안 될 때는 Groq(미국)로 갑니다. 호스팅이 팀에 준 키는 이 두 제공사, 이 음성 모델 하나, 데이터를 남기지 않는 처리(zero data retention)만 허용하고, OpenRouter에 적힌 두 제공사의 정책은 학습에 쓰지 않고 입력을 남기지 않는다는 것입니다. 팀마다 한 달에 소리가 Starter 50시간, Team 100시간, Business 200시간(무료 요금제 10시간)까지 포함되며, 음성 입력과 영상·오디오 파일 읽기가 이 시간을 함께 씁니다. 키는 호스팅의 것이며 팀 서버에 암호화해 두고 보여 주지 않고, 팀 내보내기 파일에도 들어가지 않습니다. 팀 서버는 그 키로 보낸 소리의 초만 셉니다(소리나 글은 남기지 않음). 팀이 자기 OpenRouter 키를 넣으면 그 키를 대신 쓰며, 팀의 OpenRouter 계정과 설정을 따릅니다. 관리자는 음성 입력이나 "영상 소리를 글로 바꾸기"를 끌 수 있습니다. 기밀 대화에서는 파일의 소리도 음성 입력도 내보내지 않습니다. 입력창이 어느 대화의 녹음인지 서버에 알리고, 서버가 그 대화를 확인해 기밀 대화의 녹음은 OpenRouter로 보내지 않습니다(작업을 시작할 때와 다시 보내기 전에도 확인). 아직 만들지 않은 새 대화는 모든 대화가 기밀일 때(안전 운영 1A 켜짐)만 기밀로 봅니다. "이 서버에서"를 쓰면 소리가 서버 밖으로 나가지 않으므로 기밀 대화에서도 음성 입력을 쓸 수 있습니다.

Codex 웹 검색은 검색할 때마다 지금까지의 대화 내용을 OpenAI의 검색 서비스로 보냅니다(ChatGPT 로그인은 chatgpt.com, API 키는 api.openai.com). Claude의 웹 검색이 Anthropic으로 보내는 것과 같습니다. 기밀 채팅과 승인된 템플릿 실행에서는 검색하지 않습니다.

AI는 Claude Code처럼 웹 페이지를 열고, 주소마다 팀 서버가 확인합니다. 사람이 입력한 주소는 묻지 않고 엽니다. 웹 검색 결과와 AI가 읽은 페이지의 링크는 답변당 30개, 채팅당 150개까지 묻지 않고 엽니다(아무도 물어볼 수 없는 예약 작업 실행은 8개). 그 뒤로는 새 주소마다 묻고, 그 사이트를 이 대화에서 허용할 수도 있습니다. AI가 직접 쓴 주소는 사이트마다 처음 한 번 묻고("이 대화에서 이 사이트 허용"), 쿼리가 길거나 알아보기 어려운 긴 문자열이 있는 주소는 매번 묻습니다. AI가 앞서 이 채팅에서 도구에 보낸 내용과 겹치는 검색 결과나 링크는 사이트가 받은 내용(AI가 실은 자료)을 되돌려 준 것일 수 있으므로 한도가 남아 있어도 항상 묻고, 그런 주소로 넘어가는 리다이렉트도 묻습니다. 사무실망·로컬·클라우드 메타데이터 주소와 서버 자신의 공인 주소는 열지 않습니다. AI가 페이지의 링크 중 무엇을 고르느냐로는 여전히 약간의 자료(한 채팅에서 많아야 약 170바이트)를 실을 수 있고, 이 숫자들이 그것을 제한합니다. 기밀 대화에서는 웹을 쓰지 않습니다.

사람마다 **모든 웹사이트 허용**을 켤 수 있습니다(설정 › 브라우저, 또는 주소 확인 카드의 네 번째 답). 켜면 그 사람이 물을 때 AI가 일반 공개 주소를 카드 없이, 개수 제한 없이 엽니다. 내 채팅과 대화방 모두입니다. 언제나 물은 사람 자신의 설정이고, 다른 팀원의 설정은 쓰지 않습니다. 예약 작업, Slack 질문, 기밀 대화에는 적용되지 않습니다. 알아보기 어려운 긴 문자열, 사이트 이름 앞의 긴 부분, 사용자 이름, 200자가 넘는 쿼리가 있는 주소는 계속 묻고, AI가 앞서 보낸 내용과 겹치는 주소도 묻습니다. 다만 이것은 눈에 띄는 토큰만 거릅니다. 문서, 웹 페이지, 대화방 메시지에 숨겨진 지시 하나로 AI가 읽을 수 있는 내용을 어떤 사이트로든 보낼 수 있습니다(예: 주소에 읽을 수 있는 단어로). 사무실망·로컬·메타데이터 주소는 계속 막힙니다. 팀원이 켤 수 있는지는 관리자가 정합니다(팀 설정의 "팀원이 '모든 웹사이트 허용'을 켤 수 있음" 아래 "AI가 여는 웹 페이지에도", 기본 켜짐). 끄면 모두의 설정이 꺼집니다.

AI는 웹의 파일을 팀 폴더에 저장할 수 있습니다(save_url, `curl -o`와 같은 일). PNG·JPEG·GIF·WebP 이미지, PDF, MP4·MOV·WebM 영상, MP3·WAV·M4A·AAC·FLAC·Ogg(Vorbis, Opus) 오디오를 받습니다. 형식은 사이트가 알려 준 것이 아니라 파일의 바이트로 판별합니다. SVG·HTML·압축 파일·실행 파일은 받지 않고, 이미지는 격리된 변환기에서 한 번 디코딩해 확인합니다(저장하는 것은 원본 파일입니다). 웹 페이지와 같은 주소 규칙을 따릅니다. 리다이렉트마다 주소를 다시 확인하고(공용 인터넷 주소만, 사무실망·서버 자신·클라우드 메타데이터 주소는 거절), 대화에 나온 적 없는 주소는 먼저 사람에게 보여 줍니다. 연결된 서비스가 이 채팅에서 돌려준 주소(이미지 생성 결과 링크 등)는 검색 결과와 같은 한도(답변당 30개, 채팅당 150개) 안에서 묻지 않고 엽니다. 다만 AI가 앞서 이 채팅에서 도구에 보낸 내용과 겹치는 주소는 서비스가 받은 내용을 되돌려 준 것일 수 있으므로 항상 묻습니다. 서비스가 쿼리를 바꾸거나, 자기 리다이렉트 주소 안에 넣거나, 대소문자를 바꿔 돌려준 경우도 같습니다. 그런 주소로 넘어가는 리다이렉트도 묻습니다(짧은 주소 서비스로 우회할 수 없습니다). 한 번에 다 확인할 수 없을 만큼 큰 입력을 보낸 채팅에서는 돌아오는 주소를 모두 묻습니다. 1 GB가 넘는 파일은 크기와 서버 디스크 여유를 보여 주고 먼저 묻습니다. 받은 뒤 디스크 여유가 디스크의 10%(최소 5 GB, 최대 20 GB)보다 적게 남는 다운로드는 거절합니다. 채팅이 읽은 자료보다 더 많은 사람이 보는 곳에 저장하면 다른 저장과 같이 확인을 요청합니다. 연결된 서비스가 답 안에 담아 보낸 이미지는 저장할 수 있도록 24시간 동안 채팅에 보관하고, "이미지·PDF 페이지·영상 장면을 AI에게 보내기"가 켜져 있으면 AI도 그 이미지를 봅니다.

HTML 페이지와 아티팩트 미리보기에는 팀 파일만 보입니다. 페이지가 쓰는 이미지는 보는 사람의 권한으로 팀 폴더에서 가져와 넣고, 그 페이지를 열 수 있는 모든 사람이 열 수 있는 파일만 넣습니다. 웹 이미지는 계속 막고, 몇 개가 막혔는지 미리보기 위에 알려 줍니다.

서버는 시작할 때와 30분마다 트리나 업데이트 피드(`https://updates.trina.app/ip`)에 자기 공인 주소를 묻습니다. 그래서 피드는 그때마다 서버의 주소를 봅니다(업데이트 확인 때도 봅니다). 서버 환경 파일에 `MYCEL_EXIT_ADDRESS_CHECK=off`를 넣으면 묻지 않습니다. 그때는 AI가 여는 웹 주소마다 사람에게 묻고, 예약 작업은 웹 주소를 열지 않습니다.

AI는 Claude Code처럼 큰 요청의 일부를 다른 AI(하위 작업, 한 번에 최대 4개)에게 나눠 맡길 수 있습니다. 나눠 맡은 AI도 같은 사람으로 일합니다. 사람에게 묻기·기억·예약·브라우저를 뺀 같은 도구를 쓰고, 파일 요청마다 같은 권한 확인과 같은 확인 카드를 거치며, 작업 기록에도 어느 하위 작업의 호출인지와 함께 남습니다. 관리자는 팀 설정의 "AI가 일을 나눠 맡기기"로 끌 수 있습니다.

서버가 추적한 제한 자료를 더 넓은 대상의 폴더에 쓰려고 하면 확인을 요청합니다. 이는 모든 외부 전송·사람의 복사를 통제하는 기능이 아닙니다. 권한을 회수해도 이전 답변에 인용된 내용은 지워지지 않습니다. 보안 인증이나 무유출을 보장하지 않습니다.
