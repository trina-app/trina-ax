# 安全与权限

[English](security-and-permissions.md) · [한국어](security-and-permissions.ko.md)

同样一句“总结一下我们的入职政策”，只有有权阅读人事文件的人提问时，才会用到人事文件。每次请求文件时，服务器都会检查提问者本人的访问权限。技能只是一份你本来就能看到的说明，不会给你额外的权限。

团队项目的文件、聊天、说明和技能只属于它的成员。所有者和管理员能看到每个项目的名称和成员人数，也能管理成员，但他们要先把自己加为成员才能打开项目，而这一点项目成员都能看到，活动记录里也会留下记录。服务器自己的备份里仍然有所有文件，服务器磁盘上也一样：这是应用的规则，不是服务器层面的限制。

技能遵循同样的文件夹规则。放在受限文件夹（例如 `skills/finance/`）里的技能，只有能读这个文件夹的人才能看到和使用。放在 `users/<you>/skills/` 里的个人技能只属于你：其他成员、所有者和管理员都看不到。定时任务使用的是这个定时任务所有者的技能。

所有者和管理员负责设置团队的 AI 连接（不需要输入密码，因为每种连接只会发往它所属服务商的固定地址；管理员做的修改会通知所有者；团队 API 引擎的地址由设置的人自己填写，所以仍然需要输入本人的密码）；只有所有者能处理更新、恢复和修改团队名称。所有者和管理员可以移除成员：所有者可以移除除自己以外的任何人，管理员只能移除普通成员，而且都要再次输入自己的密码；被移除成员的个人文件夹会移到所有者的个人文件夹里，只有所有者能读（也可以通过 API 改为删除：`personalFolder=delete`）。应用管理员拥有的是管理操作和活动记录，没有可以浏览所有人私人聊天的界面。服务器、操作系统和存储的运维人员可以读取存储的文件和聊天记录。在托管部署中，这也包括 Trina 的运维人员。

大家通过链接加入团队；不会发送邀请邮件。一次性邀请链接只能开通一个账号，角色和小组由管理员事先选好。团队邀请链接（管理 › 成员）是一个可以多人使用的链接，适合发在团队群里：用它加入的人都是成员，进入所有者或管理员选好的小组；它有人数上限（默认是套餐里的空余席位，绝不超过套餐的成员上限，而且每个人加入时仍然需要一个空余席位），并会在 7、14 或 30 天后失效。链接中的密钥部分在地址的 `#` 后面，浏览器永远不会把这一部分发给服务器、代理或其他网站；加入页面只会把它放在请求正文里发送。通过同一个链接尝试加入的次数有限制（每 15 分钟 30 次，不论从哪里发起），每次加入都会记在活动记录里，并通知所有者；当链接被关闭或更换，或者创建链接的人不再有邀请权限时，链接就会失效。服务器用存放在数据库之外的密钥加密保存这个链接，所以管理员可以再次复制它，而单凭一份数据库副本是打不开它的。链接可以指定一个团队技能；只有当文件夹规则允许新成员阅读时，新成员才能打开它。

提示词、相关的对话记录，以及被选中的文件和工具内容，会发给所选的模型服务商。这也包括图片：AI 读取照片、截图或扫描的 PDF 页面时，看到的是图片本身（在隔离的转换程序里解码，并去掉 GPS 等元数据），除非管理员在团队设置里关闭了“把图片、PDF 页面和视频画面发给 AI”。AI 读取的视频（Linux 服务器）也一样，以均匀抽取的画面发送。标准连接会把 Claude 的请求发给 Anthropic，把 Codex 的请求发给 OpenAI。实验性的 API 引擎可以使用另外配置的服务商。外部集成也会收到各自的请求。自托管并不等于模型在离线处理；AWS 首尔托管说的是团队服务器的位置，并不保证服务商的处理也留在韩国。本项目不承诺任何服务商的数据保留或训练政策；请自行确认所授权账号和服务的条款。

AI 读取的视频或音频文件的声音，只有在管理员允许时，才会由团队的语音服务转成文字（团队设置里语音输入下的“把视频声音转成文字”；服务商是这台服务器时默认开启，除非服务器只有 2 个或更少 CPU 核心；服务商是 OpenRouter 时默认关闭；更换服务商后会恢复为新服务商的默认值）。使用 OpenRouter 时，团队文件的声音（会议录音、客户通话、培训视频）会发给 OpenRouter 以及它选择的服务商；我们会要求零数据保留、不收集数据，并指定 DeepInfra 为服务商（DeepInfra 不可用时用 Groq，不用其他服务商），但这只是对第三方提出的要求，服务器无法强制执行（OpenRouter 目前还不会对语音应用服务商的选择；但密钥本身在 OpenRouter 上的服务商设置会生效）。发送声音时不带文件标题和注释标签。每条文字稿的活动记录都会写明每次请求由哪个服务商处理。机密聊天永远不会把声音发出去（服务器之前已经生成的文字稿可以在那里使用）。文字稿按内容保存在服务器的数据文件夹里，最多 30 天（不在备份中）。文字稿和文件里的任何文字一样，是文件内容，而不是提问者的指示：AI 会被告知这一点，系统不会过滤它；对于 AI 从中得知的内容，扩大共享范围时的确认和连接检查，与对待任何文件一样适用。

在 Trina 托管的服务器上，语音输入以及视频和音频文件的声音，默认经由 OpenRouter（美国）发给 DeepInfra（美国），DeepInfra 不可用时发给 Groq（美国）：托管服务为团队提供的密钥只允许这两个服务商、这一个语音模型和零数据保留，而且这两个服务商在 OpenRouter 上的政策都写明不用于训练、不保留提示词。每个团队每月包含的声音时长为 Starter 50 小时、Team 100 小时、Business 200 小时（免费套餐 10 小时），语音输入和视频、音频读取共用这一份额度。这个密钥属于托管服务，加密保存在团队的服务器上，从不显示，也不包含在团队的导出数据里；团队的服务器会统计用它发送的秒数（为此不保存任何声音或文字）。如果团队填入自己的 OpenRouter 密钥，就改用这个密钥，按团队自己的 OpenRouter 账户和设置处理。管理员可以关闭语音输入或“把视频声音转成文字”。机密聊天永远不会把声音发出去，文件的声音和语音输入都不会：输入框会告诉服务器这段录音属于哪个聊天，服务器会检查这个聊天，并拒绝把机密聊天的录音发给 OpenRouter（任务实际运行时和重试之前都会再检查一次）。还没有创建的聊天，只有在所有聊天都是机密聊天时，才算机密聊天（开启“安全操作 1A”时）。选择“在这台服务器上”时，机密聊天里仍然可以用语音输入，因为声音不会离开服务器。

Codex 每次联网搜索，都会把截至当时的对话发给 OpenAI 的搜索服务（用 ChatGPT 登录时发往 chatgpt.com，用 API 密钥时发往 api.openai.com），就像 Claude 的联网搜索会发给 Anthropic 一样。机密聊天和已批准的模板运行从不联网搜索。

AI 打开网页的方式和 Claude Code 差不多，由团队服务器检查每一个地址。你自己输入的地址会直接打开，不再询问。网页搜索结果以及 AI 读过的网页里的链接，也会直接打开，但每个回答最多 30 个、每个聊天最多 150 个（定时运行时是 8 个，因为没有人可以询问）；超过之后，每个新地址都会先询问，或者由你允许这个网站在本次对话中使用。AI 自己写出的地址，每个网站第一次打开时都会询问（“在本次对话中允许这个网站”）；带有很长的查询参数或很长的、看起来像随机字符的部分的地址，每次都会询问。如果某个搜索结果或链接，和 AI 在这个聊天里先前发给某个工具的内容相符（网站可能会把收到的内容原样带回来，其中就有 AI 的数据），那么不管还剩多少次，都一定会询问；重定向到这类地址时也一样。办公室网络地址、本机地址、云端元数据地址以及服务器自己的公网地址，永远不会被打开。AI 选择打开网页里的哪些链接，这件事本身仍然可能带出一点数据（整个聊天最多约 170 字节）；上面这些数量限制就是为了控制这一点。机密聊天不使用网络。

每个人都可以开启**允许所有网站**（设置 › 浏览器，或者网址卡片上的第四个选项）。开启后，只要这个人提出请求，AI 就会在他的聊天和对话里直接打开普通的公网地址，不再弹出卡片，也没有数量限制。起作用的永远是提问者本人的开关，而不是其他成员的。它不适用于定时任务、Slack 提问或机密聊天。带有很长的、看起来像随机字符的字符串，网站名前有很长的名称，带用户名，或者查询参数超过 200 个字符的地址，仍然会询问；和 AI 先前发送过的内容相符的地址也一样。这只能拦住明显的令牌：文档、网页或对话消息里隐藏的指令，仍然可能让 AI 把它能读到的任何内容发送到任何网站，比如写成地址里可以读懂的文字。办公室网络、本机和元数据地址仍然会被拦截。是否允许成员开启，由管理员决定（团队设置里“成员可以开启‘允许所有网站’”下方的“也适用于 AI 打开的网页”；默认开启）。关掉它，所有人的这项设置都会关闭。

AI 可以把网上的文件保存到团队文件夹（save_url，类似 `curl -o`）：PNG、JPEG、GIF 和 WebP 图片，PDF，MP4、MOV 和 WebM 视频，MP3、WAV、M4A、AAC、FLAC 和 Ogg（Vorbis、Opus）音频。文件类型按文件本身的内容判断，而不是按网站声称的类型；SVG、HTML、压缩包和程序都会被拒绝，图片还会在隔离的转换程序里解码一次作为检查（保存的是原始文件）。网页的地址规则同样适用：每次重定向都会检查（只允许公网地址，绝不访问办公室网络、服务器本身或云端元数据地址），没有在对话里出现过的地址会先给你看。已连接的服务在聊天里返回的地址（例如图片生成服务给出的结果链接）会直接打开，和搜索结果共用同一份额度（每个回答 30 个、每个聊天 150 个）；但如果它和 AI 在这个聊天里先前发给某个工具的内容相符（即使换了查询参数、藏在服务自己的重定向地址里，或者改了大小写），那就一定会询问，因为服务可能会把收到的内容原样带回来；重定向到这类地址时也一样（短链接服务没法把它转手绕过去）。如果某次输入太大、无法完整检查，那么这个聊天里之后返回的所有地址都会先询问。超过 1 GB 的文件会先询问，并显示文件大小和服务器的剩余磁盘空间；如果下载后磁盘剩余空间会低于 10%（至少 5 GB，最多 20 GB），下载会被拒绝。如果保存的位置会让更多人看到这个聊天读过的内容，会和其他保存一样先询问。已连接的服务在回答里返回的图片，会随聊天保存 24 小时，方便保存下来；开启“把图片、PDF 页面和视频画面发给 AI”时，AI 也能看到它们。

HTML 页面和作品（artifact）的预览只显示团队的文件。页面自己的图片从团队文件夹中按查看者的权限放进来，而且只放进所有能打开这个页面的人也都能打开的图片。网上的图片仍然会被拦截；预览上方会提示拦截了多少张。

服务器在启动时和之后每 30 分钟，会向 Trina 更新源（`https://updates.trina.app/ip`）查询自己的公网地址，所以更新源会以这个频率看到服务器的地址（检查更新时也会看到）。在服务器的环境变量文件里设置 `MYCEL_EXIT_ADDRESS_CHECK=off` 可以关闭这项功能；关闭后，AI 打开的每个网址都要先问人，定时任务则一个网址也不打开。

和 Claude Code 一样，AI 可以把一个大请求的一部分交给辅助 AI（子代理，最多同时 4 个）。辅助 AI 以同一个人的身份工作：使用同样的工具（但不能询问本人，也不能使用记忆、定时任务和浏览器），每次请求文件都做同样的权限检查，使用同样的确认卡片，留下同样的活动记录，每次调用都会标明它所属的子任务。管理员可以关闭这项功能（团队设置里的“让 AI 把工作拆成子任务”）。

当受追踪的受限内容要写到更多人能看到的地方时，服务器会请求确认。这不是全面的数据防泄漏（DLP）：它不能控制所有对外传输，也管不了人工复制。撤销文件夹权限，并不会收回之前回答里已经引用的内容。我们不声称拥有任何认证，也不保证零泄漏。

Linux 和使用角色账号的 Mac 安装方式，会额外使用专用的引擎账号和系统级隔离。办公室 Mac 以当前登录的用户身份运行；开发模式不提供正式环境的账号隔离。[详细的权限模型（韩文）](PERMISSIONS.md) · [交给 IT](for-admins.zh.md)。

新团队默认可以用一个公司连接供全团队使用，已保存的设置会保留，符合条件的个人连接优先，每个连接的同意设置依然有效。软件里的设置并不代表服务商的条款允许这样做。请只使用获得授权的账号和套餐。

发现安全问题，请[私下报告](../SECURITY.md)（英文）。
