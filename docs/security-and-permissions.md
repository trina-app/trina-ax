# Security and permissions

[한국어](security-and-permissions.ko.md)

The same question, “Summarize our onboarding policy,” can use an HR file only for a person permitted to read it. The server checks the asking person's access on file requests. A skill is an accessible instruction, not extra authority.

Skills follow the same folder rules. A skill in a restricted folder such as `skills/finance/` is listed and usable only for the people who can read that folder. A personal skill in `users/<you>/skills/` is yours only: other members, owners and admins cannot see it. Scheduled tasks use the skills of the schedule owner.

Owners and admins configure the team's AI connections (no password is asked, since each kind of connection goes only to its provider's fixed address; an admin's change is told to the owner; the team API engine, whose address the caller chooses, still asks for the person's own password); owners alone handle updates, restores and the team name. Owners and admins remove members: the owner anyone but themselves, an admin plain members only, after typing their own password again; a removed member's personal folder moves into the owner's personal folder, where only the owner reads it (the API can delete it instead: `personalFolder=delete`). App admins have administrative actions and activity records, not a screen for reading everyone's private chats. Server/OS/storage operators can read stored files and chats. This includes Trina operators in hosted deployments.

People join through links; no invitation email is sent. A single-use invite link opens one account with the role and groups the admin chose. The team invite link (Admin › Members) is one link many people can use, meant for a team chat: everyone who joins with it is a member, in the groups the owner or admin picked; it takes a set number of people (by default the plan's free seats, never more than the plan's member limit, and each join still needs a free seat) and stops after 7, 14 or 30 days. Its secret part is after `#` in the address, which browsers never send to a server, a proxy or another site; the join page sends it in the request body only. Join attempts through one link are limited (30 per 15 minutes, from anywhere), every join is in the activity log and in the owners' notifications, and a link stops working when it is turned off or replaced, or when the person who made it can no longer invite. The server keeps the link encrypted with a key outside the database, so an admin can copy it again, and a copy of the database alone does not open it. A link can name a team skill; a new member opens it only if the folder rules let them read it.

Prompts, relevant conversation history and selected file/tool content go to the chosen model provider. That includes images: when the AI reads a photo, screenshot or scanned PDF page it sees the image (decoded in an isolated converter, metadata such as GPS removed), unless an admin turns off "Send images, PDF pages and video frames to the AI" in Team settings. Videos the AI reads (Linux servers) go the same way as evenly spaced frames. Standard connections route Claude to Anthropic and Codex to OpenAI. The experimental API engine can use another configured provider. External integrations receive their requests too. Self-hosting is not offline model processing, and AWS Seoul hosting describes the team server location, not a guarantee that provider processing stays in Korea. This project does not promise a particular provider retention or training policy; confirm the terms of the authorized account and service.

The sound of a video or audio file the AI reads is turned into text by the team's speech provider only when an admin allows it ("Turn video sound into text" under Voice input in Team settings; on by default when the provider is this server, unless it has 2 CPU cores or fewer, off when it is OpenRouter, and a change of provider starts again from that provider's default). With OpenRouter the sound of team files (meeting recordings, customer calls, training videos) goes to OpenRouter and the provider it picks; zero data retention, no data collection and DeepInfra as the provider (Groq when DeepInfra is down, no other) are requested, but that is a request to a third party, not something the server can enforce (OpenRouter does not apply the provider choice to speech yet; a key's own provider settings on OpenRouter do). The sound goes without the file's title or comment tags. Each activity record of a transcript names the provider that served each request. Confidential chats never send sound out (a transcript the server already made may be used there). Transcripts are kept by content in the server's data folder for up to 30 days (not in backups). A transcript, like any text in a file, is file content and not instructions from the person: the AI is told so, nothing filters it, and the wider-sharing confirmation and connection checks apply to what the AI learned from it as from any file.

On a Trina-hosted server, voice input and the sound of video and audio files go, by default, through OpenRouter (US) to DeepInfra (US), or to Groq (US) when DeepInfra is down: the hosting service's key for the team only allows these two providers, this one speech model and zero data retention, and both providers' policies at OpenRouter say no training and no prompt retention. Up to 50 hours of sound a team a month are included on Starter, 100 on Team and 200 on Business (10 on the free plan), one pool for voice input and video and audio reads together. The key is the hosting service's, kept encrypted on the team's server and never shown, and it is not in the team's export; the team's server counts the seconds sent with it (no sound or text is kept for that). A team that enters its own OpenRouter key uses that key instead, under its own OpenRouter account and settings. An admin can turn voice input or "Turn video sound into text" off. Confidential chats never send sound out, neither the sound of files nor voice input: the composer tells the server which chat a recording is for, and the server checks that chat and refuses to send a confidential chat's recording to OpenRouter (checked again when the job runs and before a second try). A chat not created yet counts as confidential only while every chat is (Safe operations 1A on). With "On this server" voice input still works there, because nothing leaves the server.

Each Codex web search sends the conversation so far to OpenAI's search service (chatgpt.com for a ChatGPT sign-in, api.openai.com for an API key), as Claude's web search sends it to Anthropic. Confidential chats and approved template runs never search.

The AI opens web pages much as Claude Code does, with the team server checking each address. An address you typed opens without asking. Web search results and the links of pages the AI read open without asking, up to 30 per answer and 150 per chat (8 in a scheduled run, where nobody can be asked); after that each new one asks, or you allow its site for the conversation. An address the AI wrote itself asks the first time for each site ("Allow this site in this conversation"); one with a long query or a long random-looking part asks every time. A search result or a link that matches what the AI had sent to a tool earlier in the chat (a site may repeat what it was sent, with the AI's data in it) always asks, however many are left, and so does a redirect to such an address. Office-network, local and cloud metadata addresses and the server's own public address are never opened. Which of a page's links the AI picks could still carry a little data (about 170 bytes in a whole chat at most); that is what the numbers limit. Confidential chats do not use the web.

Each person can turn on **Allow all websites** (Settings › Browser, or the fourth answer on an address card). Then, when that person asks, the AI opens ordinary public addresses without the card, in their chats and in rooms, with no limit on how many. It is always the switch of the person who asked, never another member's. It does not apply in scheduled tasks, Slack questions or confidential chats. Addresses with a long random-looking string, a long name before the site, a user name, or a query over 200 characters still ask, and so do addresses that match what the AI had sent. That catches obvious tokens only: a hidden instruction in a document, page or room message can make the AI send anything it can read to any site, for example as readable words in an address. Office-network, local and metadata addresses stay blocked. Admins decide whether members may turn it on ("Also for web pages the AI opens", under "Members can turn on 'Allow all websites'" in Team settings; on by default). Turning it off turns everyone's off.

The AI can save a file from the web into the team folder (save_url, like `curl -o`): PNG, JPEG, GIF and WebP images, PDF, MP4, MOV and WebM video, MP3, WAV, M4A, AAC, FLAC and Ogg (Vorbis, Opus) audio. The type is judged by the file's bytes, not by what the site says; SVG, HTML, archives and programs are refused, and an image is also decoded in the isolated converter as a check (the original file is saved). Web pages' address rules apply: every redirect is checked (public internet addresses only, never the office network, the server itself or a cloud metadata address), and an address that did not appear in the conversation is shown to you first. Addresses a connected service returned in the chat (an image generator's result link) open without asking, within the same budget as search results (30 per answer, 150 per chat), except one that matches what the AI had sent to a tool earlier in the chat (also with another query, inside the service's own redirect address, or with its case changed): a service may repeat what it was sent, so that one always asks, and so does a redirect to such an address (a link shortener cannot pass it on). An input too large to check completely makes every address that comes back in that chat ask. A file over 1 GB asks first, with its size and the server's free disk space; a download that would leave less than 10% of the disk free (at least 5 GB, at most 20 GB) is refused. Saving where more people can see what the chat read asks, as for other saves. Images a connected service returns inside its answer are kept with the chat for 24 hours so they can be saved, and the AI sees them when "Send images, PDF pages and video frames to the AI" is on.

Previews of HTML pages and artifacts show only team files. A page's own images are put in from the team folder with the viewer's permissions, and only those that everyone who can open the page can open as well. Images from the web stay blocked; a note above the preview says how many.

The server asks the Trina update feed (`https://updates.trina.app/ip`) for its own public address at start and every 30 minutes, so the feed sees the server's address that often (it does on update checks too). `MYCEL_EXIT_ADDRESS_CHECK=off` in the server's environment file turns this off; then every web address the AI opens asks a person and scheduled tasks open none.

Like Claude Code, the AI can hand parts of a big request to helper AIs (sub-agents, up to 4 at a time). A helper works as the same person: the same tools minus asking the person, memories, schedules and the browser, the same access check on every file request, the same confirmation cards and the same activity records, each call marked with its sub-task. Admins can turn it off ("Let the AI split work into sub-tasks" in Team settings).

The server asks for confirmation when tracked restricted context is written to a broader audience. This is not universal data-loss prevention: it does not control all external transfers or human copying. Revoking folder access does not retract quotations in previous answers. No certification or zero-leak guarantee is claimed.

Linux and role-account Mac installations add dedicated engine accounts and OS isolation. Office Mac runs as the logged-in user; development mode is not production account isolation. [Detailed permission model (Korean)](PERMISSIONS.md) · [IT handoff](for-admins.md).

On new teams one company connection can serve the whole team by default, existing saved settings persist, eligible personal connections take priority, and connection-level consent still applies. Software settings are not permission under provider terms. Use only authorized accounts and plans.

Report security problems [privately](../SECURITY.md).
