# Security and permissions

[한국어](security-and-permissions.ko.md)

The same question, “Summarize our onboarding policy,” can use an HR file only for a person permitted to read it. The server checks the asking person's access on file requests. A skill is an accessible instruction, not extra authority.

Skills follow the same folder rules. A skill in a restricted folder such as `skills/finance/` is listed and usable only for the people who can read that folder. A personal skill in `users/<you>/skills/` is yours only: other members, owners and admins cannot see it. Scheduled tasks use the skills of the schedule owner.

Owners configure the team and its AI connections. App admins have administrative actions and activity records, not a screen for reading everyone's private chats. Server/OS/storage operators can read stored files and chats. This includes Trina operators in hosted deployments.

Prompts, relevant conversation history and selected file/tool content go to the chosen model provider. That includes images: when the AI reads a photo, screenshot or scanned PDF page it sees the image (decoded in an isolated converter, metadata such as GPS removed), unless an admin turns off "Send images, PDF pages and video frames to the AI" in Team settings. Videos the AI reads (Linux servers) go the same way as evenly spaced frames. Standard connections route Claude to Anthropic and Codex to OpenAI. The experimental API engine can use another configured provider. External integrations receive their requests too. Self-hosting is not offline model processing, and AWS Seoul hosting describes the team server location, not a guarantee that provider processing stays in Korea. This project does not promise a particular provider retention or training policy; confirm the terms of the authorized account and service.

The sound of a video or audio file the AI reads is turned into text by the team's speech provider only when an admin allows it ("Turn video sound into text" under Voice input in Team settings; on by default when the provider is this server, unless it has 2 CPU cores or fewer, off when it is OpenRouter, and a change of provider starts again from that provider's default). With OpenRouter the sound of team files (meeting recordings, customer calls, training videos) goes to OpenRouter and the provider it picks; zero data retention, no data collection and DeepInfra as the provider (Groq when DeepInfra is down, no other) are requested, but that is a request to a third party, not something the server can enforce (OpenRouter does not apply the provider choice to speech yet; a key's own provider settings on OpenRouter do). The sound goes without the file's title or comment tags. Each activity record of a transcript names the provider that served each request. Confidential chats never send sound out (a transcript the server already made may be used there). Transcripts are kept by content in the server's data folder for up to 30 days (not in backups). A transcript, like any text in a file, is file content and not instructions from the person: the AI is told so, nothing filters it, and the wider-sharing confirmation and connection checks apply to what the AI learned from it as from any file.

On a Trina-hosted server, voice input and the sound of video and audio files go, by default, through OpenRouter (US) to DeepInfra (US), or to Groq (US) when DeepInfra is down: the hosting service's key for the team only allows these two providers, this one speech model and zero data retention, and both providers' policies at OpenRouter say no training and no prompt retention. Up to 10 hours of sound a team a month are included, one pool for voice input and video and audio reads together. The key is the hosting service's, kept encrypted on the team's server and never shown, and it is not in the team's export; the team's server counts the seconds sent with it (no sound or text is kept for that). A team that enters its own OpenRouter key uses that key instead, under its own OpenRouter account and settings. An admin can turn voice input or "Turn video sound into text" off. Confidential chats never send sound out.

Each Codex web search sends the conversation so far to OpenAI's search service (chatgpt.com for a ChatGPT sign-in, api.openai.com for an API key), as Claude's web search sends it to Anthropic. Confidential chats and approved template runs never search.

The server asks the Trina update feed (`https://updates.trina.app/ip`) for its own public address at start and every 30 minutes, so the feed sees the server's address that often (it does on update checks too). `MYCEL_EXIT_ADDRESS_CHECK=off` in the server's environment file turns this off; then every web address the AI opens asks a person and scheduled tasks open none.

Like Claude Code, the AI can hand parts of a big request to helper AIs (sub-agents, up to 4 at a time). A helper works as the same person: the same tools minus asking the person, memories, schedules and the browser, the same access check on every file request, the same confirmation cards and the same activity records, each call marked with its sub-task. Admins can turn it off ("Let the AI split work into sub-tasks" in Team settings).

The server asks for confirmation when tracked restricted context is written to a broader audience. This is not universal data-loss prevention: it does not control all external transfers or human copying. Revoking folder access does not retract quotations in previous answers. No certification or zero-leak guarantee is claimed.

Linux and role-account Mac installations add dedicated engine accounts and OS isolation. Office Mac runs as the logged-in user; development mode is not production account isolation. [Detailed permission model (Korean)](PERMISSIONS.md) · [IT handoff](for-admins.md).

New teams allow subscription sharing by default, existing saved settings persist, eligible personal connections take priority, and connection-level consent still applies. Software settings are not permission under provider terms. Use only authorized accounts and plans.

Report security problems [privately](../SECURITY.md).
