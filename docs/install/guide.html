00

시작 전에

10분

Team AX는 사무실 맥 한 대(이하 서버 맥)에서 팀 서버와 AI 엔진(Claude Code, 선택으로 Codex)을 돌리고, 팀원은 웹·데스크톱 앱·휴대폰으로 그 맥에 들어와서 써요. AI 사용량은 팀장의 Claude 구독에서 나가요.

준비물

무엇설명
늘 켜 둘 맥 한 대애플 실리콘(M1 이후)을 권해요. 인텔 맥도 되지만 빌드할 때 한 단계가 더 있어요(1장). 전원에 꽂아 두고, 잠자기에 들지 않게 둬요. 정식 설치는 잠자기를 알아서 꺼요.
macOS이 가이드는 macOS 26.3.1에서 확인했어요. 메뉴바 앱은 macOS 13 이상이 필요해요.
Claude 구독Claude Pro 또는 Max 계정. 팀 전체의 AI 답변이 이 구독에서 나가요. 사람이 많으면 Max를 권해요.
ChatGPT 구독 (선택)두 번째 엔진 Codex를 쓰려면 필요해요. 없어도 Claude만으로 동작해요.
맥 관리자 암호정식 설치(2장)에서 sudo 명령이 물어봐요. 개발 모드(1장)는 필요 없어요.
저장소 접근 권한소스 코드 저장소(potenlab/team-ax)는 아직 비공개예요. GitHub 계정에 읽기 권한을 받아 두세요.
인터넷·저장 공간도구와 앱을 내려받아요. 음성 입력을 쓰면 처음 한 번 약 490MB 모델을 더 받아요.

아직 준비되지 않은 것 준비 중

  • 정식 설치 후 AI 채팅. 정식 설치(2장)는 끝까지 되지만, 이 버전의 서버는 그 상태에서 Claude를 켜지 않아요(“회사 API 키 모드는 이 버전에서 아직 켤 수 없습니다”). 팀장이 만든 Claude 장기 토큰을 서버가 아직 쓰지 않기 때문이에요. Codex도 정식 설치에는 아직 연결되지 않아요. 그래서 지금 실제로 팀이 AI와 대화하려면 1장의 개발 모드를 써야 해요.
  • 공개 팀 주소(우리팀.treesoop.com). 이 주소를 이어 주는 중계 서버가 아직 돌지 않아요. 지금 되는 주소는 3장에 정리했어요.
  • 서명된 앱. 맥 앱·메뉴바 앱·윈도우 설치 파일에 애플·마이크로소프트 서명이 없어서, 처음 열 때 경고가 나와요(3장에 여는 법). 자동 업데이트도 아직 없어요.
  • 메일은 일부러 없어요. 초대와 비밀번호 재설정은 링크를 복사해서 카카오톡·슬랙 등으로 전해요. 준비 중이 아니라 원래 이렇게 만든 거예요.

01

빠르게 써 보기

개발 모드 · 약 30분

맥 한 대에 Team AX를 개발 모드로 띄워요. AI 엔진은 지금 로그인한 맥 사용자로, 그 사람의 Claude 로그인으로 돌아요. 지금 AI 채팅까지 되는 유일한 방법이에요.

1-1필요한 도구 설치

애플의 개발 도구와 Homebrew(맥용 설치 도구)부터 설치해요. 이미 있으면 건너뛰어요.

xcode-select --install
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Homebrew 설치가 끝나면 마지막 “Next steps”에 나오는 명령(~/.zprofile에 한 줄 넣는 것)을 그대로 실행하고, 터미널을 닫았다가 다시 열어요. 그다음 나머지 도구를 한 번에 설치해요.

brew install go node ripgrep pandoc poppler typst ffmpeg whisper-cpp
curl -fsSL https://bun.sh/install | bash -s "bun-v1.3.12"
도구왜 필요한가요
Bun 1.3.12Team AX 서버를 돌려요. 버전을 고정해 두었어요.
GoAI 엔진을 지키는 작은 프로그램(도구 관문·실행기)을 빌드해요.
Node 25 이상중계 서버(원격 주소 시험용)만 써요. 없으면 “relay skipped”가 나오고 직접 주소는 그대로 돼요.
ripgrep, pandoc, poppler, typstAI가 파일을 찾고, Word·PDF를 읽고, PDF를 만들어요.
ffmpeg, whisper-cpp음성 입력·받아쓰기. 없으면 그 기능만 안 돼요.
확인터미널을 다시 연 뒤 bun --version → 1.3.12, node --version → v25.… 이상, go version → 버전이 나와요.
1-2Claude Code 설치와 로그인
curl -fsSL https://claude.ai/install.sh | bash
claude

claude를 처음 실행하면 브라우저가 열려요. Claude Pro/Max 계정으로 로그인하고 승인한 뒤, 터미널로 돌아와 control + C를 두 번 눌러 닫아요. 이 가이드는 Claude Code 2.1.305로 확인했어요(시험이 이 버전에 맞춰져 있어요).

Codex(선택): OpenAI의 Codex CLI 안내대로 설치한 뒤 codex login으로 ChatGPT 계정에 로그인해요. 이 가이드는 0.163.0으로 확인했어요.

확인claude --version에 버전이 나와요. 로그인 여부는 1-5에서 Team AX 화면으로 확인해요.
1-3내려받고 빌드하기
cd ~
git clone git@github.com:potenlab/team-ax.git
cd team-ax
bun install
bun run build

git clone은 GitHub에 SSH 키가 등록되어 있고 저장소 권한이 있어야 돼요. 앞으로 나오는 명령은 모두 이 ~/team-ax 폴더에서 실행해요.

인텔 맥이라면

빌드 도구가 기본으로 애플 실리콘용만 만들어요. bun run build 다음에 ARCHS=amd64 bun run build:native를 한 번 더 실행하세요. 안 하면 채팅이 “엔진을 쓸 수 없음”으로 끝나요.

확인bun install은 “1579 packages installed”, bun run build는 오류 없이 10초 안팎에 끝나요.
1-4실행하기
bun run dev
[dev] data: /Users/나/.team-ax-dev
[dev] direct: http://localhost:19100
[dev] relay:  http://demo.localhost:19161  (the team registers itself a few seconds after start)
[dev] engines run as 나 with your own Claude Code / Codex logins (local-login). Ctrl-C stops everything.
[server] … first-run setup: … (or open http://127.0.0.1:19100/setup?token=설정코드)
  • 이 창은 켜 둔 채로 둬요. 닫거나 control + C를 누르면 Team AX가 꺼져요(계속 켜 두는 법은 1-7).
  • “relay: team address registered; the recovery code was saved once…”라는 줄도 나와요. 개발 모드에서는 무시해도 돼요.
  • 포트 19100과 19161은 고정이에요. 이 맥에 이미 Team AX 개발 서버가 돌고 있으면 먼저 bun run dev:service stop으로 멈추세요. 한 맥에 개발 서버는 하나만 띄울 수 있어요.
확인위처럼 [dev] 네 줄과 setup?token=이 들어간 줄이 보여요. 브라우저에서 http://localhost:19100을 열면 Team AX 화면이 나와요.
1-5팀 만들기 — 둘 중 하나

A. 내 팀을 처음부터 만들기

  1. 11-4의 로그에서 http://127.0.0.1:19100/setup?token=… 주소를 통째로 복사해 브라우저에 붙여 넣어요. 설정 코드가 주소에 들어 있어서 따로 입력하지 않아요.
  2. 2화면은 처음에 영어(Create your team)예요. Team language에서 한국어를 고르면 화면이 바로 한국어로 바뀌고, 팀 기본 언어도 한국어가 돼요.
  3. 3팀 이름, 이름, 아이디(영문·숫자와 . _ @ -, 2–64자), 비밀번호(10자 이상)를 넣어요. 이 계정이 팀장(owner)이에요.
  4. 4팀 만들고 시작하기(Create team and start)를 누르면 바로 로그인된 첫 화면으로 가요.
주소는 하나로

127.0.0.1:19100과 localhost:19100은 같은 서버지만 로그인이 따로예요. 처음 쓴 주소로 계속 들어가면 헷갈리지 않아요.

B. 데모 팀으로 둘러보기

예시 파일과 계정이 들어 있는 한국어 데모 팀을 만들어요. bun run dev가 켜져 있는 상태에서 터미널 창을 하나 더 열고:

cd ~/team-ax
bun run demo:seed
[demo] team "데모 팀" created, owner dion
… 9 sample files uploaded … project 신제품 출시 created
[demo] sign in at http://localhost:19100 as dion / admin1 / alice / bob with the password teamax-demo-1

다시 실행해도 안전해요(빠진 것만 채워요). 단, A로 이미 팀을 만들었으면 데모는 만들 수 없어요(팀은 하나뿐이에요).

확인첫 화면 맨 위에 노란 띠 “개발 모드: OS 격리 없음…”이 보이고, 팀장에게는 시작하기 전에 상자(AI 연결 확인하기 · 팀원 초대하기 · 폴더 권한 정하기 · 첫 백업 만들기)가 보여요.

언어 바꾸기

  • 나만: 왼쪽 아래 내 이름 → 설정 → 프로필 → 언어 (영어 화면: Settings → Profile → Language).
  • 팀 전체 기본값: 관리자 → 팀 설정. 자기 언어를 고르지 않은 사람은 모두 이 언어로 봐요.
  • 로그인·초대·비밀번호 재설정 화면 아래에도 언어 선택이 있어요.
1-6AI 연결 확인

관리자 → AI 엔진을 열어요. 개발 모드에서는 Claude Code가 연결됨 · 팀장 구독 로그인으로 보여야 해요.

“로그인 필요”로 나오면 같은 맥 사용자로 터미널에서 claude(또는 codex login)를 실행해 로그인하고, 카드 오른쪽 위 새로 고침 버튼을 눌러요. 그다음 새 채팅에서 “안녕”이라고 보내 답이 오는지 봐요.

확인채팅에 답이 와요. “AI 엔진이 예기치 않게 멈췄습니다”가 나오면 5장 첫 표를 보세요(데이터 폴더 위치 문제일 때가 많아요).
1-7계속 켜 두기 (선택)

터미널을 닫아도 돌고, 맥에 로그인하면 자동으로 켜지게 하려면 백그라운드 서비스로 등록해요. 먼저 1-4의 bun run dev 창에서 control + C로 멈춘 뒤:

cd ~/team-ax
bun run dev:service install     # 등록하고 시작
bun run dev:service status      # 두 주소가 답하는지
명령하는 일
bun run dev:service logs최근 로그. 전체는 ~/Library/Logs/team-ax-dev/dev.log
bun run dev:service restart다시 시작(업데이트 뒤 등)
bun run dev:service stop / start잠시 멈춤 / 다시 켬
bun run dev:service uninstall서비스 등록 해제(데이터는 남아요)
한 맥에 하나

서비스 이름(app.team-ax.dev)이 고정이라, 다른 폴더에 받은 Team AX에서 install을 하면 기존 서비스를 덮어써요.

확인status가 두 주소(19100, 19161) 모두 답한다고 알려 줘요.

개발 모드에서 알아 둘 점

  • 이 맥에서만 들어올 수 있어요. 서버가 이 맥 안(127.0.0.1)에서만 연결을 받아서, 다른 컴퓨터·휴대폰은 들어오지 못해요.
  • AI가 내 맥 사용자 권한으로 돌아요. 팀 폴더 권한은 지켜지지만, 정식 설치의 OS 격리(전용 계정·샌드박스·방화벽)는 없어요.
  • AI 사용량이 내 Claude·ChatGPT 구독에서 나가요. Claude Code는 매 답변 문맥에 내 Claude 계정 이메일을 넣어요(끌 수 없어요).
  • 데이터는 ~/.team-ax-dev에 있어요. 이 폴더를 /tmp 아래나 아주 긴 경로로 옮기면 채팅이 멈춰요(5장).
  • 팀장 비밀번호를 잊으면 서버를 켠 채로 bun run dev admin reset-link를 실행해 나오는 1회용 링크를 열어요.

업데이트 — 정식 설치

관리자 화면의 업데이트 설치는 릴리스 정보 주소가 아직 없어서 쓸 수 없어요 준비 중. 지금은 이렇게 해요.

  • 버전 번호가 같을 때(0.1.0): 새 코드를 받고(git pull, bun install) bun run build:bundle 후 2-3의 설치 명령을 그대로 다시 실행해요. 같은 버전 폴더를 새것으로 바꿔요.
  • 새 버전 번호로 올릴 때: 설치 명령을 다시 돌려도 새 버전으로 바뀌지 않아요(알려진 문제). 아래처럼 서버 계정으로 올리고 바꿔요. 묶음 파일은 서버 계정이 읽을 수 있는 곳(/Users/Shared)에 먼저 복사해요.
bun scripts/build-bundle.ts --version 0.1.1
cp dist/release/0.1.1.tar.zst /Users/Shared/
cd / && sudo -u _axserver env MYCEL_MODE=prod \
  "/Library/Application Support/mycel/app/current/bin/bun" \
  "/Library/Application Support/mycel/app/current/server/src/admin.js" \
  stage-update /Users/Shared/0.1.1.tar.zst

이어서 같은 앞부분(cd / && sudo -u _axserver … admin.js)에 switch 0.1.1 --restart를 붙여 실행하면 새 버전으로 다시 시작해요. 되돌리려면 rollback --restart. 새 버전이 120초 안에 답하지 않거나 세 번 연달아 꺼지면 이전 버전으로 자동으로 돌아가요(설계상 동작, 실제 설치에서는 확인 전).

백업은 같은 디스크에 있어요

맥이 고장 나면 백업도 같이 잃어요. 가끔 다른 곳에 복사하세요. 개발 모드는 서비스를 멈추고(bun run dev:service stop) ~/.team-ax-dev 폴더를 통째로 외장 디스크에 복사한 뒤 다시 켜요. 정식 설치는 서버 계정으로 암호화 묶음을 만들어요:

cd / && sudo -u _axserver env MYCEL_MODE=prod \
  "/Library/Application Support/mycel/app/current/bin/bun" \
  "/Library/Application Support/mycel/app/current/server/src/admin.js" \
  archive --out /Users/Shared/teamax-backup.tar.zst.age --password-stdin

관리자 암호 다음에 묶음용 암호(8자 이상)를 입력하고 Return, 이어서 control + D를 눌러요. 입력한 암호가 화면에 보이니 주변을 확인하세요. 다른 명령: backup, list-backups, restore-archive --in 파일 --to 새폴더. 정식 설치에는 팀장 비밀번호 재설정 도구가 아직 없어요 준비 중.

알려진 문제 (개발 담당에게 전할 것)

  1. 정식 설치에서 채팅이 안 됨: 설치 스크립트가 engine.authMode를 "proxy"로 쓰는데 서버는 이 모드를 거절하고, 장기 토큰을 쓰는 모델 프록시가 시작되지 않음.
  2. 정식 설치에 Codex가 연결되지 않음(codexBin 없음, 로그인 폴더 세 곳이 서로 다름).
  3. 설치 스크립트가 --engine 이름을 확인하지 않아 첫 엔진이 무조건 Claude로 잡힘.
  4. 실행기 소켓이 없을 때 진단을 열면 정식 서버가 꺼짐.
  5. 새 버전 번호로 설치 스크립트를 다시 돌려도 app/current가 바뀌지 않음.
  6. 데스크톱 앱이 사무실 자체 서명 주소에 연결하지 못함(/api/connect-info 없음).
  7. 직접 운영 중계: 관리자 화면에 팀 이름 칸이 없어 server.json을 손으로 고쳐야 함.
  8. 정식 설치에 계정 도구(reset-link, create-owner)가 없음.
  9. 개발 모드 포트가 고정(19100·19161)이라 한 맥에 둘을 띄울 수 없음. 데이터 폴더 경로가 길면 원인 대신 “예기치 않게 멈춤”만 보임.
  10. 개발 모드 진단의 샌드박스 문구가 예전 설명 그대로임. 인증서에 en0 말고 다른 네트워크의 IP가 들어가지 않음.
