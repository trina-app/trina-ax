# Files › Trash: names and places, "Deleted by me", repeats grouped, one-line note (QA TC-1040)

- Date (UTC): 2026-11-13 15:57
- Branch: `feat/trash-ui-tc1040`
- Status: done
- Where: web/ (Team AX core). Why: a screen of the core Files area; the server's trash rules and API stay as they are
  (see docs/REPOSITORY-RULES.md)
- Version impact: patch, a screen change with no API or data change

## Goal

Files › Trash shows raw storage paths ("users/<id>/projects/Hello", "groups/QA Sales"), one identical row per delete
of the same file and a long two-line note. Ordinary office workers cannot tell where an item was or which row to
restore. The owner approved four changes on 2026-11-13.

## Scope

In:

1. Each row: the item's name, then where it was in the Files sidebar's words ("Hello · My projects", "price-sheet.xlsx ·
   Company-wide › Sales", "remotion-video.md · Team skills", a project folder by its project name, the person's own
   folder as "My files"). Folders and projects get their icon. No users/<id>, groups/, projects/ or shared/ prefix.
   Built on lib/folderLabels.ts (`folderWords`) and the project list (store/projects.ts).
2. A "Deleted by me / Everyone" segmented switch (components/ui.tsx `Tabs segmented`), shown when the Everyone list
   has items someone else deleted. Default Everyone. "Deleted by me" reads `GET /api/files/trash?mine=1`.
3. Items with the same original path are one row with "3 copies" and the latest delete's who / when. The row opens to
   one line per copy (who, when, size) with its own Restore; the row's Restore restores the latest. Grouped on the
   client over every loaded page (a group may span pages: "Load more" merges into it).
4. One plain line on top: "Items are removed for good N days after they're deleted.", N = the team's retention as
   the newest item was given it (purgeAt - deletedAt; the app does not read the setting for members). Each row says
   "removed for good in 18 days" with the full date in its tooltip.

Rows are the shared ListRow (components/list/List.tsx); no new boxes or cards.

Out: server visibility (`trashVisible`, `trash()`), Restore permissions and its " (restored)" name, purge. No
"Delete for good" button is added (the screen has none today; `DELETE /api/files/trash/:id` stays API-only).

## Steps

1. `web/src/lib/trashList.ts`: `trashPlace()` (path → name, where, kind), `groupTrash()` (by original path, newest
   first, merged across pages), `showWhoSwitch()`, `retentionDays()`, `purgeIn()`.
2. pages/Files.tsx `TrashView`: the switch, the note, grouped ListRows, copy rows, Restore per copy.
3. i18n keys in en first, then ko, ja, es, id; drop `files.trashNote` / `files.trashNoteShort`.
4. Mock server: trash newest first, `mine`, members see only what they may write (like the server).
5. Tests: web unit (mapping, grouping across pages, switch visibility), e2e (admin and member restore one copy of a
   group), existing trash e2e updated.
6. Help page that describes the Trash, `changes/trash-ui-tc1040.md`.

## Risks

- No migration, no API change. Permissions unchanged: the list is what the server sends.
- Five languages: plural forms in en / ja / es (check:i18n).
- Phone (390 px): the second line is shortened (place and the "in N days" hint); Restore stays 44 px.

## Result

Built as planned in `web/src/lib/trashList.ts` and pages/Files.tsx `TrashView`. "N copies" is the row's trailing tag
(ListRow `tag`); the row opens with a click (ListRow got an `expanded` prop for its aria-expanded). Phones show the place
and a short "gone in 30 days" (the full date in the tooltip) and a Restore button without its icon, so the lines fit
at 390 px. The retention line shows only with items (an empty trash keeps its empty state). The mock server's trash now
lists newest first with `mine`, pages and write access, and a restore onto a taken name gets " (restored)". Tests:
web/test/unit/trash-list.test.ts, web/test/e2e/trash-groups.spec.ts; the existing trash checks in files, phone-files
and team-skills follow the new rows.
