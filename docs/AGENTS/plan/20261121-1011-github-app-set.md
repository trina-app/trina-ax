# Tenant command github-app-set: the hosting service gives a team server its GitHub App

- Date (UTC): 2026-11-21 10:11
- Branch: `feat/github-app-set`
- Status: done
- Where: native/cmd/mycel-ctl, shared/src/cloud-protocol (MIT). Why: hosted team servers have no way to receive the
  GitHub App file the GitHub connector needs (docs/REPOSITORY-RULES.md: tenant commands live in mycel-ctl and the
  shared contract)
- Version impact: patch: one new tenant command for the hosting service; nothing changes for self-installed servers

## Goal

The GitHub connector (server/src/integrations/github/app.ts) signs in through one GitHub App whose values the server
reads from `<secrets>/integrations/github/app.json`. On a hosted team server nobody can put that file there: the
hosting service reaches a team server only through allow-listed `mycel-ctl` tenant commands, and none writes it. So
the GitHub card stays "Not set up yet" on every hosted team.

## Scope

In:
- Contract (MIT): `github-app-set`, stdin `GitHubAppFile` `{ clientId, clientSecret, slug? }` (strict, the
  rules of app.ts, the secret printable ASCII without spaces), answer `{ ok, changed }`, 30 s. Accept and refuse
  vectors with fake values.
- mycel-ctl: checks the same rules, then the server account writes the file (server-write: new allowed target,
  file 0600, folder 0700, atomic rename, never through a link). Same bytes again: `changed: false`, nothing written.
  No restart: app.ts reads the file at each request. The secret is never in an argument, an error, a log or the
  answer.
- server-write prints `{"changed":bool}` (asServer hands its stdout back).

Out: taking the app away (`null`): not needed now, the file can be removed by hand; the hosting service's credential
and push job (trina-cloud).

## Steps

1. Contract + vectors + contract test.
2. mycel-ctl command, server-write target, tests (written, idempotent, modes, refused shapes write nothing and print
   nothing, the secret never on stdout or stderr).
3. changes/ fragment.

## Decisions

none (mirrors error-reports-set, docs/decisions/20261119-hosted-error-reports.md).

## Risks

Security: a secret on stdin only; the root half never writes into the server account's folders (server-write runs as
the server account). Hosted team servers get the command only with the release that contains it (0.6.0 or later);
the hosting service must gate on that version.

## Tests

`bun run typecheck`, `go test ./cmd/mycel-ctl/`, `bun test tests/unit/cloud-protocol.test.ts`, `bun run check:prepush`.

## Result

Built as planned. Review changes: the file is written without HTML escapes (json.Marshal made `< > &` six bytes each,
which could push the largest app over app.ts's 16 KiB), stdin is 32 KiB (the largest app, escaped, fits), and Go runs
the contract's vectors (TestTenantGitHubAppVectors). The hosting service's side (credential, push job, hostd
allow-list) is a trina-cloud PR, gated on 0.6.0.
