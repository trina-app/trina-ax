# electron-builder 26.0.12 → 26.15.3, so the Mac dmg window shows its background

- Date (UTC): 2026-11-16 01:36
- Branch: `chore/electron-builder-26-15`
- Status: done
- Where: desktop/package.json and bun.lock. Why: the desktop app's packaging tool (see docs/REPOSITORY-RULES.md)
- Version impact: patch, a build tool update with no app change (target 0.5.10)

## Goal

Finder shows no background in our Mac dmg window: the released 0.5.7 dmg (built in CI) and every dmg built with
electron-builder 26.0.12 open on a bare window. 26.0.12 makes the dmg as APFS with an old copy of dmgbuild; 26.15.3
(dmg HFS+ by default, a newer dmgbuild, "fix dmg background" in 26.5.0) showed the Trina background in a real Finder
check on macOS 26.6. The branded background itself is a separate PR on top of this one.

## Scope

In: the `electron-builder` version in desktop/package.json (26.15.3: the build that was checked by eye) and the lock.
Out: electron-updater stays 6.8.10. Newer 26.15.x patches wait for their own check.

## Steps

1. Plan (this commit).
2. Bump and lock; read the changelog 26.0.13 to 26.15.3 for mac signing, notarization, dmg, zip, NSIS, MAS and appx.
3. Checks: typecheck, the desktop and packaging unit tests, a local unsigned dmg (`dist:mac`), a Mac App Store package
   (`editions/trina/mac-app-store`), a Windows NSIS build on the Windows test PC, and the MSIX build in CI.
4. The release path: mac-app.yml "Run workflow" on a temporary branch (Developer ID sign, notarize, staple, Gatekeeper),
   then install the signed dmg into a scratch folder and check that the app updates itself from the zip, as for
   QA TC-2704. Delete the temporary branch after.

## Risks

- Mac signing and notarization (`electron-builder.devid.config.ts`, `scripts/release/mac-app.ts`): newer
  @electron/osx-sign and @electron/notarize; the hardened runtime and entitlements; the signed dmg.
- The update zip: 26.15.2 makes it with macOS `zip` (keeps framework links); Squirrel.Mac must still take it.
- The dmg is HFS+ instead of APFS: it mounts on every macOS the app supports.
- Which node_modules go into the app: the collector changed (bun support in 26.3.0); release-check.ts and the app's
  start show a missing module.
- Windows: NSIS changes (process-name match, makensis checks) and Authenticode signing through `win-sign.ts`.

## Tests

`bun run typecheck`, `bun run check:docs`, `tests/unit/e-desktop-common.test.ts`, `tests/unit/g-mac-app.test.ts`,
`tests/unit/office-update.test.ts`, `tests/unit/mac-permission-languages.test.ts`, `tests/unit/plugins-package.test.ts`,
and the builds above.

## Result

Bumped to 26.15.3 (lock: one builder-util-runtime 9.7.0, shared with electron-updater 6.8.10). Checked:
- Changelog 26.0.13 to 26.15.3 read: dmg background fix (26.5.0, newer dmgbuild), HFS+ default with a `filesystem`
  option (26.13.0), native `zip` for the Mac zip (26.15.2), `.ts` configs loaded with jiti (comments updated), NSIS and
  Windows signing fixes; no option this repo uses was removed.
- Local unsigned universal `dist:mac`: app contents and Info.plist the same as a 26.0.12 build (asar hash only).
- mac-app.yml "Run workflow" on a temporary branch (0.5.9-test.1, deleted after): Developer ID signed, notarized and
  stapled; `spctl` accepts the dmg and the app (Notarized Developer ID); HFS+ dmg; designated requirement and
  entitlements the same as the released 0.5.7; the update zip keeps the framework links and passes
  `codesign --deep --strict`; the server's own `latest-mac.yml` check (server/src/office/update.ts) passes on it.
- The quarantined app copied from that dmg to a scratch folder opens with the usual "Apple checked it" question and
  starts like 0.5.7.
- Mac App Store package built and signed; `altool --validate-app`: no errors.
- Windows NSIS installer built (installer.nsh included). The Microsoft Store package builds in this PR's CI
  (msstore.yml runs on the store manifest change).
- Windows install, update over and uninstall on GitHub windows runners (scripts/ci/windows-install-check.ps1 from
  #1041): this PR's own Desktop run (two 26.15.3 installers), and a one-off run from a temporary branch (deleted) that
  installed the released 0.5.7 installer (electron-builder 26.0.12) and updated it with a 26.15.3 installer the way the
  updater does (`--updated /S --force-run`): one uninstall entry, the same folder, the new version, the trina-ax://
  handler kept and the app running again; the uninstall removed the entry, files, shortcuts and the handler and kept the
  data folder.
