## Goal

A team member asked: "Online status: see if someone is online, away, or offline (a dot on their picture)." The owner
approved it on 2026-11-08. People in rooms and DMs see whether the other person has the app open and is at it, before
they write, as in Slack. Web, the desktop app and the phone app all load the same web UI, so one change covers them.

## Reference check (Slack)

Read: Slack help "Set your Slack status and availability" and the developer page "User presence and status".

Copied:
- Active = at least one app connected and not marked away. Several devices: the most online one counts.
- Away after 10 minutes without activity on a computer; away as soon as the phone app is left or closed.
- "Set yourself as away" from the profile menu, and back with "Set yourself as active". A manual away overrides the
  automatic state and stays across connections until changed.
- Bots get no automatic presence: the AI (@트리나) has no dot.
- No "last seen" anywhere.

Skipped:
- Slack has two values (an offline person shows as away). The request asks for three: offline shows no dot.
- The "notifications paused" mark on the dot, status emoji and text (the owner dropped the one-line status:
  docs/DECISIONS.md "한 줄 상태는 쓰지 않는다"), automatic statuses (huddle, focus, working hours).
- A dot on a group DM's row (Slack shows none: whose would it be?). Its member list shows each person's.
- Slack's desktop app watches the whole computer's idle time; a web page sees only its own input, so a hidden page
  simply gets none (away 10 minutes after the last input on a computer).
- Setting yourself away on the phone (Slack has it in the phone's profile menu): our phone app has no account menu; the
  item is in the computer's account menu only.

## Scope

In:
- **States.** Each window says `active` or `idle`. A person is online when a window of theirs is active and they did
  not set themselves away; away when a window is connected but none is active, or they set themselves away; offline when
  no window is connected for 30 s (a reload or a relay reconnect does not flicker). A change is told after it holds
  1.5 s, so a quick back and forth tells nobody.
- **The page.** No input (pointer, keys, touch, wheel, focus) for 10 minutes: idle. On a phone (the phone app, or a
  browser whose only pointer is a finger) a hidden page is idle at once and a visible one active. Input or the page
  coming back: active. The page sends a frame only when its own state changes, and again after each `hello` (the server
  forgets windows on a reconnect); never queued while disconnected.
- **On the wire, the socket the app already keeps** (`/api/ws`, no second channel). A control frame (no seq, never
  replayed, like `hello`): `presence {full: true, people}` right after `hello` and any replay (only people who are not
  offline), then `presence {full: false, people}` with changes, a few batched. Each entry is `{id, state}`. Nothing
  else: no device, window count or time. Client frame `presence {state: 'active' | 'idle'}`.
- **Who sees it.** Everyone signed in to this team server (one team per server), and nobody else. Only active
  accounts appear; disabled and deleted ones never (their sockets close, and the server checks again before telling).
  The AI is not an account and has no dot; there are no other bot accounts.
- **Manual away: included**, as one item in the existing account menu (computer sidebar): "자리 비움으로 표시", then
  "접속 중으로 표시". `PUT /api/me/away {away}`; kept in `users.prefs` JSON as `away` (no migration), shown back in
  `Me.user.prefs.away`; `PATCH /api/me` cannot set it. Kept until changed, as in Slack.
- **Where the dot shows.** The sidebar's DM rows; the DM rows of the conversations page (the phone's 대화 tab); the DM
  header (on the 24 px picture on a computer; on a phone, which shows no picture there, a dot before the name); each
  person in a room's member list (me too); my own picture in the account row. Not on message avatars, team room and
  group chat rows, the people picker or the @ menu. There is no profile popover or hover card to put it in.
- **Look.** Online: a filled dot in the `ok` green. Away: a hollow dot (a 2 px `faint` ring with the background inside).
  Offline: no dot. A 2 px ring in the colour behind the picture (following a row's hover and current colour), like
  Slack. 8 px on 20–28 px pictures, 10 px on 32 px. Words: "접속 중" / "자리 비움" / "오프라인" as the shared tooltip on a
  computer and as the picture's label for screen readers (offline is read in the header and the member list only),
  in all five languages.
- **Last seen: no** (Slack shows none for offline; it would also tell when someone worked).

Out: last seen, a do-not-disturb mark, status text, presence in the people picker, the @ menu or on message avatars,
group chat rows, native app changes (none needed: the WebView's `visibilitychange` is enough), any history of states.

## Risks

- No migration (the highest on `dev` is 265; the parallel branches take 266 and 267).
- Privacy: only the state goes out. Admins learn nothing members do not.
- Load: one small frame per change per open window; the page sends only changes, the server tells a change once it
  holds. A reconnect wave after a restart sends one list per window, of the people not offline only.
- Old pages ignore the unknown control frame (not a known event, so no reload) and send no state: their windows count
  as active while open. A new page on an old server gets an `error` frame for its state, which it ignores.
- The hub change touches every socket: the full web e2e runs once.
- Phone: an iPhone may keep a suspended app's socket open until the WebSocket idle timeout (120 s) closes it: away
  first (the page goes idle when hidden), then offline.

## Result

Built as planned, with no migration. Server: `realtime/presence.ts` (the state machine on an injected clock, started by
the chat runtime on its hub), `Hub.sendControl` and `Hub.connectedUsers`, `PUT /api/me/away` (kept in `users.prefs`).
Web: `lib/presence.ts`, `store/presence.ts`, `components/Presence.tsx`; dots on the sidebar's and the conversations
page's DM rows, the DM header (a dot before the name on a phone), the member list and the account row; the account
menu's first item "자리 비움으로 표시". Measured: 8 px dots on the 20 and 24 px pictures, 10 px on 32 and 40 px, a 2 px
ring in the row's colour (hover and current too); rows 14 px (17 px on a phone), the header 16 px (17 px).

Changed after the independent review: the hub no longer tells `open` for a socket that was dropped while its hello or
replay went out (presence kept such a window for good); an account turned off is offline at once instead of after the
30 s grace; one person's changes are told at most once per 5 s; for 15 s after a server start the whole list waits, so
a deploy does not take every dot off the screen; the page works its state out again after each hello. Not done from the
review: a `PATCH /api/me` answer that arrives after "자리 비움으로 표시" can show the old menu word until the account is
read again a moment later (cosmetic). The account menu e2e now expects the new first item. PR: see the PR that links
this plan.
