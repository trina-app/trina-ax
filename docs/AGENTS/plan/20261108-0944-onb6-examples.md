## Goal

The example viewer from #192 says "예시를 준비하고 있어요" for every kept skill. With no automatic deck (v6.2), these
examples are the only result a new owner sees before their own first run. This makes one example per kept skill per
language (8), made by the real skills on the fictional company 예시커피 / Example Coffee, and registers them so the
viewer shows them.

## Scope

In:
- Inputs, hand-written and marked fictional: `examples/data/example-coffee/{ko,en}/`: the company intro (one page),
  the type-only wordmark (#3B2A20, #E9D8C4), and for 자연스러운 글 one AI-sounding paragraph. No photos.
- Runs on a local dev server with a real AI (this Mac's subscription seat), one team per language, the company profile
  filled from the intro file, no web search (deck tier `quick`): 회사 소개서, 카드뉴스, 홍보 영상, 자연스러운 글, each
  through its form message, at most 2 tries each.
- Outputs (EXAMPLES-PLAN.md §3):
  - `web/public/skill-examples/<locale>/intro-deck.webp`: cover + 2 slides, 1280 wide;
  - `…/card-news.webp`: cards 1–3 of 5;
  - `…/promo-video.webp`: 3 frames of the 18 s video and the label "18초 영상" / "18-second video";
  - `resources/skill-packs/work/<locale>/humanizer/EXAMPLE.md`: before → after, front matter `fictional`, `company`,
    `made`, `engine`, `skillHash`.
  Each image a 2× Playwright screenshot of the artifact, WebP quality 80, at most 90 KB.
- Registration in `PACK_EXAMPLES`; the mock server serves the same examples; unit test: every kept skill × {ko, en}
  has its example within the limits, and each example records the hash of the SKILL.md it was made from; web unit and
  e2e: the viewer shows the real image and text, no placeholder.

Out:
- id, ja, es examples: those teams get the English one (their skill text is English).
- An MP4 in the repository: three stills stand for the video.

## Steps

1. Inputs in `examples/data/example-coffee/`.
2. Dev server per language (fresh data folder, deleted after), owner, profile, brand folder with the intro and the
   wordmark, the two packs installed; run the four skills.
3. Capture and compress; write the two EXAMPLE.md files.
4. Register; tests; mock server.
5. Checks; PR to `dev` with the gallery.

## Risks

- Public repo: invented names only (예시커피 / Example Coffee checked by web search: no real business), the reserved
  domain `coffee.example`, no real people, logos or photos.
- A SKILL.md change later makes its example stale: the recorded hash and a test say so.
- Web build size: about 0.5 MB of images, loaded only when the viewer opens.
