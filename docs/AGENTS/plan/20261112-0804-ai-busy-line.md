# Chat: say "The AI service is busy" while the engine retries a 429 (QA TC-388)

- Date (UTC): 2026-11-12 08:04
- Branch: `fix/ai-busy-line`
- Status: done
- Where: `server/`, `shared/`, `web/`. Why: a status for a running answer in the team server and its web app
  (see docs/REPOSITORY-RULES.md)
- Version impact: patch, a new status line for an existing state; no API removed

## Goal

QA TC-388: when the AI provider answers 429 (a short rate limit), Claude Code retries by itself. The model proxy passes
the 429 through, and the person sees only the thinking dots for minutes. Show a short line in that chat while the engine
retries: "The AI service is busy. Still trying…". Clear it when text or a step arrives, or when the answer ends.

## Scope

In:
- Model proxy (Anthropic path, `server/src/proxy/model-proxy.ts`): a short 429 or a 529 (overloaded) tells the turn
  `{ type: 'busy', on: true }`; a 2xx answer tells it `on: false`.
- The turn (`server/src/chat/turn.ts`) sends a realtime frame `turn.busy` { chatId, messageId, turnId, busy } to the
  person's windows when the state changes (personal chats; not room answers).
- Web: the chat store keeps the busy answers; `Messages.tsx` shows the line under a running answer. Five languages.

Out:
- Room answers (they have their own run status), and the Codex path (it waits out a short 429 inside the proxy).

## Steps

1. `shared/src/api/ws.ts`: the `turn.busy` frame.
2. Proxy event and the turn's frame.
3. Web store, live dispatch, the line, `chat.providerBusy` in en, ko, ja, es, id.
4. Unit tests: proxy + turn (a short 429, then an answer: busy true, then false), web store (set, cleared by text, a
   step, the end).
5. DECISIONS entry, changelog fragment.
6. Repeat TC-388 (`tests/stress/tc388-429.ts`) on the Mac mini.

## Risks

The five app languages; nothing in the database; one new optional frame (an older web app ignores it).

## Tests

`bun run typecheck`, `bun run check:i18n`, `bun run check:docs`, the proxy and chat unit tests, the web store unit
tests.

## Result

Built as planned. Review (a fresh agent) found one blocking bug: the web store dropped `turn.busy` for an answer that
already had text or a step. Fixed (only an ended answer ignores the frame), with a test. Also added: a 529 test, the
line hidden while a card waits for the person, Korean wording, "Not covered" in DECISIONS.

TC-388 re-test (real Claude Code 2.1.305, the real proxy, a fake model service that answers 429 for 120 s, 30 people,
Mac mini):
- concurrency 3: the 3 running answers got `turn.busy` true during the 429 window and false when the service answered
  again; the 27 waiting answers showed their queue position. 30/30 answered; after recovery 3/3 new questions answered.
- concurrency 8: 8 of 8 running answers got busy true, then false. 30/30 answered; after recovery 3/3.
- Mac mini unit tests (`proxy-subscription`, `b-credential-failover`, `b-chat`, `contracts`): 83 pass, 0 fail.
