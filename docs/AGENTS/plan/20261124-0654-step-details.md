## Goal

Owner, 2026-11-24, on a private research chat: about 50 rows read "Bright Data · Search Engine" with no query, address
or result, and some rows had a minus icon with no words. "클로드는 각각 스텝에서 뭘하는지 조금 더 디테일하게 보여주지
않나?" Claude Code shows each call's key input (a query, an address, a path, a command) and a short result line.

For the person who ran the chat, every tool step (connectors included) shows its key input after the tool name and a
short result where one is cheap and sure ("10 results", "Declined", "Failed"). The minus icon says in words what it
means. Long runs of the same tool fold into one row that opens.

## Scope

In:
- `stepKeyInput(input, schema)` in shared/src/step-labels.ts: one key input chosen from the call's arguments and the
  tool's input schema, never from a list of tools or services. Secrets never show (key names, values that look secret
  or random), long values are cut, an address loses its query.
- Connection tools (a service's own tools, `call_tool`) and any tool without words of its own: `<name> · "<query>"` /
  `<name> · <address or path>`. `api_request` adds the path without its query. Built-in tools keep their labels.
- `Step.outcome` (optional): `count` (items listed in a service's JSON answer) and `end` (declined, no answer,
  refused, failed). A service's error answer: its first line as the step's detail.
- Web: the row shows the outcome in words next to the line; a failed step the AI got past says "Didn't work" in place,
  not only in a tooltip; 3+ calls in a row of the same tool fold into one row "<name> · 12 calls" that opens.

Out: per-call result previews of whole answers (Claude Code's ctrl+o view); Slack and the phone app keep their lines.

## Privacy

Teammates in shared and project chats keep the generic verb (#488, docs/decisions/20261124-shared-chat-card-steps.md):
every new detail is in the label, the detail or `outcome`, and `stepRepeatsCard` already gives other viewers the verb
alone for every connection tool; `outcome` is dropped for them too. Their AI's record is unchanged.
