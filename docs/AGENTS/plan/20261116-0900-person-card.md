# A person card: click someone in a room, then message them

- Date (UTC): 2026-11-16 09:00
- Branch: `feat/person-card`
- Status: done
- Where: Team AX core (`web/src/components/`, the rooms screens). Why: rooms and people are core (see docs/REPOSITORY-RULES.md)
- Version impact: patch, a small card on the web screens; no API change

## Goal

In a room, a click on a person's photo or name beside a message did nothing. The owner (2026-11-16) wants to click the
person and message them directly. A small card opens: photo, name, their title, and one **Message** button that opens
the 1:1 chat with them (the existing one, or a new one) with the message box ready.

## Scope

In: one shared card (`web/src/components/PersonCard.tsx`) on the shared menu (`rooms/MenuButton.tsx`: a popover on a
computer, a bottom sheet on a phone). Opened from a message's photo and name (the room and a thread), an @mention of a
person in a message, and a row of the room's member list. Only data the people directory already gives (name, title,
status, photo, the Guest tag). Message only for someone the directory lists (the server's own 1:1 rule), never for
yourself (a link to your profile settings instead). No card for an app, the AI or someone the directory does not list.
Out: a profile page, status editing, huddles, e-mail / role / groups on the card (the directory never gives them), the
faces of the "n replies" line (they stay one button that opens the thread), server changes.

## Steps

1. `MenuButton`: a `body` slot above the items (always shown), `bare`, `inline`, `closeOnScroll`.
2. `PersonCard.tsx`: `PersonButton` (the trigger around a face or a name) and the card.
3. Use it in `RoomMessages` (face, name), the mention span (`Markdown.tsx` / `lib/messageMarkdown.ts`) and `MembersDialog`.
4. i18n (en first, then ko, ja, zh, es, id), unit tests, an e2e spec, docs, a changes/ fragment, a decision file.

## Decisions

`docs/decisions/20261116-person-card.md`.

## Risks

Every message face becomes a button: no layout shift (same box), and a long press on a touch screen must still open
the message's menu.

## Tests

`bun run typecheck`, `check:i18n`, `check:docs`, web unit tests, the new e2e spec and the rooms e2e specs that touch
message rows.

## Result

Built as planned. The card shows only what the people directory gives (name, title, status, photo, Guest tag); the faces of the "n replies" line stay one button that opens the thread; people outside the directory, the AI and apps have no card. Decision: `docs/decisions/20261116-person-card.md`.
