# One menu list, one delete-and-leave helper, one word per action (UX package C)

- Date (UTC): 2026-11-26 10:24
- Branch: `feat/shared-menus`
- Status: in progress
- Where: web/ (menus of chats, rooms and projects; i18n). Why: the owner asked for shared components managed in one
  place ("컴포넌트화, 공통관리") after the 11-26 UX audit (see docs/REPOSITORY-RULES.md: UI in web/).
- Version impact: minor. Menus gain items (Copy link and Rename on the project page, Rename in a phone room's menu,
  Undo after a project goes to the trash) and the order changes everywhere; no API change.

## Goal

The audit found that the same action sits in a different place, has a different name and asks in a different way
depending on the screen: Copy link is item 2 in one menu and item 9 in another, a project's page says "수정" where its
row says "이름 바꾸기", deleting a chat has Undo but trashing a project does not, "프로젝트 나가기" is red in one menu
and not in another. People learn a menu once; after this every chat, room and project menu reads the same way.

## Scope

The independent review (opus, 2026-11-26) approved with required changes; they are folded in below.

In:

1. **One item list** `web/src/components/menus/entityMenu.tsx` (`MENU_ORDER`, `menuItem`, `orderMenu`): one label, icon
   and place per kind. Every title and row menu of AI chats (`ChatTitleMenu`, `useChatMenuItems`), rooms
   (`useRoomMenuItems`, `RoomMenu`) and projects (`useProjectMenuItems`, the project page's name menu) builds its items
   with it; each surface only says which kinds it offers and what they do. Order:
   0. search (the room header's "이 대화에서 검색" stays first, as ⌘F: docs/decisions/20261120-search-shortcuts-slack.md)
   1. pin / unpin, then move to section / remove from section (rooms and AI chats alike: list keeping)
   2. notifications: a room's 알림 설정, a shared chat's 알림 끄기/켜기
   3. copy link, open in the app
   4. rename (a group chat's "비공개 채널로 만들기" takes this slot)
   5. move: a chat's 프로젝트에 추가/변경, a room's 프로젝트로 만들기 / 1:1's "New project with …"
   6. share, members, invite, apps, continue in a chat only you see, project settings
   7. hide / show again, leave / leave project, delete / move to trash (always last; danger style for leave and delete)
   A phone's sheet still moves danger items under a line at its end (MenuButton sheetOrder), which this order already
   does; a phone room header's "threads with new replies" (a status) stays above the list. RoomMenu's old splices
   (pin, invite, search, sections) go: `orderMenu` places them.
2. **Gaps closed**: "앱에서 열기" in a room header's and a project page's menu too (`pageOpenInAppHref`, the desktop app
   already opens `/rooms/<id>` and `/projects/<id>`); the project page's menu gets Copy link and Rename (the row's
   prompt), its "수정" becomes "프로젝트 설정" (the edit dialog); a phone room header gets Rename back.
3. **One destructive helper** `web/src/lib/destructive.ts` `destructive({ confirm?, run, done })`: a confirm only where
   one exists today, then one toast, with `common.undo` when an undo is given. Callers: chat delete (confirm + undo),
   chat and room hide (undo), chat leave, group chat leave (new toast), project leave (confirm + toast), project to the
   trash (confirm + **Undo** offered from the project the server answers with, only when it has `canRestore`, run as
   `trashProject(reply, false, true, onShown)` on the same optimistic key so a refusal says the server's words; the
   creator who does not manage it gets `'gone'` and no Undo), project deleted for good (confirm + toast), scheduled
   task on the Scheduled page (confirm + new toast; no restore route, no undo).
4. **Leave is always danger**: `leaveItems` through `menuItem('leave')`; the share dialog's leave button
   `variant="ghost-danger"`.
5. **One i18n key per action**, existing keys made canonical (no new `menu.*` keys), duplicates removed in all six
   locales: copy link `rooms.menu.copyLink` (drop `integrations.requests.copyLink`, `teamLink.copyLink`,
   `members.copyLink`); link copied `rooms.menu.linkCopied` (drop `auth.linkCopied`); copied `common.copied` (drop
   `roomApps.copied`; `files.ev.copied` is a file-history event, not feedback: kept); undo `common.undo` "실행 취소"
   (drop `shareCard.undo`, `steps.memoryUndo`, `chat.project.undo`, `files.findWork.undo`, `projects.undoRemove`,
   `postedCard.undo`), `common.restore` "되돌리기" stays for the trash; delete `common.delete` (drop
   `allowances.delete`, `postedCard.delete`, `scheduledCard.delete`, `schedules.delete`); deny `devEnvSite.deny` "허용
   안 함" (drop `browser.deny`); hide `chat.hide` (drop `rooms.menu.hide`, `rooms.menu.hideDm`; `chatFile.hide` is a
   panel's close, kept); trash `files.moveToTrash` "휴지통으로 옮기기" (drop `projects.moveToTrash`); rename
   `chat.rename` (drop `rooms.info.rename`, `files.rename`, `credentials.rename`). One AI chat is "채팅" in Korean (its

## Decisions

`docs/decisions/20261126-shared-menus.md`: one item list and order for chat, room and project menus; destructive
actions through one helper (confirm only where one exists, undo where the server can take it back); one key per
action. Supersedes in part "Guests from Invite people" (invite after the pin), the QA TC-257 phone header without
rename, and 20261123-do-then-undo.md's card words (취소 / 지우기 → 실행 취소 / 삭제).

## Risks

- Many existing tests pin item order, labels or keys: updated in the same PR.
- PR #641 (chat fork) edits `ChatTitleMenu` "Continue in a chat only you see": small conflict, whoever lands second
  rebases.
- Locale files are large and shared by every PR: only removals and value changes of the listed keys.
- No migration, no server change, no permission change (Undo of a trashed project uses the existing restore route and
  is only offered when `canRestore`).
