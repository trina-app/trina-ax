# One menu list, one delete-and-leave helper, one word per action (UX package C)

- Date (UTC): 2026-11-26 10:24
- Branch: `feat/shared-menus`
- Status: in progress
- Where: web/ (menus of chats, rooms and projects; i18n). Why: the owner asked for shared components managed in one
  place ("컴포넌트화, 공통관리") after the 11-26 UX audit (see docs/REPOSITORY-RULES.md: UI in web/).
- Version impact: minor. Menus gain items (Copy link and Rename on the project page, Rename in a phone room's menu,
  Undo after a project goes to the trash) and the order changes everywhere; no API change.

## Goal

The audit found that the same action sits in a different place, has a different name and asks in a different way
depending on the screen: Copy link is item 2 in one menu and item 9 in another, a project's page says "수정" where its
row says "이름 바꾸기", deleting a chat has Undo but trashing a project does not, "프로젝트 나가기" is red in one menu
and not in another. People learn a menu once; after this every chat, room and project menu reads the same way.

## Scope

In:

1. **One item list** `web/src/components/menus/entityMenu.tsx`: the canonical order and the one label/icon per item
   kind. Every title and row menu of AI chats (`ChatTitleMenu`, `useChatMenuItems`), rooms (`useRoomMenuItems`,
   `RoomMenu`) and projects (`useProjectMenuItems`, the project page's name menu) builds its items with it; each
   surface only says which kinds it offers and what they do. Order (groups separated in the code, not by lines):
   1. pin / unpin, then move to section / remove from section (list keeping, docs/decisions/20261121-personal-sidebar-sections.md)
   2. notifications: a room's 알림 설정, a shared chat's 알림 끄기/켜기
   3. copy link, open in the app
   4. rename (a group chat's "비공개 채널로 만들기" takes this slot)
   5. move: a chat's 프로젝트에 추가/변경, a room's 프로젝트로 만들기 / 1:1's "New project with …"
   6. people and tools: share, members, invite, apps, search in this conversation, continue in a chat only you see,
      project settings (the edit dialog)
   7. hide / show again, leave / leave project, delete / move to trash (always last; danger style for leave and delete)
   The room header's "이 대화에서 검색" moves from first to group 6 (⌘F stays the fast way). A phone room header's
   "threads with new replies" stays first (a status, not an action on the room).
2. **Gaps closed**: "앱에서 열기" for rooms and projects too (same rule as chats: a computer's browser on macOS or
   Windows, `openInAppHref` with `/rooms/<id>` or `/projects/<id>`); the project page's menu gets Copy link and
   "이름 바꾸기" (the row's prompt, `useRenameProject`), and its "수정" becomes "프로젝트 설정" (the edit dialog: shared
   chats setting, instructions) in group 6; a phone room header gets Rename back.
3. **One destructive helper** `web/src/lib/destructive.ts` `destructive({ confirm?, run, done })`: asks only when a
   `confirm` is passed (only where one exists today; no new confirms, following a4e889c87 / docs/decisions/20261123-do-then-undo.md),
   runs, then one toast: the result text, plus `common.undo` when an undo is passed. Callers: chat delete (confirm +
   undo, as now), chat hide and room hide (undo, as now), chat leave (confirm + "left" toast, as now), group chat leave
   (confirm + a new "left" toast), project leave (confirm + toast, as now), project to trash (confirm + **new Undo**
   that restores it when the server says I may: `Project.canRestore`), project delete for good / any other delete
   (confirm, toast, no undo: cannot be undone), scheduled task delete on the Scheduled page (confirm + a new "deleted"
   toast; the server has no restore, so no undo). The AI's Scheduled card keeps its in-card state (it already says
   "deleted" in place).
4. **Leave is always danger**: `leaveItems` (project page and project rows) gets `danger: true`; the share dialog's
   "이 채팅에서 나가기" uses `variant="ghost-danger"` instead of a ghost button recoloured with `text-danger`.
5. **One i18n key per action**, duplicates removed from all six locales (en ko ja zh es id):
   - copy feedback: `common.copied` = "복사했어요"/"Copied" (drop `files.ev.copied`, `roomApps.copied`); link copied:
     `rooms.menu.linkCopied` (drop `auth.linkCopied`); copy link item: `rooms.menu.copyLink` → `menu.copyLink`
     (drop `integrations.requests.copyLink`, `teamLink.copyLink`).
   - edit message: `chat.editMessage` stays the one key (drop `chat.edit`); generic edit stays `common.edit` ("수정").
   - undo: `common.undo` = "실행 취소"/"Undo" everywhere (drop `shareCard.undo`, `steps.memoryUndo`,
     `chat.project.undo`, `files.findWork.undo`, `projects.undoRemove`, `postedCard.undo`); `common.restore`
     ("되돌리기"/"Restore") stays for bringing back from the trash.
   - delete: `common.delete` = "삭제" (drop `allowances.delete`, `postedCard.delete`, `scheduledCard.delete`,
     `schedules.delete`); "지우기" stays only for Clear / Discard / Remove, which are other actions.
   - deny: one key `common.deny` = "허용 안 함"/"Don't allow" (drop `browser.deny`, `devEnvSite.deny`).
   - hide: one menu key `menu.hide` = "내 목록에서 숨기기"/"Hide from my list" for chats and rooms (drop `chat.hide`,
     `rooms.menu.hide`, `rooms.menu.hideDm`); `common.hide` stays for hiding a card or panel.
   - trash: `files.moveToTrash` = "휴지통으로 옮기기" (drop `projects.moveToTrash`).
   - rename: `common.rename` = "이름 바꾸기" (drop `chat.rename`, `rooms.info.rename`, `files.rename`,
     `credentials.rename`).
   - one AI chat is "채팅" in Korean everywhere (its list stays "기록", a room stays "대화"): `chat.menu`,
     `chat.deleteTitle`, `chat.deleted`, `chat.restoreFailed`, `chat.project.removed`, `chat.project.moveFailed`,
     `chat.inTrash`, `chat.shareFiles.*`, `sidebar.noChats`, `sidebar.trash` and the like, found by a scan of `chat.*`
     and `sidebar.*` values.
   - `groups.originTitle`, `groups.originWarning`, `groups.originGone` in 해요체.
   Package B (message actions) and A (composer) own `Messages.tsx`, `RoomMessages.tsx`, `ChatThreadPanel.tsx` and the
   composers: keys used only there (`rooms.copied`, `rooms.editLabel`, `chat.edit` in Messages) get the canonical text
   now and the PR says which key they switch to; the duplicate is deleted in the same PR only when no A/B file uses it.

Out: the menus' place on screen (the AI chat's title ▾ on the left, as Claude has it; a room's "···" on the right, as
channel headers have it) — the items and their order are what people read; moving the menus is a layout change for
later if the owner wants it. Copy button behaviour (package B). Message action menus (B).

## Decisions

`docs/decisions/20261126-shared-menus.md`: one item list and order for chat, room and project menus; destructive
actions through one helper (confirm only where one exists, undo where the server can take it back); one key per
action. Builds on docs/decisions/20261123-do-then-undo.md and docs/DECISIONS.md "Pinned chats" / "대화 숨기기".

## Risks

- Many existing tests pin item order, labels or keys: updated in the same PR.
- PR #641 (chat fork) edits `ChatTitleMenu` "Continue in a chat only you see": small conflict, whoever lands second
  rebases.
- Locale files are large and shared by every PR: only removals and value changes of the listed keys.
- No migration, no server change, no permission change (Undo of a trashed project uses the existing restore route and
  is only offered when `canRestore`).
