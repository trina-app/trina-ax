# Phone push stays quiet while the computer is in use, also with the Mac app behind other windows

- Date (UTC): 2026-11-16 06:44
- Branch: `fix/away-os-idle`
- Status: in progress
- Where: server (presence, a new `/api/me/computer` call), web (presence frames), desktop (main process report). Why:
  "Phone notifications only when I'm away" rang the phone while the owner was working with the Mac app in the back.
- Version impact: patch: a bug fix; the new call is additive (an older server answers 404 and the app stops asking).
  Target 0.5.10.

## Goal

Settings › Notifications says "While you're using Trina … not on your phone". With the Mac app open behind other
windows and the person working on the computer, a notice must show on the Mac only. Idle computer, locked screen or no
app: the phone rings.

## Root cause

A covered or minimized window is hidden to Chromium, and Electron throttles it (backgroundThrottling, default on).
Measured on Electron 44.7.2 with the app's BaseWindow + WebContentsView: the page's 20 s ping fired once, then not for
more than 4 minutes; main → page messages (the 30 s system-activity tick) came 24-34 s late. The page sends its
presence state only on a change, so the server heard nothing from the window for over 60 s
(PRESENCE_SILENT_MS) and `inUse` left it out: `phoneDecision` said send. Same code in v0.5.7 and dev.

## Scope

In:
- Desktop main process (not throttled) posts `{ idleMs, locked }` to the open, signed-in team every 30 s and at
  once on lock and unlock (`POST /api/me/computer`). Nothing while signed out (401 stops it until the next sign-in);
  a 404 (older server) stops it for that team.
- Server: Presence keeps the latest computer report per person, in memory. `inUse` is true while a report is fresh
  (≤ 60 s), unlocked and idle below 10 minutes, with or without a connected window. A fresh locked report means away
  even if a window still counts as active.
- Web: the page re-sends its presence frame on every desktop tick (helps 0.5.7 desktop apps with a server update alone).
- Wording: a locked screen means away (decision file), comments in away.ts / presence.ts / web presence.
- Tests: background desktop window with recent OS input → cancel; OS idle beyond 10 min → send; no window → send;
  locked → send; browser tab hidden → idle (current behaviour, documented).

Out: backgroundThrottling stays on (battery). Teams the desktop app has not opened are not reported (one team view
at a time).

## Steps

1. Shared contract `computerActivity` endpoint; server route + Presence.computer.
2. Desktop `ComputerReporter` in common/system-activity.ts, wired in app-window.ts.
3. Web tracker resends on system ticks.
4. Tests, decision file, changes fragment.
