# Per-answer caps and prompt cuts closer to Claude Code

- Date (UTC): 2026-11-18 10:42

- Where: Team AX core (`server/src/chat/`, `server/src/tools/`, `server/src/files/`, `shared/src/api/`). Why: chat,

- Version impact: patch, higher limits and honest prompt text, no new feature

## Goal

The AI should work like Claude Code on long jobs. Today it stops or is cut where Claude Code is not:

1. make_file's description says "Limits: 30 slides, 20 images, 100,000 characters" on every server, but those limits
   only apply with safe operations on. The AI may refuse or split a 40-slide deck for nothing.
2. One answer may write at most 50 MB / 200 files and take at most 150 tool rounds; then the person has to say
   "continue". The disk floor (system/storage.ts) now protects the disk, so the write cap is no longer the disk guard.
3. Team rule files (10 files × 4,000 characters), skills (16,000 characters) and memories (300 characters each, a 4 KB
   block) are cut; a cut file or memory is not mentioned to the AI.

## Scope

In:
- The make_file limit sentence only when safe operations are on.
- Writes per answer: 1 GB / 2,000 files (guests keep 50 MB / 200). Tool rounds: default 500 (guests keep at most 150).
  The existing "This task ran long, so it paused here" + Continue button is the continue path (no new UI).
- Rule files 50 × 20,000 characters, with a total budget for all rule text; skills 100,000 characters; memories 1,000
  characters each, a 32 KB block. Every cut says so in the prompt and how to read the rest (the read tool).
- UI copy that names the old numbers follows the shared constants.

Out: the API engine's own 30 rounds, sub-agent rounds, the image budget, the history cut (other items of the audit).

## Steps

1. tools/index.ts: the limit sentence behind `safeOpsEnabled()`.
2. config.ts + one helper for the turn's write limits by person (guest or not); every check uses it.
3. entities.ts default 500; turn.ts caps a guest's rounds at 150.
4. prompt.ts / skills.ts: new numbers, cut notes, total budget for rule text.
5. memories: shared MEMORY_TEXT_MAX 1000; the remember tool description from the constant.
6. Tests that fail on the old code; decision file; changes file; QA rows.

docs/decisions/20261118-limits-caps.md.

## Risks

Prompt size: more rule text and memories go into every request. Bounded by the total rule budget and the 32 KB memory
block; measured in the decision file. Guests: unchanged limits, tested.

## Tests

`bun run check:prepush` (Bun 1.3.12), new unit tests for each limit and each cut note, the touched area's tests.

## Result

Built as planned (docs/decisions/20261118-limits-caps.md). Two additions: a total budget of 100,000 characters for all
rule files (the files past it are named, with a note to read them), and the skill tool's result is cut at 22,000 tokens
(Claude Code cuts a tool result over 25,000), with the same note. The 128 KB skill file limit stays (about 43,000 Korean
characters). Real-AI check on a copy of the QA team: with a 24,000-character rule file whose answer is in the cut part,
the AI read the file and answered. PR: fix/limits-caps to dev.
