## 1. What Claude Code's auto mode does

Source: Anthropic, "Auto mode is now the default in Claude Code"
(https://claude.com/ko/resources/articles/auto-mode-default-in-claude-code, read 2026-11-23).

- Each tool call goes to a classifier, not to a permission prompt. Safe calls run. Calls that are irreversible,
  destructive or go out of the person's environment are blocked. Claude then finds a safer way or asks.
- Data exfiltration is a deny category that always holds. Pushes check if the target is public, private or trusted.
  Destructive git commands check the repository state first.
- Permission rules run first. Tool results are scanned for prompt injection, and calls are checked against what the
  person asked for.
- After 3 blocks in a row, or 20 in one session, Claude Code goes back to manual approval.
- The person switches the mode (Shift+Tab, or the mode menu in the desktop app). An admin sets a default
  (`defaultMode`) or turns auto mode off (`disableAutoMode`).
- Their numbers (vendor numbers): people approve 97% of prompts; people caught 13.6% of risky commands, auto mode 89%;
  the human catch rate fell from about 17% to about 5% after 50 prompts. The lesson for Trina: many cards train people
  to press "allow" without reading. Fewer, sharper cards are safer.

## 2. What auto mode means in Trina

Trina does not use Claude Code's permission prompts. The engine runs with `--permission-mode dontAsk` and a fixed tool
list (`server/src/engine/claude.ts`, the `args` of the turn). Every ask the person sees is Trina's own card, raised by
Trina's own tools. This plan does not change the engine flag. Claude Code's own auto mode stays off: it does not know
Trina's floor, it adds a model call to every tool call, and the Codex engine does not have it. Trina's auto mode works
in Trina's tools, for every engine.

**Definition.** With auto mode on, a card whose kind is marked `auto` in the ask registry does not show when the call is
free of the floor. Trina runs the call, shows a step "자동 모드로 진행했어요" with the undo the action already has, and
writes an audit row. Every other card shows as before.

**Auto mode is not Always.** Three rules keep them apart:

1. Auto mode never skips the floor (section 3). Under Rule A, the person's own Always skips floor items 1 and 2.
   Auto mode does not.
2. Auto mode never writes `card_always_allow` rows and never reads them as its own. When the person turns auto mode
   off, all the cards it skipped come back.
3. The person's explicit Always still wins (Rule A). With auto mode on or off, an Always for a kind skips that card as
   it does now.

So auto mode is weaker than Always and wider than one card: one switch for "the safe kinds", without a press on each
first card.

## 3. The floor: always asks, also in auto mode

The Batch 5 floor (`docs/decisions/20261123-do-then-undo.md`, `chat/explicit-send.ts floorFree`), plus the items
Dion's brief names. Auto mode never removes these:

1. Sending to someone the person did not name or clearly refer to.
2. Showing people content they could not see, from a source the person did not name (a chat, a room, a connected
   service, the in-app browser, a file shared with the person, a team file nobody named).
3. Real money and team credits (Higgsfield video, paid connector calls, anything with a price).
4. Permanent delete with no trash.
5. A schedule that sends to others while nobody watches.
6. Sharing with new people: folder access, project members, a chat share, a guest.
7. Secrets and sign-ins: a key, a token, a login a command can use (`dev.login`), a new connection (`conn.connect.*`),
   an office-network address (`site.office`).
8. Anything that changes what other people's AI does: a team, group or project skill or rule (`skill.save`).
9. The AI's own questions (`ai.ask_user`) and choices between people (`*.pick`). They are not permissions.

**Open for Dion (D1):** the brief says "deleting always asks". The Batch 5 floor says only a permanent delete with no
trash. `delete_files` moves to the trash, and the trash undoes it. This plan proposes: auto for the person's own files
in their own folder; ask in places other people see. Dion decides.

## 6. Who can turn it on

- **Person:** one setting per person, `auto_mode` (on or off). The person changes it in the composer's mode pill and in
  Settings › 트리나에게 허용한 것. It holds in every chat they ask in. (Open D2: one setting per person, or one per chat
  as Claude Code's per-session mode.)
- **Admin:** Admin › Team AI settings gets "Auto mode" with three values, as Claude Code's managed settings:
  - `off`: nobody can turn it on (as `disableAutoMode`). The pill does not show.
  - `allowed`: each person can turn it on; it starts off. (Proposed default for existing teams.)
  - `default`: it starts on for each person who did not choose; each person can turn it off (as `defaultMode`).
- When the team's "Always allow" switch (`roomAlwaysAllow`) is off, auto mode is off too. Both switches mean "the admin
  wants the cards".
- **Guests** never get auto mode. Auto mode does not read the setting of anyone but the person whose turn it is.

## 7. Where auto mode is off

Auto mode works only in a turn the person watches, in the web app, desktop app or phone app (`LIVE_CLIENTS`). It is
off in:

- a scheduled run (only the person's own Always holds there, as now; open D3);
- a Slack turn (Slack never reads or offers Always either);
- a turn of a guest, and a shared chat while a guest is among the people;
- a confidential chat, a draft, a demo server;
- the rest of the answer after the chat read room messages or other people's words, for every `auto-if` kind. This is
  the prompt-injection guard, the same signal `room.change` already uses;
- the rest of the answer after an outside read (a site, a connection, the browser), for the file kinds (`save.wider`,
  `files.*`, `skill.*`) and `conn.write.own`. A site read does not stop `site.web`, `dev.site` or `conn.read.unsure`:
  for them the url gate's own exfiltration checks (marked, echo, redirect, long query, the 30 / 150 budget) are the
  guard. Else auto mode would let only the first site of an answer go;
- the rest of the chat after 3 skipped cards in one answer that the person then undid, or 20 auto approvals in one
  chat in one day. Then the cards come back, with a line "자동 모드를 잠시 멈췄어요" (as Claude Code's 3 / 20 fallback).

## 8. How it works in the code (for the build PR)

`alwaysHere(p, kind)` in `server/src/chat/always-allow.ts` knows only the card kind. It cannot see the call's floor
result, so it is not enough as the only hook. The build adds:

1. `shared/api`: `AUTO_KINDS` (kind → `auto` | `auto-if` | `ask`), next to `CARD_ALWAYS_KINDS`.
2. `always-allow.ts`: `autoHere(p, kind, call)` with `call = { floorFree: boolean; othersRead: boolean; outsideRead: boolean }`. It returns
   true only when the team value and the person's setting allow it, the place is one of section 7, the kind is `auto`,
   or `auto-if` with `floorFree` and the read rules of section 7. `withAlways` gets an optional `call` argument and checks Always
   first, then `autoHere`, then the card.
3. Each tool that raises an `auto-if` card already computes its floor (`floorFree`, `confirmWidening`, the url gate,
   the connector tiers). It passes that result into `withAlways`. No tool gets a new floor rule; the floor stays
   decided once, on the server.
4. `request:*` and `allowance:*` paths (`site.web`, `dev.site`, `conn.*`) call `autoHere` at the place they now read
   their own allowance.
5. Data: migration adds `users.auto_mode` (null = team default) and the team setting `auto_mode` (`off` | `allowed` |
   `default`). Additive only.
6. A tool result line `RAN_UNDER_AUTO`, as `RAN_UNDER_ALWAYS`, so the AI says "자동 모드로 했어요" and never "you
   approved".

## 9. UI

- **Mode pill** under the composer: "묻기" / "자동". One tap changes it. A first tap shows a one-time sheet: what auto

- **Step:** each skipped card leaves a step in the answer: "자동 모드로 진행했어요: {what}" with the action's own undo

- **Settings › 트리나에게 허용한 것:** the switch, and "최근 자동 승인" (the last 50 audit rows of section 10, each with a
  link to its chat).

- Six app languages for every new string (en, ko, id, ja, es, zh). Phone: the pill in the composer bar, the sheet as a bottom sheet.

## 10. Audit trail

- One audit row per skipped card: `action: 'ai.auto_allow'`, `actor` = the person, `detail: { kind, registryId,
  chatId, turnId, rule: 'auto' | 'auto-if', undo: <kind of undo> }`.
- One row per change of the setting: `ai.auto_mode` with `{ on, via: 'pill' | 'settings' | 'admin-default' }`.
- The team value change: `admin.auto_mode`.
- The rows are kept as other audit rows. The person sees their own; an admin sees the team's.

## 11. Safety

- The floor is server code, not a prompt. Auto mode only reads it.
- Prompt injection: `auto-if` kinds stop after an outside or other people's read in the same answer (section 7). The
  recipient and the source checks of Batch 5 stay as they are.
- Fail closed: when any input is missing (no floor result, an unknown kind, a read error), the card shows.
- No new grant is kept. Turning auto mode off restores every card at once.
- The security review of the build PR is done by a fresh subagent, with the floor list of section 3 as its checklist.

## 16. Build notes: what changed from the plan (2026-11-25)

Rebased on `dev` at a6c9e644c. The code moved little; these are the changes:

- **Kinds that stay `ask` for now:** `site.web`, `dev.site`, `conn.read.unsure`, `conn.write.own`. Each one can carry
  data out of the person's environment (a short query or a path is enough), and the brief puts that on the floor.
  They need their own security review (a classifier, phase 5, or a fixed host list). So the `auto` column is on the
  `always:` kinds only, and the registry test fails if a `request:` or `allowance:` kind is marked `auto` or `auto-if`.
- **`files.delete` is `ask`** (D1, section 15).
- **The `auto` column is in the "Kinds" table**, not on each of the 219 entries: `AUTO_KINDS` is keyed by kind, so the
  test compares the two one to one. A kind with mixed entries (`save_wider` also covers `room.change.widen`,
  `move_files` also covers `files.copy.places`) is `auto-if`; those entries show only after a room read, which the
  read rule turns into a card, and `files.copy.places` passes no floor value, so it always asks.
- **The read rule** uses the chat's own marks: "other people" = other authors or a room read (`readRooms`); "outside"
  = `session_tainted` or `others_words` (a site, a connection, the browser, a file someone else wrote). This is
  stricter than section 7: a site read also stops the file kinds for the rest of the session.
- **Security review (fresh subagent, section 3 as the checklist) found no critical issue; fixed:** auto mode's save
  yes was kept as a 12-hour chat approval (now kept for the call only); the move floor read the folder as typed (now
  its real name on disk); the `auto` kinds went after a room read (now no kind goes after other people's words); one
  auto yes lifted the many-items card for the answer (now not); a bulk rename needed only "no room read" (now also the
  person's own folder); the summary's check could add the pause step (now a quiet check).
- **The fallback:** only the 20-a-day pause per chat is built (counted from the `ai.auto_allow` audit rows). "3 auto
  steps undone in one answer" is left out: the server cannot tell reliably that a person undid an auto step.
- **A demo server** has no extra check: its team value is `off` like every team's, and nobody there can change it.
- **Code:** `server/src/chat/auto-mode.ts` (settings, audit, pause count), `chat/always-allow.ts` (`autoHere`,
  `autoAllow`, `withAlways` with an optional `call`, `RAN_UNDER_AUTO`), `chat/turn.ts` (the place's `guestAmong`,
  `reads`, `ranAuto`, `autoPaused`; the step; `widenFloorFree`), `tools/url-gate.ts` (`ConfirmExtra.auto`,
  `TurnPerson.autoOn`), `tools/file-moves.ts`, `chat/skill-files.ts`, `chat/tools.ts` (the floor of each `auto-if`
  card; `autoNote` on the tool result), migration `455_b_auto_mode.sql`, `shared/src/api/ai-allowances.ts`
  (`AUTO_KINDS`, the auto mode API), web (`AutoModePill`, `AutoModeSettings`, Admin `AutoModeField`).
- **The QA count of section 5** (asks with auto mode off and on in 4 to 6 new flows) is still to do on qa.trina.app
  after the merge, with the QA team set to `allowed`.
