# Small wording fixes: Mac update notice, HWP to-do, the browser answer on the web

- Version impact: patch, wording only (and one instruction line for the AI)

## Goal

QA TC-242: words that do not match what people see elsewhere.

1. **Setup page without the setup link.** It says "설치 토큰" and asks for a "비공개 설정 토큰" in the server's
   "configured data directory". Open PR #38 already rewrites this hint (`setup.tokenHint`, all five languages:
   "…서버의 데이터 폴더에 있는 setup-token 파일의 내용을 붙여 넣으세요"). It also adds a line right after it. Any change
   to that key, or to the label next to it, conflicts with #38 (checked with `git merge-file`), so this part is left
   to #38.
2. **Mac update notice.** The message repeats the title ("새 버전이 있어요 (45.0.0)…") and ends with "44.7.2이에요"
   (a particle after a number). New wording: title "맥 앱 업데이트", message "새 버전({version})이 나왔어요. 지금
   버전: {current}". No particle after a version number, in all five languages.
3. **HWP to-do on Admin home.** It says "HWP 플러그인", while Admin › 플러그인 lists the plugin by its catalog
   name ("한글 문서 미리보기", "HWP Preview", "Pratinjau HWP", "HWPプレビュー", "Vista previa de HWP"). The to-do
   uses those names.
4. **Asking for the browser on the web.** On the web or a phone the AI said it cannot use a browser and offered to
   read pages, but never said the desktop app can. Open PR #432 (TC-185–187) changes Settings › Browser only, not
   what the AI says. New instruction for the person's own chat on the web or a phone: say the desktop app has a
   browser that can do it, read public pages with the web tools meanwhile, and do not just say you cannot. Not in
   rooms, shared chats, confidential chats or scheduled runs (each already has its own line), and not in the desktop
   app.

## Steps

1. `desktop/src/common/i18n.ts`: `update.mac.title`, `update.mac.message` in ko/en/id/ja/es.
2. `web/src/i18n/*`: `adminHome.after.hwp-plugin` with the catalog name.
3. `server/src/chat/prompt.ts`: `PromptInput.browserInDesktopApp`; `NO_BROWSER_RULE` in the `browser` section of
   the first instructions and of the turn context, only when set and not confidential. `server/src/chat/turn.ts` sets
   it for clientKind web / mobile when the turn has no browser and is neither a room, a shared chat nor restricted.
4. Tests: `tests/unit/b-browser.test.ts` (web: the line is there; desktop: not), desktop i18n test if one checks
   these keys.
