# Web e2e: the twelve tests that fail on dev pass again

- Date (UTC): 2026-11-07 10:46
- Branch: `fix/dev-e2e-failures`
- Status: done
- Where: trina-ax `web/test/` (the e2e specs and the mock team server). Why: the failures are in the tests and their
  test server, not in the app (see docs/REPOSITORY-RULES.md).
- Version impact: none. Only tests and the test server change; nothing that ships.

## Goal

The full web e2e run on `dev` has 12 failures, each also failing alone. The local gate (`bun run --cwd web e2e`
before a merge) means nothing while they fail: a new failure hides among them. After this change the 12 pass and the
rest of the suite stays as it is.

## Scope

In: only the failing tests, and for each one the cause, its class (stale test, app regression or flake) and the
commit that broke it.

- Sign-out (9 tests in `auth`, `offline`, `source-code`, `states`, `upload-progress`): since PR #143 the service
  worker clears the icon badge (`clearAppBadge`) when the account changes. Playwright's Chromium headless shell kills
  the page's renderer when a service worker calls the Badging API; Chrome, full Chromium and Electron 44 do not. The
  app is right; the mock team server serves the worker with no-op badge calls.
- Team skills (`a11y` x2, `rankings`): since PR #148 the page asks `GET /api/skills?shadowed=1`, which the tests'
  `**/api/skills` route no longer catches, and a row shows `/name` instead of the name in words. The tests follow,
  as PR #148 already did for `team-skills.spec.ts`.

Out: any other test, any refactor, any app change.

## Steps

1. Rerun the failing specs on the latest `dev`; bisect each cause over the day's merges.
2. Fix each in its test or in the mock server, the smallest change that keeps the test's meaning.
3. Each fixed spec three times in a row, its neighbours, then one full web e2e run.

## Risks

The mock server serves a changed `sw.js` to every e2e test (two browser calls replaced by no-ops, nothing else). The
worker's badge logic stays covered by `web/test/unit/push-worker.test.ts`. No migration, no app code.
Not taken: `channel: 'chromium'` in `playwright.config.ts` (full Chromium does not crash, but it changes the browser of
the whole suite), removing the worker's clear (a decided behaviour, DECISIONS.md "The installed web app's icon badge"),
blocking the worker per spec (`offline.spec.ts` needs it).

## Tests

`bun run typecheck`, `bun run check:i18n`, `bun run check:docs`, `bun run test:web`, the fixed specs three times in a
row, their neighbours, and one full web e2e run.

## Result

As planned. Sign-out: bisected to the merge of PR #143 (`df27e19b`, commit `23ad63a7`); the crash reproduces with a bare
page and a worker of a few lines in the headless shell only. The mock server (`web/test/mock/server.ts`
`withoutWorkerBadge`) puts no-op `setAppBadge` / `clearAppBadge` in front of the served `sw.js`. Team skills: PR #148
(`4843dae5`); `a11y.spec.ts` and `rankings.spec.ts` use the route `team-skills.spec.ts` got there, and rankings reads
`/weekly-report`.

Checks: the 12 tests (and the offline `401` sibling) 3 runs in a row before and after the rebase on dev, their spec
files and `team-skills` / `push` in full, and one full web e2e run (both projects): 827 passed, 22 skipped, 0 failed.
`bun run test:web` (1629 pass) has one failure that base dev has too (`download-only-actions.test.ts`, "Cannot call beforeAll()
after the test run has completed").
