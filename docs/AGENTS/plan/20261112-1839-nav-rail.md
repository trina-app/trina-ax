### List folders (P4a)

```sql
-- min_compatible_reader: 1
CREATE TABLE nav_folders (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  kind TEXT NOT NULL CHECK (kind IN ('chats', 'rooms')),
  name TEXT NOT NULL,
  name_key TEXT NOT NULL,
  position INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (id, user_id, kind)
);
CREATE INDEX nav_folders_user ON nav_folders(user_id, kind, position);
CREATE UNIQUE INDEX nav_folders_name ON nav_folders(user_id, kind, name_key);
CREATE TABLE nav_folder_items (
  folder_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('chats', 'rooms')),
  chat_id TEXT REFERENCES chats(id) ON DELETE CASCADE,
  room_id TEXT REFERENCES rooms(id) ON DELETE CASCADE,
  added_at TEXT NOT NULL,
  FOREIGN KEY (folder_id, user_id, kind) REFERENCES nav_folders(id, user_id, kind) ON DELETE CASCADE,
  CHECK ((kind = 'chats' AND chat_id IS NOT NULL AND room_id IS NULL)
      OR (kind = 'rooms' AND room_id IS NOT NULL AND chat_id IS NULL))
);
CREATE UNIQUE INDEX nav_folder_items_chat ON nav_folder_items(user_id, chat_id) WHERE chat_id IS NOT NULL;
CREATE UNIQUE INDEX nav_folder_items_room ON nav_folder_items(user_id, room_id) WHERE room_id IS NOT NULL;
CREATE INDEX nav_folder_items_folder ON nav_folder_items(folder_id);
```

The table is not called `personal_folders`: "personal folder" already means a person's own file folder (`users/<name>/`),
and `folders` is the team drive. Re-check migration 289 against `dev` and open branches before merge.

API (`shared/src/api/nav-folders.ts`, owner B):
- `GET /api/nav-folders` returns both kinds, each with a visible `count`.
- `POST /api/nav-folders` (201).
- `PATCH /api/nav-folders/:id` renames.
- `DELETE /api/nav-folders/:id` (204); the items go back to their place.
- `PUT /api/nav-folders/order` takes `{ kind, ids }`. Any subset of my ids is accepted; the rest keep their order after
  them. It returns the full list, so two devices can reorder at the same time.
- `PUT /api/chats/:id/folder` and `PUT /api/rooms/:id/folder` take `{ folderId | null }`.
- `Chat` and `Room` gain `folderId`: mine only, built per recipient in `roomEvent`.
- `ListChatsQuery` gains `folderId`.
- `navFolders.changed` is declared in `ws.ts` and sent to my own windows only.

Rules:
- Only the maker sees a folder. Others, admins included, get 404. No audit row contains folder names.
- **One SQL visibility check** is used for lists, counts and group heads:
  - chats: `c.user_id = me`, not deleted, no project, no room, not an internal chat;
  - rooms: a member row, `hidden_at IS NULL` and `archived_at IS NULL`.
- A project chat stays in its project (409 `folder_project_chat`). `updateChat` deletes the folder row in the same
  transaction when `project_id` becomes non-null.
- Internal draft chats get 404.
- Rows are removed when a chat goes to the trash and when I leave or am taken out of a room. A **hidden room keeps its
  row**; it is filtered on read.
- **Account deletion** deletes both tables' rows explicitly in `server/src/admin/users.ts`, next to the pin deletes. The
  users row is a tombstone, so the cascade never runs.
- Limits:
  - 30 folders per kind;
  - names: NFC, 1–40 graphemes, unique per person and kind by `name_key`;
  - 500 items per folder; at the limit, invisible rows are dropped first;
  - one folder per item and no nesting.
