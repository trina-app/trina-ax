# Microsoft 365 connection names its signed-in account

- Date (UTC): 2026-11-25 13:46
- Branch: `fix/m365-account-label`
- Status: done
- Where: server/src/integrations (connections/service.ts, microsoft/graph.ts). Why: the connection's sign-in code
  lives there (see docs/REPOSITORY-RULES.md)
- Version impact: patch: a bug fix; the connection page showed "Signed in" without the account

## Goal

Live QA on qa.trina.app (0.18.2-dev.20261125131845): after "Sign in with Microsoft" the Microsoft 365 connection's
`account` stays empty, so its page says only "Signed in" while Google connections name the address. Name the
Microsoft account (its address) the moment a sign-in is kept, and again on every reconnect.

## Scope

In: after a Microsoft 365 sign-in's tokens are kept (web return or the desktop app's claim), read Graph `/me`
(`mail`, else `userPrincipalName`, else `displayName`; `User.Read` is already asked for) and store it as the
connection's `account`; a reconnect replaces it (empty when Graph does not answer, never the old account's). A check
of a connection signed in before this fix fills an empty one.
Out: other OAuth connectors (their services have no common "who am I" call); keeping the id_token.

## Steps

1. `microsoftAccountOf(graph)` in microsoft/graph.ts: one `/me?$select=displayName,mail,userPrincipalName` call, a
   clean short string or null.
2. service.ts `keep()`: for a connection at Microsoft 365's address, name the account before the check, only while
   these tokens are the stored ones. `check()`: a connected Microsoft 365 connection with no account gets it.
3. Tests in tests/unit/c-integrations-microsoft.test.ts with the faked Microsoft: the label after sign-in, a
   reconnect to another account replaces it, Graph failing leaves it empty and the sign-in still works, backfill.
4. changes/m365-account-label.md; docs/CONNECTIONS.md only if its text needs it.

## Decisions

none

## Risks

A connection's "Always allow" answers are bound to its account (tool-allow.ts sharedBind): one already given on a
Microsoft 365 connection signed in before this fix is asked once more after the label is filled. The connector is
new (0.18.x), so few exist. No migration.

## Tests

`bun run typecheck`, `bun run check:prepush`, tests/unit/c-integrations-microsoft.test.ts and the connections tests,
web unit tests (web/test/unit).

## Result

Built as planned: `microsoftAccountOf` (microsoft/graph.ts), `nameMicrosoftAccount` in service.ts called from
`keep()` (every sign-in and reconnect, web and desktop claim) and from `check()` for a connected one with no account.
The label is a plain string, as `ConnectionPage.tsx` shows it ("Account …"). docs/CONNECTIONS.md needed no line (no
connection mode changed). Three tests in tests/unit/c-integrations-microsoft.test.ts.
