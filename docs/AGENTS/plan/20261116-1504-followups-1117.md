# Skill suggestion dialog says the place in words; why the Desktop macOS jobs are red

- Date (UTC): 2026-11-16 15:04
- Branch: `fix/followups-1117`
- Status: done
- Where: `web/src/components/SuggestSkillDialog.tsx`, `server/src/skills/suggestions.ts`, `shared/src/api/skills.ts`,
  `.github/workflows/desktop.yml`. Why: the dialog and the overview it reads live there (see docs/REPOSITORY-RULES.md)
- Version impact: patch (a dialog's words; a CI workflow)

## Goal

1. The "Suggest as a skill" dialog's folder list shows `skills/` and `groups/<g>/skills/` as paths in every language.
   The Team skills page says the same places in words ("Team skills", "<group> skills"). The dialog says them the same
   way; the value sent stays the path.
2. The Desktop workflow's "Desktop e2e (macOS)" job (and "Mac dmg") ends red on dev pushes and pull requests. Find
   since when and why; fix it if it is ours.

## Scope

In: the dialog's option words (all six languages), the group's current name in the skills overview (optional field),
a web unit test; the Desktop workflow cause and the smallest change.
Out: the Team skills page's other folder lists.

## Steps

1. Overview: `suggestGroups` (suggest folder → its group's id and current name), optional for older servers.
2. Dialog: each option's text is `skillPlaceWords` (Skills.tsx), the value the path.
3. Unit test for the option words; e2e that asserts the old text follows.
4. Desktop: job logs and annotations of every red run since the last green one; classify; change or write up.

## Decisions

- The dialog uses the Team skills page's own words (`skillPlaceWords`, moved to `web/src/lib/skillPlaces.ts`). The
  overview's new `suggestGroups` gives each group folder's group by its name now; without it (an older server) the
  folder's name stands in, as on the page.
- Desktop: a runner problem, not ours. After 2026-11-16 08:30 UTC no arm64 `macos-15` job of the workflow got a hosted
  runner: every one (dev pushes 43848572638, 43867434347, 43875172880 (42b4416), 43881103475, 43887587121 and every
  pull request run) was cancelled with 0 steps, annotated "The job was not acquired by Runner of type hosted even after
  multiple attempts" and "Due to capacity constraints, jobs targeting macOS arm64 runners may experience longer queue
  times". "Mac dmg" is skipped on pushes and cancelled the same way on pull requests. The last green run, 43830930243
  (a2891d6c0), got a runner in 1 min 23 s. The suite run locally on this branch (`e2e/ci.config.ts`, arm64 Mac):
  74 passed, 11 skipped, 1 flaky (quit.spec, passed on its retry). Change: both Mac jobs on `macos-15-intel` (another
  pool), switchable back with the repository variable `DESKTOP_MAC_RUNNER`; `runner.arch` in the cache keys.

## Result

Both done on `fix/followups-1117`. The Intel runner is not proven yet: the first pull request run that carries this
workflow shows whether it gets a runner and passes there.
