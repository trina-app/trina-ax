# Desktop app: the folder window works on the team page

- Date (UTC): 2026-11-08 05:14
- Branch: `feat/onb6-desktop`
- Status: done
- Where: trina-ax core (`desktop/src/main/security.ts`, a new pure `desktop/src/common/folder-access.ts`,
  `desktop/electron-builder.config.ts`). Why: the desktop shell's permission rules are core desktop code (see
  docs/REPOSITORY-RULES.md).
- Version impact: patch. A fix in the desktop app: a folder picked in the team page's folder window reaches the page;
  no API, database or setting change.

## Goal

Onboarding v6 asks the owner to pick folders: the .claude, .codex or .agents folder for skills, and a company-documents
folder for 팀 파일. In the direct-download desktop app (dmg, Windows) the team page uses Chromium's folder window
(`showDirectoryPicker`). The suspicion (onboarding v6 walk review, M6): the pick ends as a silent Cancel, because the
team session does not allow the `fileSystem` permission, and a pick of Documents, Desktop, Downloads or the home folder
itself is refused by Chromium's blocklist. After this change a picked folder reaches the page, read only.

## Scope

In:
- Check first: what happens today for `showDirectoryPicker` and `<input webkitdirectory>` in the team window (Electron
  44.7.2 source and docs, and a run of the real Electron binary with a hidden window where it can be driven).
- The team session allows `fileSystem` with `fileAccessType: 'readable'` for the team address (and its office address)
  only: the request from the top frame, the check for that origin. Writable is refused. No other permission changes.
- The session event `file-system-access-restricted`: `allow` for exactly the home folder, Desktop, Documents and
  Downloads as directories, picked by the team page's top frame; `deny` for everything else Chromium blocks.
- macOS usage strings for the Desktop, Documents and Downloads folders (`extendInfo`).
- Unit tests for every decision; DECISIONS "W6".

Out:
- The one-press read of ~/.claude and ~/.codex with no window (OPEN Q1, decided: later).
- The Mac App Store build keeps its own window for the page's file inputs (`answerFileChoosers`), unchanged.
- The pane (in-app browser) and the app's own screens keep refusing every file-system request.
- Web changes (the pages already call the folder window).

## Steps

1. Read Electron 44.7.2's File System Access permission context and Chromium 152's pick flow; write down today's
   behaviour.
2. A pure decision module (`common/folder-access.ts`): request, check, restricted folder.
3. Wire it into `hardenAppSession` before the existing permission list.
4. Unit tests, plus a hidden-window run of the real binary if it can be driven without a person.
5. `extendInfo` usage strings; DECISIONS "W6".

## Risks

- Security: reading folders is new for the team page. Only a folder the person picks (or drops) gets a handle; the
  team page's other frames, other origins and the pane get nothing; nothing can be written. A pick of the home folder
  gives the page everything Chromium does not block under it (Chromium still refuses files in ~/.ssh, ~/.gnupg,
  ~/Library and app data).
- Mac App Store build: same session rules; its page uses `<input webkitdirectory>`, which the app answers itself.
- No migration, no UI strings in the five app languages (the usage strings are Info.plist text, English and Korean
  like the existing ones).

## Tests

`bun run typecheck` (root and desktop), `bun test tests/unit/e-desktop-*.test.ts` and the other desktop tests,
`bun run check:docs`, `bun run check:i18n`.

## Result

- Confirmed (Electron 44.7.2 source and a hidden-window run of the real binary): a pick ended as the page's
  `AbortError` (both the request and the check handler refused `fileSystem`; with a check handler set, Electron answers
  every read from it alone), and a pick of a folder Chromium blocks never answered (nobody listened to
  `file-system-access-restricted`). `<input webkitdirectory>` was not affected.
- Built as planned, with one tightening: the check only reads folders picked in the window while the app runs
  (`FolderGrants`), so a dropped folder handle or one the page saved earlier is not readable without a new pick.
- Tests: `tests/unit/e-desktop-folder-window.test.ts`, and `desktop/e2e/folder-window.spec.ts` (real Electron, hidden
  window; run by hand with `bunx playwright test -c e2e/rtc-native.config.ts`), which fails on the previous rules.
- Also: CHANGELOG, DECISIONS "W6", Info.plist usage strings for Desktop, Documents and Downloads.
