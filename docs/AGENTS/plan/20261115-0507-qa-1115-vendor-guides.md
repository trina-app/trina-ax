## Goal

QA TC-2802 (live run 2026-11-15): some steps in Add an app don't match what Typeform, Tally and Jotform show today.
QA TC-2803: a Google Forms file-upload answer would show raw Drive file IDs on the card.

## Scope

In:
- Typeform: save first, then the switch (it starts off and only works after saving).
- Tally: "Add a signing secret" comes with Tally's own secret filled in; replace it with Trina's.
- Jotform: Complete Integration first, then paste the URL and Finish; don't press Add New Web Hook.
- Jira: check the label is "Create flow" everywhere (guide and docs).
- Google Forms script: for FILE_UPLOAD items send how many files (`files: n`), not the IDs. Names would need
  `DriveApp`, which adds a "see all your Google Drive files" permission to the setUp prompt, so no names.
- Server: show "N files" for the new `files` field, and for older scripts an answer made only of Drive file IDs.
- docs/site/use/room-apps.md (en, zh), six locales, unit tests, changelog fragment.

Out: file names for Google Forms (would need the Drive permission).

## Steps

1. Guide wording in en, then ko/id/ja/es/zh.
2. Script + parser + unit tests.
3. Docs, changelog, checks.

## Risks

Older scripts keep sending IDs: matched by shape (25-60 of `A-Za-z0-9_-`, with a digit, an upper- and a lower-case
letter); a typed answer that looks exactly like that would show as "1 file". No migration.

## Result

- Typeform, Tally and Jotform guide steps reworded in all six languages; Jotform names **Add New Web Hook** as the
  button not to press. Jira already said "Create flow" in the guide and the docs (since TC-1634): no change needed.
- The script sends `files: n` for FILE_UPLOAD items and never touches DriveApp (no new permission in setUp).
  `formsAnswer` in server/src/rooms/apps/parse.ts shows "N files" for it and for Drive IDs from older scripts.
- Tests: tests/unit/b-room-apps-forms-files.test.ts (the script run against a fake Apps Script, the parser, a card).
