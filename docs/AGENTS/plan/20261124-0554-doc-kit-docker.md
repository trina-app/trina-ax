## Goal

In the default Docker image, the AI builds Word, PowerPoint, Excel and PDF files with the document skills in an srt run,
like a hosted server does. Korean draws correctly, and the server renders the pages so the AI can look at them.

## Scope

- The image carries the run kit: srt, node, run-wrap, the run's Python libraries and node libraries, and the kit fonts.
  LibreOffice and Noto CJK already come from the `documents` group (#499).
- The container starts the dev environment's runner with no systemd (`MYCEL_DEV_ENV_SRT_DIRECT=1`).
- A root-owned plan file written at every start, which the server cannot change: network offline, one run at a time,
  a memory cap for each run.
- Not in scope: the Mac, Ubuntu hosts, or the documents-mode setting for teams with the dev environment off (that comes
  from `feat/doc-kit-everywhere`).

## Steps

1. Package list: split the run's libraries out of `devenv` into a group `docrun`, so the image takes them without
   build tools or chromium. `devenv` installs keep everything they had.
2. `install-srt.sh --image-mode --documents`: install `core media fonts docrun`, node, srt, the Python venv, the node
   libraries and run-wrap. The Dockerfile runs it from the kit's root copy.
3. Entrypoint: when the image has the kit, write `MYCEL_DEV_ENV=1`, `MYCEL_DEV_ENV_SRT_DIRECT=1` and
   `MYCEL_RENDER_PARALLEL=1` to `/etc/default/mycel`, and write `<base>/root/dev-env.json` (root-owned, plan `docker`:
   offline, `maxRunning` 1, 1024 MiB). Create `<base>/devenv` for the server account.
4. A direct run has no cgroup. Its runner adds up the memory of the run's process tree twice a second and stops the run
   at the plan's limit (reported as out of memory). Page renders go one at a time across the server.
5. `docker/test.sh`: a Korean Word file built in the srt run, network and Unix sockets refused inside it, and the
   LibreOffice render with Noto CJK in the converter isolation.
6. Docs: INSTALL-DOCKER.md ("Documents", "Limits"), a decision file, a `changes/` note.

## Decisions

- **Runs use the server account, not `axagent`.** The server cannot start a process as another account in the
  container (`no-new-privileges`, no capabilities). The launcher starts only engines, inside the turn sandbox, which
  forbids the nested user namespace that srt needs. A run also reads and writes the person's team folders, which belong
  to the server account. A run on a hosted server uses that account too (`trina-dev@.service` `User=`). The walls are
  srt's: bwrap, seccomp with no AF_UNIX, the offline network forced by the root-owned plan file, and `<base>` hidden.
- No per-run cgroup in a container: the memory is watched by the runner, one run at a time, renders one at a time, and
  the container's own `mem_limit`, `pids_limit` and `cpus` hold the whole team.
- docs/decisions/20261124-doc-kit-docker.md.

## Risks

- The memory watch polls, so a fast spike can go over the cap for up to half a second; the container limit is the
  backstop.
- No per-run task or CPU limit in a container (the container's limits hold).
- The image does not update itself: LibreOffice fixes need a new image.
- The image grows (measured in Result).
- Existing Docker teams with no dev-environment row turn the offline run on at their next image (the owner's decision 2
  in the parent plan).

### After the security review (7661546b4)

The review reproduced a run outliving its slot: a build filled srt's tmpfs `/tmp`, the container's OOM killer took
srt's node, run-wrap ended 137, the slot was freed and the sandboxed shell went on unwatched. Fixed at the root
(docs/decisions/20261124-doc-kit-docker.md "No cgroup per run"): every process a run's watch has seen is killed when the
run ends, however it ends; a restarted server kills what an earlier one left; the container's working set
(memory.current less inactive page cache, tmpfs included) is watched against its limit less 768 MiB; runs start at
nice 19 and SCHED_IDLE under a hard RLIMIT_NPROC; their commands go before srt in the OOM order; one direct system per
base (a new one per srtConfig() call had lost the live runs). `TRINA_AX_DEV_ENV=0` turns AI commands off in Docker.

The review's probes against the real code in the product container (4g, 2 CPUs): 6 GB into srt's tmpfs stopped as out
of memory with nothing left and no container OOM kill; 2.5 GB within the headroom runs; srt's node killed mid-build
leaves nothing; 700 forks stop at the hard cap; 64 busy loops slow a loop outside 2.0-2.4x (40-100x before); a planted
bwrap leftover is gone after a server restart. Logs: scratchpad final/.
