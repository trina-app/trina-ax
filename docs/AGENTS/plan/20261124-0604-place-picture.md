# One way to place a picture in Word and Hangul: place, look, move

- Date (UTC): 2026-11-24
- Branch: `feat/place-picture`
- Status: done
- Where: `server/src/files` (docx, hwp, hwpx editors), `server/src/tools/edit-office.ts`, `server/src/tools/edit-hwp.ts`,
  `shared/src/tools.ts` (edit_hwp's input only). Why: the owner wants general picture placement, not more seal logic.
- Version impact: minor, because pictures in Word and Hangul gain page + x/y targets and a move; the mark rules are removed.

## Goal

The AI places a picture the way Claude Code would: put it at a text, a table cell or a spot on the page, look at the
page, and move or resize the same picture. No mark rules, no mm gates, no "checked" claim.

## Scope

In:
- Targets: text (`at` / `over` / `after`), table cell (`cell` / `next_to`), or page + `x_mm`/`y_mm`. Hangul takes a page
  number. Word has no pages here, so its x/y is on the page of the text it is anchored at.
- `move_picture { picture, dx_mm?, dy_mm?, or a new target, width_mm?, height_mm? }` for Word and Hangul: the same
  picture by the id the result gave. The server keeps what the call that placed it did and does it again on the file
  as it was before that call, with the picture's place changed. Only while the file is still that call's result.
- Look: a Hangul result carries the rendered page as an image (team files). Word points to `read as_images`.
- Deleted: `sign-slots.ts` (mark words, signer picking), the pairing proofs (table readings), the landing check and
  "checked, N mm", the refusal of wrapped lines and other places that could not be proved. When the place may differ in
  Hangul, the result says it was not verified.
- Kept: read access, re-encoding, size limits, the not-your-own-picture card with Always, byte preservation, read-back.
  When a text is in several places, the refusal lists them with the occurrence to give.

Out: PDF keeps stamp_pdf x/y. PowerPoint and Excel already have this shape (#493). Moving a picture that was already in
a Word or Hangul file before.

## Steps

1. Plan (this file).
2. Hangul: page + x/y, simple pairing of a text with its drawn line, anchors without refusals, notes on what was not
   verified; remove the landing check and sign-slots.
3. Word: `over` centred on the text it names; x/y on the text's page; remove sign-slots.
4. move_picture by replay, for both.
5. Hangul look: the page image in the result.
6. Tests, real-AI check (Word, .hwp, .hwpx: stamp, logo top right, a little to the left).

## Validation

typecheck, affected suites, check:prepush on Bun 1.3.12, real-AI runs.

## Result

Built as planned. The real-AI run (Word, .hwp, .hwpx: stamp, logo top right, a little to the left) succeeded in all 9 turns, and the move kept the same picture. It also found that a picture spliced into a Word text run hid that run's text from `read`; the picture now goes in a run of its own.
