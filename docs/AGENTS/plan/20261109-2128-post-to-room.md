# post_to_room: the AI posts to a room from the person's own chat, behind one server card

- Date (UTC): 2026-11-09 21:28
- Branch: `feat/post-to-room`
- Status: in progress
- Where: trina-ax core (`server/src/chat/`, `server/src/rooms/`, `shared/src/`). Why: chat, rooms and permissions are
  core (see docs/REPOSITORY-RULES.md)
- Version impact: minor. A new AI tool and a card; no API or data change.

## Goal

The AI cannot post to a room today: the person must press "대화방에 보내기" under a finished answer. In a side chat the AI
is told to point at the button and never claim it posted; in an ordinary chat it only says "I cannot post". People ask
"이 요약 #영업팀에 올려줘" or "요약해서 스레드에 올려줘" and get a refusal. The owner approved (2026-11-10):

- Q1: the AI posts the text it writes (`text`), shown in full on the card. "요약해서 올려줘" works in one step.
- Q2: always one card, even when nothing is at stake (a room message reaches everyone and notifies them; the button is one
  press too).

## Scope

In:
- New tool `post_to_room(room?, text, note?, thread_id?)` (server/src/chat/post-to-room.ts, registered in chat/tools.ts).
  - Never offered in a room's "@트리나" session (`exec.room`), a shared project chat (`exec.shared`), a draft/judge/merge
    chat (`exec.restricted`), an approved scheduled template's run (`exec.templateRun`), a confidential chat, a scheduled
    run (`clientKind` 'schedule') or a question asked from Slack (`clientKind` 'slack'). In `PARENT_ONLY_TOOLS`
    (sub-agents never get it). In `ROOMS_SEEN_READ_ONLY_TOOLS` as a tool that raises its own card, like `remember`: no
    extra room card after a room read.
  - When reached anyway (the chat turned confidential during the answer, a sub-agent's call) it refuses with a reason and
    a next step; so do a room that is archived or not mine, a gone thread, content that used earlier answers hidden from
    some members, a text too long for one message, and the sending budget.
- Refactor `shareAnswerToRoom` (chat/answer-share.ts) into `prepareShare` (the checks up to the "confirm" decision) and
  `sendShare` (the decision and the send). The button path behaves as before.
- The tool path, in order: `exec.noteReads()`; the running answer's id (`active_leaf_id` points to it, so the chat's read
  scope describes it, and its turn is unended so every place of the scope counts); `text` (redacted) as the content; the
  room by `findRoom` among mine (`rooms.mine` checks it again) and the thread by `Rooms.threadRootOf`; ONE server card
  (`ask_user`, origin server) with the full text, the provenance line and the file line; on yes `prepareShare` again and
  `sendShare` with the key of the choice the person pressed and the chosen files; a "confirm" then means the check
  changed while the card waited: refused, "changed while waiting; ask again". `clientMessageId` is `ai-<turnId>-<n>`, `n`
  per target and text in this answer, so the same call again finds the first message (no second card, no second post).
  Audited as `room.answer_share` with `via: 'ai'`.
- Side chat: with no `room`, the side chat's room; when the nearest earlier question that quotes something quoted a
  message with a thread token (#271's rule, moved to shared/src/api/rooms.ts so the app and the server read one rule),
  that message's thread.
- The card (lean): "#영업팀(12명)에 보낼까요?" or "#영업팀(12명)에서 '…' 메시지의 스레드에 보낼까요?"; the text in full,
  folded when long; the lines about people who cannot see some sources, or linked files some cannot open, only when they
  apply; buttons [보내기], [파일도 함께 보내기] (only when there are files to attach), [보내지 않기]. After it: the step
  "대화방에 보내기 · #영업팀". Step label in shared/src/step-labels.ts, card texts in chat/i18n.ts, five languages.
- Prompt: the side chat's line says post_to_room raises a card and to say it posted only when the result is sent; one
  sentence in the rooms rule when the tool is offered.

Out: posting as the AI; a toast; anything in the app's screens (the card is the existing server card); `fix/ai-refusals-clear`'s
`refusal()` helper (not on dev yet; the texts follow its shape: what did not happen, why, what next).

## Risks

- Prompt injection: a web page, a file or a room message can tell the AI to post. The card shows the room, its number of
  people and all of the text, and nothing goes without [보내기]; a planted instruction is tested.
- The running answer's sources are not recorded yet: treated as an unended answer, every place of the chat's scope
  counts (the existing conservative rule).
- Habitual [보내기]: the room and its number of people lead the card; the "cannot see" lines show only when they apply.
- Coordination: `fix/ai-refusals-clear`, `feat/fewer-cards-after-room-read`, `feat/room-read-connection-cards`,
  `feat/ai-delete-files`, `feat/ai-skill-folder-actions` touch prompt.ts, turn.ts, tools.ts and the rooms-seen lists;
  dev is merged before the push.
- No migration. Five languages.
