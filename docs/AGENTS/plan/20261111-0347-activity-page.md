# Activity: the Inbox becomes its own page, laid out like Slack's

- Date (UTC): 2026-11-11 03:47
- Branch: `feat/activity-page`
- Status: done
- Where: web/. Why: the Inbox list is web UI only; the API already returns everything the page needs (docs/REPOSITORY-RULES.md)
- Version impact: minor, a new page (`/activity`) and a renamed menu item; no API or data change

## Goal

The Inbox is a list inside the Settings dialog (Settings › Notifications). People read it like Slack's Activity: a
page of its own, with tabs, an unread filter and the list grouped by day. Rename it to "Activity" and move it out of
the dialog into a full page at `/activity`.

## Scope

In:
- `web/src/pages/Activity.tsx`: title "Activity", tabs All · DMs · Mentions · Threads, an "Unreads" toggle and a
  search field that filter the loaded rows, rows grouped under a day heading (Today, Yesterday, a date), a row per
  notice in Slack's shape (photo or bell; who + time; the line; where/what it is underneath; the unread count on the
  right). "Load more" pages through the 30 days the server keeps.
- The sidebar's Inbox row, the phone's 나 tab row and the search action open `/activity` and say "Activity".
- Settings › Notifications keeps the preferences only (no list there any more).
- The five languages.

Out: server-side filters (the tabs filter what is loaded; the server keeps 30 days and pages by 30), a "mark all read"
(no endpoint yet), custom tabs (Slack's "+").

## Steps

1. Plan (this file).
2. Activity page, route, phone tab mapping (`lib/tabs.ts`: under 나) and the phone bar title.
3. Links: Sidebar, SettingsDialog phone row, SearchDialog action. Notifications.tsx: preferences only.
4. i18n: `inbox.title` → Activity in every language, new `activity.*` keys.
5. Tests: the unit tests that rendered the list in Notifications render Activity; e2e specs that opened
   `/settings/notifications` for the list open `/activity`.

## Risks

No migration. Push links for room notices open rooms (unchanged); `connection.reconnect` still opens
`/settings/notifications` (its preference). Phone: the page sits under the 나 tab and its top bar.

## Tests

`bun run typecheck`, `bun run check:i18n`, the web unit tests for the inbox, sidebar and phone navigation.

## Result

Built as planned, web only. `/activity` page (pages/Activity.tsx); Settings › Notifications keeps the preferences and links to Activity; on a phone the 알림 settings row is back in its group (the top row opens Activity). Keys under `feed.*` (`activity.*` is the admin audit log).
