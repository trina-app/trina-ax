## Goal

demo.trina.app (the free-roam demo) runs en and ko today. Make all six of the app's languages work once their
Steepling content lands, so turning one on is a config change (`pool.locales`) plus a snapshot build.

## Steps

1. `scripts/demo/steepling/make.ts`: `STEEPLING_LOCALES` = the six; the per-language words (the scripted story's
   strings, `strings/<l>.ts`, `strings/rich.<l>.ts`) in ONE typed map, so a missing language is a type error and a
   clear import failure. The two language checks in it (the company answer's team size, the time zone) become maps
   with a line per language. `steeplingWords(locale)` is exported for the tests.
2. `scripts/demo/free-roam/build-snapshot.ts`: usage text and checks take the six (it reads `STEEPLING_LOCALES`).
3. `demo-gate/src/config.ts`: `Locale`/`LOCALES` = the six; the default `pool.locales` stays `['en', 'ko']`, so the
   live config decides. `pages.ts`: the six pages' words in every language (the en/ko wording, "about 8 questions");
   `localeOf` takes the configured languages and falls back to en (or the first configured one). `stats.ts` and
   `/__demo/status` know the six.
4. `web/src/lib/freeRoam.ts` `FREE_ROAM_LOCALES` = the languages Steepling has (the six); a root unit test keeps it equal
   to `STEEPLING_LOCALES` so the sign-in page follows the snapshots' languages.
5. The web free-roam bar strings (#229): check the six i18n tables have every `demo.free.*` key (they do).
6. Tests: demo-company-seed checks every language's structure against en without a server; demo-gate page tests for
   the six; the no-dates guard asserts it scans every language's strings.
7. Merge the four content branches, fix type mismatches in their files (their copy kept), run typecheck,
   check:prepush, check:i18n, the demo tests and one full ja snapshot build.
