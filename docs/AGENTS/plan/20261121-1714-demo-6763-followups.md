## Goal

The live check of the deployed demo failed three rows:

1. TC-6790: a ja/zh/es/id instance's sign-in page offered English only. `freeRoamSignInLocales` gets the instance's
   language from GET /api/setup `defaultLocale`, but demo-gate denies /api/setup (DENY_PATHS, "Not available in the
   demo"), so the web never learned it.
2. TC-6791: after `make_banner` the chat showed no picture, and Trina saved the file only when asked again. A
   connection's inline image is kept as an `mcp-file:` handle; it shows in the chat only once it is saved to the team
   folder and named in the answer as a Markdown image, and nothing told the AI to do both.
3. TC-6792: Trina did not say the photo comes from a prepared set. The note was only in the system prompt.

## Steps

1. GET /api/demo says the team default language (`locale`, optional; the team settings' defaultLocale). demo-gate
   already lets /api/demo through; /api/setup stays denied. The web reads it when GET /api/setup fails before sign-in
   (store/session.ts), so the sign-in page shows the instance's language and offers it next to English; the switcher
   also reads it from the demo store.
2. The fake Higgsfield's generate_image and make_banner results carry one short line: the picture is one of the demo's
   prepared photos (no new photo was made), and the next step: save it with save_connector_file into the project's
   folder and show it as a Markdown image. The tool descriptions say the same, and DEMO_FAKES_NOTE (trusted, the system
   prompt) tells the AI to save each Higgsfield picture right away without being asked and show it in the answer as
   `![name](/api/files/download?path=<team path, URL-encoded>)`, which the web draws inline (Markdown.tsx TeamImage).
3. DEMO_FAKES_NOTE / DEMO_BANNER_NOTE: one plain sentence that the photo comes from the demo's prepared photos.
