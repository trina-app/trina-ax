# CI: a hung apt command in the Tools step fails and is tried again

- Date (UTC): 2026-11-23 12:20
- Branch: `fix/ci-apt-timeout`
- Status: in progress
- Where: `.github/workflows/ci.yml`. Why: CI's own setup step (see docs/REPOSITORY-RULES.md)
- Version impact: none, CI only; nothing that ships changes

## Goal

On 11-23 merge queue entries kept dropping because `apt-get update` in the "Tools (ripgrep, poppler, pandoc)" step hung
on the Ubuntu mirrors until the job's 20 or 25 minute limit. The step's 5-try loop only reacts to a failure, and a hang
never fails. A hang should become a failure so that the loop tries again.

## Scope

In: the apt commands of the Tools step, in each of its three places in `ci.yml`, run under `timeout` (120 s).
Out: `feature-map.yml` and `desktop.yml` apt commands, `dev-build.yml` (has no such step), the pandoc download, job limits.

## Steps

1. Run each apt command as `sudo timeout -k 10 120 apt-get ...`: root can signal apt, and `-k` ends an apt that ignores TERM.
2. Run the step's real script with a fake apt under GitHub's shell flags (`bash -e -o pipefail`): a hang is retried, a
   later try succeeds, and 5 hangs fail the step.

## Decisions

none

## Risks

A healthy apt command slower than 120 s now counts as a failed try; the whole step took at most 114 s on a good run. An
install stopped halfway can leave dpkg needing repair, so later tries may fail and the job fails, as it did before but
sooner. No migration, no app code.

## Tests

The step script with a fake apt: hang then success, always hang, plain failure.
