## Goal

"이 사진들 크기 줄여줘", "가로 1200픽셀로", "용량 2MB 이하로", "웹용으로 줄여줘": an everyday office ask with no tool
behind it. The AI makes smaller copies of photos in the team folder, next to the originals.

## Scope

In: one tool, `resize_images`, for JPEG, PNG and WebP (1-20 files a call). Controls: longest side, width, a target file
size, or a preset (smaller / email / web). Aspect kept, never upscaled, EXIF orientation applied, all photo details
(location included) removed. New files "<name>-작게.jpg" (the word in the team's language); the original is replaced only
with `replace: true` after a read in this turn, as edit_pdf. The pixels are decoded and encoded by the Go helper that
already normalizes images for AI reads (`mycel-safeops`, new mode `resize`), in the converter isolation with time,
memory and output limits. Saves go through make_file's path (placeProduced, confirmSources), so the cards are the same.
Out: HEIC (said plainly), GIF/TIFF/BMP, cropping, format conversion on request, keeping metadata.

## Decisions

`docs/decisions/20261117-resize-photos.md`.

## Risks

Images are untrusted: the declared size is checked before decoding (pixel and side limits, as vision), the helper runs
isolated, and its refusal lines are fixed strings. WebP has no encoder in Go's x/image, so a WebP comes out as JPEG (or
PNG when it has see-through pixels); the AI says so.
