## Goal

One list, `docs/ASKS.md`, of every place Trina AX asks the person for anything: the AI's cards, connector and site
cards, command cards, the web app's confirm dialogs, and the system prompts the desktop and phone apps trigger. Each
entry says when it shows, what it says (ko + en), its buttons, its "Always" scope, the Settings path that takes it back,
scheduled runs, guests, why it exists, and its Rule A status (docs/decisions/20261116-always-allow-final-rule-a.md).
A unit test fails when code gains an ask the list does not have, so the list stays managed.

## Scope

In:
- Inventory from the code (base origin/dev 238220412, 0.14.1-dev): server card builders (`waitForPerson`, `askPerson`,
  `askAlways`, `withAlways`, `askConfirm`, a TurnPerson `confirm`, `connect_service`, `browser_site`, `dev_env_site`,
  the AI's `ask_user`), the always kinds (`CARD_ALWAYS_KINDS`, connector tool, site), the tools that wait
  (`CARD_LATER_TOOLS`), web dialogs (`confirmDialog`, `choiceDialog`, `useConfirmStep`, `window.confirm`, share and
  invite dialogs), desktop (Electron dialogs, macOS folder and media access) and phone (push, microphone, photos)
  system prompts, Slack's post buttons, access requests, web push and microphone. Cross-checked against the A/B
  ask-count QA run of 2026-11-22 (QA notes, not in the repo).
- Categories a non-developer can read: my files and folders; sending and sharing; connectors; websites; commands and dev
  environment; memory, skills and schedules; when guests are there; screen confirm dialogs; sign-in and setup; system
  permissions.
- `docs/ASKS.md` (English): every ask with its fields; a "Code index" table (file → number of ask call sites → ids);
  "How to add a new ask" (registry entry, an Always decision, a Settings revoke path or a written reason).
- `tests/unit/ask-registry.test.ts`: reads `docs/ASKS.md` and fails when
  1. a file in server/src, web/src, desktop/src, menubar or mobile has more ask call sites than its Code index row (a
     new file with ask call sites and no row fails too), a row is left for a file with none, or a row names an id that
     is not in the registry. Fewer sites than the row passes, so a branch that removes a card does not have to touch
     the table at once. Comment lines do not count. The patterns are what every ask has in common: `turn.request`
     publishes, `kind: 'ask_user'` and the other TurnRequest literals, `waitForPerson` / `askPerson` / `askAlways` /
     `withAlways` / `askConfirm` / `.confirm(`, a share dialog's `status: 'confirm'`; web `confirmDialog` /
     `choiceDialog` / `useConfirmStep` / `window.confirm` / `Notification.requestPermission` / `getUserMedia`; app
     `showMessageBox` / `requestPermissionsAsync` / `requestAuthorization` / usage-description strings / Android
     permissions. The failure names the file and the pattern group.
  2. a kind in `CARD_ALWAYS_KINDS`, a `TurnRequest` kind or a tool in `CARD_LATER_TOOLS` has no registry entry;
  3. an entry's id is repeated, or its "where" file does not exist.
  The scan is by pattern, not by markers in the card code: other branches (fix/* for batch 5) are changing that code
  now, and comments in those files would conflict.
- A decision file `docs/decisions/<UTC day>-ask-registry.md`, linked from docs/REPOSITORY-RULES.md and
  docs/AGENTS/README.md; docs/ASKS.md listed in docs/README.md and linked from docs/PERMISSIONS.md and
  docs/CONNECTIONS.md.
- A Korean summary for the owner, outside the repo.
- No `changes/` file: nothing changes for the user.

Out: changing any card's behaviour. Every Rule A VIOLATION and OPEN item found is listed in the registry and in the PR
for a later fix PR.

## Risks

- The test counts call sites per file, so a batch-5 branch that adds a card call fails it until the row is updated
  (that is the guard; the message says which file and what to do). Removing one passes. One row per file keeps such
  conflicts to one line.
- A pattern scan can miss an ask built in a new way. The "how to add" rule names the primitives, and the review greps
  for others.
- No migration, no UI, no i18n change.
