# Shared chats: one notice per place before a connection's first use; one card per call; the create tier in shared chats

- Date (UTC): 2026-11-23 07:00
- Branch: `fix/b5-flow2-3` (stacked on `batch/20261123-b`)
- Status: done
- Where: server/src/chat (turn, tools, open questions, prompt, i18n), server/src/integrations/connections (tools,
  tool-allow), shared/src/api (ai-allowances), web/src (Settings › Allowed for Trina).
  Why: the batch-5 measurement run (flows 2 and 3).
- Version impact: minor: the shared chat card for connected services becomes a one-time notice per place.

## Goal

Flow 2 (Aside, 5 people): the AI showed a team connection's tab list in a shared chat with no card in one chat and
refused in plain words in the other. Not a leak by the rules then (a team connection everyone in the chat may use runs
with no card); the refusal came from the shared prompt's "the browser on <name>'s computer is not available", which the
model sometimes read as the Aside connection. The owner's decision: "그냥 공유 프로젝트에서 처음 쓰기전에 노출될 수
있습니다. 경고 한번만 주고 시작하면 되지 않을까?" — one notice, once per person per shared project (or shared chat not in
a project), for every connection, personal or team. Reads then show with no card.

Flow 3 (Repl, personal connection, no Always): 9 cards. Each create had the shared card and the change card (the create
tier never held in a shared chat: `othersWords` counts any shared chat as other people's words), the first create's
answer then ended the tier (a connection's answer marks the chat as outside), and the AI called the same create again
while its card waited, so two "Create app" cards ran it twice.

## Scope

In:
- `confirmSharedConnection`: the one notice ("Other people in this chat can also see what the AI gets from <service>."
  / "이 채팅의 다른 사람도 <service>에서 가져온 내용을 볼 수 있어요.", one button Continue / 계속), kept per person,
  connection and place (`connector_tool_allow`, tool `\0seen:p:<project>` or `\0seen:c:<chat>`; no migration). The read
  record (k group) stays, so a later joiner who may not use the connection still does not see the answer.
- Settings › Allowed for Trina lists each notice seen (`warned`: the project's name or the chat's title) and resets it.
- The create tier in a shared chat: `othersInChat` (other people's messages, a room read, content someone else wrote),
  not "a shared chat". A create's short answer (≤ 300 characters, no file, no link, no error) does not end the tier.
- One card per call: a call of the same tool with the same arguments while its card waits gets that card
  (`waitingTwin`), so one press runs it once.
- The shared prompt: what a connection returns shows to everyone; a connected service is not "the browser on the
  computer".
- Tests: tests/unit/b-shared-connector-warning.test.ts; older shared-chat tests seed the notice (tests/lib/shared-warned.ts).

Out:
- A "don't show again" switch: Continue always keeps it (the default the owner named); Settings resets it.
- Writes: unchanged (a team connection's change in a shared chat asks every time; the person's own Always holds).

## Result

Flow 3 without Always: 1 notice per shared chat + no create card (was 9: 4 shared cards, 5 create cards). With Always:
the same (was 2). Flow 2: one notice the first time in each shared place, then the tab list shows with no card.
