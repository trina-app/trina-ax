# Custom connector for a service that needs no sign-in

- Status: in progress

- Version impact: patch. A connection that failed now connects; one optional answer shape on an existing endpoint.

## Goal

QA TC-4771: adding a public MCP server that needs no sign-in (DeepWiki, `https://mcp.deepwiki.com/mcp`) as a custom
connector fails. The form's default way in is sign-in (OAuth); the server publishes no sign-in, so discovery throws
`oauth_unsupported` and the person reads "This service does not offer sign-in to apps like this one. Try an API key
instead." The row stays "Sign-in needed". The working way ("No sign-in" under Advanced) is there but nobody finds it.

No decision refuses such servers: `auth: 'none'` is allowed for personal and team connections (docs/INTEGRATIONS.md,
the limits row: "that work, have a key or need no sign-in"); only templates take no `none` (DECISIONS.md, a personal
key or sign-in is the point of a template).

## Scope

In:
1. authorize: the unauthenticated MCP `initialize` that already runs to read the 401 header worked (no 401), and
   discovery then finds no sign-in (`oauth_unsupported`), and the server also lists its tools without a key: the
   connection is switched to "No sign-in" (an update to `auth: 'none'`, which checks it and saves the tools) and the
   answer is `{ connected: true }`, no flow. Only for a connection that was never signed in, has no own app and is not
   from a template. Every request goes through the same `net` options (address checks against private addresses).
2. Contract: `authorizeIntegration` answers either the flow or `{ connected: true }`.
3. Web `useSignIn.start`: `connected` closes the reserved window and runs the same "completed" path (the list reloads,
   the row shows Connected). No new button or screen.
4. Tests: a fake MCP server with no sign-in (connected, tools saved, auth none, no flow); one that asks for sign-in on
   tools/list still gets the old reason; a web unit test for the connected answer.

Out: probing at Save time (would add requests to every sign-in connector's Save); changing the form's default.

## Risks

- A server that answers `initialize` and `tools/list` without a key but wants one for calls: the calls fail with the
  service's own refusal, as for any "No sign-in" connection the person chose by hand; they can change it under Advanced.
- No migration.
