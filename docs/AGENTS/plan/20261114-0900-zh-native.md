# Simplified Chinese in the phone app, macOS prompts and store listings

- Date (UTC): 2026-11-14 09:00
- Branch: `feat/zh-native`
- Status: done
- Where: mobile/, desktop/electron-builder.config.ts (mac section), desktop/build-resources/mac-infoplist/,
  editions/trina/microsoft-store/, editions/trina/store-listings/. Why: the phone app's native screens, the macOS
  permission prompts and the store texts live there; web/server/desktop shell languages are a separate branch
  (feat/locale-zh)
- Version impact: minor: a new language on the phone app's native screens; nothing removed

## Goal

Simplified Chinese (`zh`, 简体中文) wherever the native apps speak outside the web page: the phone app's own screens
(setup, offline, errors), its iOS permission prompts and app name, and the macOS permission prompts. Store listing text
for the owner to paste.

## Scope

In:
- mobile/src/strings.ts: a `zh` table; `stringsFor` picks it for any zh phone (zh, zh-Hans, zh-CN, zh-SG, zh-TW, zh-HK).
  IOS_USAGE.zh and a `zh-Hans` entry in app.config.ts `locales`.
- macOS: one InfoPlist.strings per language (en, ko, zh-Hans, ja, es, id) copied into Contents/Resources/<lang>.lproj by
  `mac.extraResources`; English stays the Info.plist base; CFBundleLocalizations lists the six.
- Microsoft Store listing.md: a zh-CN section. The msix `languages` stays en-US/ko-KR (the listing must be entered in
  Partner Center first).
- editions/trina/store-listings/zh-Hans.md: App Store and Google Play text within the stores' limits.

Out: the web app, server, desktop shell UI, menubar, relay, push, README, release.ts (feat/locale-zh). Treating Chinese
characters typed in the team address box as their own error (team-link.ts is shared with desktop and web).

## Steps

1. Plan (this file).
2. Phone strings, permission prompts, app config, tests.
3. macOS InfoPlist.strings, config, test.
4. Listings, changes fragment, QA row.

## Risks

Electron ships its own `zh_CN.lproj`; the Chinese file goes into both `zh_CN.lproj` and `zh-Hans.lproj` so macOS finds
it whichever folder it picks. Spanish also goes into `es_419.lproj` for Latin American Spanish.
