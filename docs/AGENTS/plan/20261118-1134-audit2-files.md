## Goal

Three gaps from the second limits audit, where the AI sent a person to do something by hand:

1. **Speech model (TC-4919).** On an Office Mac the first recording read fails while the 488 MB speech model
   downloads, and the AI tells the person to "use voice input once". The model should be there before anyone asks,
   and a read that meets the download should wait for it and say how far it is, never send the person anywhere.
2. **Archives and attachments (TC-4920).** The AI can unzip but cannot make a zip, and cannot save the attachments of
   an .eml or .msg email.
3. **Office, CSV and ZIP from the web (TC-4922).** save_url takes only pictures, PDF, video and sound; web_fetch reads
   only pages, text, JSON and PDF.

## Scope

In:
- The speech model is downloaded when the server starts (and again later, with a back-off, until it is there) wherever
  the team's speech provider is "this server" and whisper.cpp is installed. A read that finds the download running
  waits for it within its time, then says how much is done and tells the AI to read again; the "use voice input"
  sentence goes. Reads on Linux may start the download too.
- `make_zip`: files and folders the person can read into one .zip saved through make_file's save path (placeProduced:
  versions or a conflict copy, the wider-audience card for the zipped files, the per-turn file count, the disk check),
  with a total size and file count cap. Streamed to a work file one file at a time; already-compressed files stored.
- `unzip_file` also takes an .eml or .msg email: its attachments are saved as files (next to the email by default),
  through the same path as a zip's files.
- save_url takes Word, Excel, PowerPoint, Hangul, OpenDocument, CSV and ZIP files, judged by their bytes; programs,
  HTML and SVG stay refused. web_fetch reads their text through the normal extractors (a zip: its list of files).
  The address rules, the private-network checks, the egress rules and the size rules are unchanged.

Out: tar.gz output (zip only), 7z/rar, password-protected zips, a live progress bar in the step for the model download
(the read's text says how far it is), Gmail and Drive attachments (other audit items).

## Steps

1. Plan (this file).
2. Speech: progress of the model download, a prefetch at start with back-off, the read waits and reports progress, the
   texts in six languages.
3. save_url / web_fetch: a download sniffer for Office/CSV/ZIP (reusing file-list/sniff.ts), web_fetch's extractor
   hook, descriptions.
4. make_zip (a streaming zip writer, the tool) and email attachments in unzip_file (a small MIME reader, the .msg
   compound file through files/cfb.ts).
5. Tool lists, step labels, prompt line, changes file, decision file, unit tests, check:prepush with Bun 1.3.12,
   real-AI checks on a copy of the QA team.

## Risks

- A zip of files from a narrow folder saved where more people read: the wider-audience card covers every zipped
  file's folder (confirmSources), as make_file does for its sources.
- A crafted email or Office file: attachments are decoded with output caps; the .msg reader is the bounded compound
  file reader edit_hwp uses; the saved files go through placeProduced and the quarantine check like any file.
- save_url now saving zips: a zip is only stored, never opened; zips that are program packages (APK, JAR) are refused.
