# AI sharing, part 1: words and refusals

- Date (UTC): 2026-11-16 15:00
- Branch: `feat/ai-share-words`
- Status: done
- Where: Team AX core, `server/src/chat/` (prompt rules, tool descriptions, card text). Why: chat and sharing are core.
- Version impact: patch. Wording only: no new tool, no schema change, no change to what is refused.

## Goal

A teammate's hands-on tests (QA tab "Manual AI tests", MAN-013, MAN-015, and the same-name and refusal cases) failed
because the AI was never told how the share and post tools behave, and because refusals were dead ends with folder
paths in them. This part changes only what the AI is told and what cards say, so that:

- a file asked into a room goes as a file (a link in `text`), not as pasted content;
- "that thread" with no thread named is asked about, never guessed;
- two files of the same name are told apart in words (name, place, who shared it and when), or picked without asking
  when one was made, read or attached in this chat;
- no card, question or option shows a disk path;
- every refusal on the share and post paths ends with the next step.

## Scope

In: `ROOMS_POST_RULE`, `SHARE_FILES_RULE`, `SOURCE_LINK_RULE`, the shared-chat section, the two tool descriptions, the
refusal texts of `share_with_person` and `post_to_room`, `ask_user` option labels that are paths (said in place words),
the file lists on the share and post cards, the thread quote in the post card's title, `fileShareView` with a count.
Out: stop sharing, the single card, "who can open this", one-tap buttons, `shared_with_me`, `looking_at`, folder sharing
(other builders). Which things are refused does not change.

## Steps

1. New file `server/src/chat/share-words.ts`: the rule texts, the refusal sentences and the place-word helpers.
2. Small edits where they are used (prompt.ts, post-to-room.ts, share-with-person.ts, tools.ts ask_user, i18n.ts).
3. Unit tests that pin each rule and each refusal; a run on a private QA copy with the real AI for MAN-013, MAN-015
   and a same-name case.

## Result

Built as planned, with these differences:

- The new rules are their own constants in `server/src/chat/share-words.ts`, appended next to the rules they extend
  (`ROOMS_POST_RULE`, `SOURCE_LINK_RULE`), not edits inside those texts: other open branches change the same lines, and
  `SOURCE_LINK_RULE` has a length budget.
- `fileShareView` is two texts picked by the count (`fileShareViewOne` for one file), not one text with `{n}`: four of
  the six languages do not change with the number.
- A folder refusal lists the files right in the folder that the person can share now (new helper `shareableIn`, each
  file checked by `FileShares.view`). In a shared chat nothing is listed.
- A room that is not found: the AI is told to call `rooms` and offer the closest ones. The list is not put in the
  refusal, because room names are other people's words and enter a chat only through the room tools.
- A share where nobody new gets access returns `already_had_access` and a note to say so. The card logic is unchanged.
- Added after the security fix on the prompts batch (a86e48ca4, `chats.others_words`): the refusal texts were checked
  against the gates again (the fix changes when "Always allow" counts, not what is refused, so none changed), and the
  card that comes back in that case says why and what skips it (`othersWordsWhy`, `OTHERS_WORDS_RULE`). Scripted engine
  only; not run with the real AI.
- Fix on the base, not part of this work: after merging the two open batch branches, `FileShares.grantedFile` and
  `fileOfLink` called `resolve()` without the rules (one batch added the calls, the other the argument). Own commit.
