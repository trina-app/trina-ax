## Goal

On a WSL server the installer's closing lines, Admin › System › Connection and the connected-folder form say what
applies to that PC, and the Windows setup window shows the installer's own lines and the heartbeat, not apt's output.

## Scope

In:
1. install-linux.sh `done_ok`: on WSL (the kernel release, as server/src/system/wsl.ts) the first-run hint says to
   open http://127.0.0.1:PORT/setup on this PC, and that the code is on the clipboard or
   `wsl -d TrinaAX --cd / -u root -- cat …/setup/code`; no `ssh -L`.
2. Admin › System › Connection on a WSL server: "Office network only" is named "This PC only" (or the public address
   when there is one), with one line why the office network cannot reach a WSL server; no office address row.
   ConnectionStatus gets an optional `wsl`.
3. The connected-folder form says "Folder path on this computer" (and a Linux example) where the server is not a Mac,
   in all six languages. The list response gets an optional `mac`.
4. The Windows script sets PK_APT_TO_LOG=1: apt's output (stdout and stderr) goes to PK_APT_LOG
   (/var/log/trina-packages-apt.log); the window shows the heartbeat lines and, on a failure, the log's path and last
   lines. The script's own bootstrap apt step logs there too.
5. install-wsl-server.ps1 step 4: a failed `wsl --install ... --web-download` (exit code -1 once on a clean PC) is
   tried once more after 10 s. A distro of our name the failed try left is unregistered only when `wsl --list`
   answered before the step without it and a probe inside it ran and said "empty" (no /var/lib/mycel, no upload, no
   home folder); any other answer stops with the message to run the script again (fail-closed, review of #757).

Out: other installers' output (Linux over SSH keeps apt's stderr in the terminal as before).
