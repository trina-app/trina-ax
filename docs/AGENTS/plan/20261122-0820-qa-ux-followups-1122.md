## Scope

In:

1. **Chat file panel "Restore this version".** The Files screen's confirm ("Restore v{n}?", whose edits drop out of the
   newest) plus one line naming who in the chat will see the change. The restore keeps telling the open windows as an
   edit does (the tiles) and adds a chat line "{actor} restored {file} to version {n}" for everyone who may open the
   file (table `chat_file_events`, migration 439). The line is read with the audience's `events`.
2. **Leaving a chat shared with people.** The "{actor} left" line shows to the creator also when the chat went back to
   being only theirs (GET …/audience gives a private chat's lines to its creator). The creator gets one Activity notice
   per person and day ('chat.left', table `chat_left_notices`, shown always, never pushed). The person who left gets no
   notice about their own leave: their "shared a chat with you" row of that chat goes.
3. **Guests without AI** see no "Ask Trina" on a file (team or room file) in the file panel.
4. **A DM with files and Activity.** By design no DM message is an Activity row, with or without files (rooms/inbox.ts
   LISTED_SQL; decision "Activity: the DMs tab is back"): the Chats list counts it and the rail badge does not. A test
   keeps a file DM the same as a text DM. The DMs tab's empty state says where DM messages are.
5. **"Archived accounts"** shows in the reader's language (all six), whatever language the folder was made in. A
   chat-share notice keeps the sharer's name after their account is gone (the name is still known).
6. **AI limit words.** Claude Code's own limit (stream-json `rate_limit_event` with `resetsAt`, or "limit reached|<epoch>")
   gives the answer's retry time, so a long limit reads "used up until {date}" (usage_used_up) instead of "try again a
   bit later". A weekly limit with no time is usage_used_up too. "Try again" is not offered for usage_used_up while its
   time has not come.

Out: an Activity row for every DM message (a product change for the owner), push for the leave notice.
