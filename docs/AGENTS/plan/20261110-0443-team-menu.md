# The team menu: the team's name and logo on top of the sidebar open a menu with Invite and Admin

- Date (UTC): 2026-11-10 04:43
- Branch: `feat/team-menu`
- Status: done
- Where: trina-ax core (`web/src/components/Sidebar.tsx`, a new `web/src/components/TeamMenu.tsx`, the ⌘K palette
  `web/src/components/SearchDialog.tsx`, `Layout.tsx` for the invite dialog). Why: the computer's sidebar and its
  entry points are core web UI (see docs/REPOSITORY-RULES.md). The admin pages are not touched.
- Version impact: minor (a visible change to the sidebar; no API or data change).

## Goal

The owner agreed: "top of the sidebar = the team, bottom = me". Today the top is a plain link with a 20 px logo and the
team name, and Admin is one more row in the main list. The team's name and logo become a bigger, clearly clickable
team menu, and Admin moves into it.

## Scope

In:
- The header (768 px and wider): a 28 px rounded logo, the team name semibold at 16 px (page titles are 18 to 20 px),
  a ▾, the rows' hover and pressed background, a focus ring, `aria-haspopup="menu"`, long names cut.
- The menu: a header block (logo, team name, the team address from `GET /api/me` `team.address` when the server knows
  one), then **Invite people** (owners and admins: the invite endpoints are admin-only) and **Admin** (owners and
  admins, `/admin`). Nothing personal: Settings and Sign out stay in the profile menu at the bottom.
- Keyboard and screen readers as in the profile menu: focus on the first item, arrows, Home/End, Esc gives the keyboard
  back to the button, Tab and a click outside close it.
- A member (no invite, no Admin): the header is not a button (an ARIA menu with no items is a dead end).
- Home: the "Ask Trina" row right below (it opens `/`, as does ⇧⌘O); the header is the team, not a second home link.
- Invite people opens the invite dialog Home's goal card opens (the team invite link's message and its copy button,
  `onboarding/InviteStep.tsx`); while the owner's welcome steps are unfinished it opens their invite step instead
  (the goal card's rule: never a second invite dialog).
- The Admin row leaves the main list on computers.
- ⌘K: "Admin" and "Invite people" among the palette's actions for owners and admins.
- Phones: the ☰ drawer keeps the AI's name and Admin stays on the 나 tab (decided after looking at both screens; see the
  DECISIONS entry "The team menu").
- Comments in Sidebar.tsx, a DECISIONS entry, a CHANGELOG line, new strings in all five languages.

Out: the profile menu (PR #288 adds the status there), the admin pages (Admin › Team settings still previews the
header at 20 px; a follow-up there), a team switcher.

## Steps

1. `TeamMenu.tsx`: the header button, the menu, the invite dialog (one, mounted in Layout, opened from the menu and
   from ⌘K).
2. Sidebar: the header uses it; the Admin row goes; comments.
3. SearchDialog: the two actions.
4. i18n (en first), DECISIONS, CHANGELOG.
5. Tests: unit (sidebar, team menu, palette), e2e (admin → Admin, member: none, Invite opens the dialog, keyboard,
   the Admin row gone, the phone drawer); every spec that clicked the Admin row.
6. Screenshots at 1440 and 390, light and dark; one independent review; the full web e2e once.

## Risks

- Every e2e spec that went to Admin through the sidebar row (admin.spec.ts, admin-home.spec.ts, sidebar.spec.ts).
- The profile menu's PR #288 touches the same file (the account menu and the drawer's footer); keep both on rebase.
- No migration, no API change, no permission change (Admin and invites stay owners and admins only).

## Tests

`bun run typecheck`, `bun run check:i18n`, `bun run check:docs`, `bun run test:web`, `bun run build:web`, the touched e2e
specs, then the full web e2e once.

  the menu (team, whole name, address as the menu's description; 팀원 초대, 관리자), the invite dialog mounted once in
  `Layout.tsx`.
- Sidebar: the team menu on computers, the AI's header in the phone drawer as before, no 관리자 row; comments.
- ⌘K: 관리자 and 팀원 초대 for owners and admins, found by their words only (the empty palette keeps six actions).
