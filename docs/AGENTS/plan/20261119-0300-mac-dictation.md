## Goal

In the Mac desktop app, the words show in the message box while the person talks (about every second), and the last
word is in the box a moment after Stop, as in Yogurt. The sound never leaves the Mac.

## Design

- **Helper** `desktop/native/dictation/main.swift` (Swift, swiftc, no Xcode project; universal, runs on macOS 12+ and
  says "unavailable" below 26 or on Intel). `probe` / `install` / `listen --language xx`. `listen` reads 16 kHz mono
  16-bit sound on stdin and writes JSON lines: `ready`, `text` (final false = a guess the next text replaces, final
  true = kept), `done`. SpeechAnalyzer + SpeechTranscriber with `.volatileResults` and `.fastResults`. It never opens
  the microphone: the page records as before and hands the samples over, so the app's one microphone question stays
  the only one. SpeechTranscriber asks no Speech Recognition question (checked: it ran with that permission "not
  determined"), so no new Info.plist text.
- **Model**: Apple's model per locale through AssetInventory, on the first tap of the mic; that recording goes the
  server's way and the bar says how far the model is; later recordings use the Mac. The reservation is per app: a
  model another program fetched still has to be reserved once (seconds when the files are there).
- **Language**: the app language (en, ko, ja, zh, es …), with the Mac's own region when its language list names one
  (en-GB on a British Mac), else a usual region. SpeechTranscriber has no "auto" language, so there is none.
- **Main process** (`DictationHost`): finds the helper next to the app's program (Apple silicon, Darwin 25+, not the
  Mac App Store build), one check per language, one download per language, one recording at a time, the words to the
  page that started it only; a reload or another page ends the recording; a crash sends the next recordings to the
  server until the app restarts.
- **Page** (`OnDeviceRun`, readiness store): the box shows final words, then the newest guess; Stop waits for `done`;
  Esc puts the box back; a helper that stops keeps the words and says so.
- **Signing**: electron-builder copies `native-build/dictation` into `Contents/MacOS` and signs it with the app
  (Developer ID, hardened runtime, notarized with the app), as the meeting helper was. No step of its own in CI.

## When the team server transcribes instead

| case | what happens |
|---|---|
| Intel Mac, macOS before 26, Windows, a browser, the phone apps | the server, as before (no helper or no bridge) |
| a language the Mac lacks (Indonesian) | the server |
| first tap for a language (model not here yet) | that recording: the server; the model comes down meanwhile |
| the model download failed | the server; the next tap tries again |
| the helper does not start, crashes, or stops answering | the server for the rest of the app's run; words already written stay |
| the browser keeps the sound paused | the whole recording to the server, as before |
| the team turned voice input off | no mic at all (unchanged) |
| a confidential chat, Safe operations 1A, voice input through OpenRouter | **the Mac** (the sound never leaves it); while its model is not there yet, the note says it is getting ready, with its progress |

No team setting asks for the server's handling: speech settings are about where sound may go (off, this server,
OpenRouter), and the Mac is stricter than all of them. Details in the decision file.

## Final text: as the Mac writes it, or a whisper pass as Yogurt does

As the Mac writes it, no whisper pass. On real read speech (60 Zeroth Korean, 73 LibriSpeech clips) the Mac's final
text had 6.1% CER / 3.7% WER, whisper large-v3-turbo 6.7% / 5.0%, whisper small 10.8% / 8.3% (no-digit clips: 2.7% /
3.4% against turbo's 2.7% / 5.2%). First words 1.26 s (ko) / 0.88 s (en) after the speech starts, every word final
0.37 s / 0.20 s after Stop. Details in docs/decisions/20261119-mac-dictation.md.

- **iPhone** (Expo app, `mobile/`): a native module over SpeechAnalyzer/SpeechTranscriber on iOS 26 (the same JSON
  events as the Mac's bridge, so `macDictation.ts` becomes `deviceDictation.ts`), SFSpeechRecognizer with
  `requiresOnDeviceRecognition` on older iOS where the locale has an on-device model (Korean did not on this Mac; check
  on a phone). Needs NSSpeechRecognitionUsageDescription for the old API only. App Store release. About 3 days + review.
- **Android**: `SpeechRecognizer.createOnDeviceSpeechRecognizer` (Android 13+) with partial results; Korean depends on
  the phone's language pack: check on the Note10 (phone-lock first). The WebView keeps the microphone, so the app
  hands its own recognizer's words to the page, not sound. Play release. About 3 days + review.
- Both: the same fallback table; the page's state machine and tests carry over.
