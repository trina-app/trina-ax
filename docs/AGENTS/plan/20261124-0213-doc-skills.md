# Word, PowerPoint, Excel and PDF are built with real document skills

- Date (UTC): 2026-11-24 02:13
- Branch: `feat/doc-skills`
- Status: in progress (phase 1 of 20261124-0314-doc-quality-all-situations.md, on branch plan/doc-quality-all)
- Where: `resources/doc-skills/`, `server/src/devenv/`, `server/src/chat/prompt.ts`, `scripts/system/packages.json`. Why:
  documents are core server work and the libraries belong in the one package list (docs/REPOSITORY-RULES.md)
- Version impact: minor, a new way to build documents. A root update, because the package list changes

## Goal

A person asks for a Word, PowerPoint, Excel or PDF file and gets a designed result. Today the prompt sends those requests
through Markdown, which cannot express a cover, cards or a colour system, and the AI cannot see Word or Excel pages.

## Scope

In: Anthropic's Apache-2.0 docx, pptx, xlsx and pdf skills at one pinned commit, available to the AI in the existing
dev environment run; the prompt uses them where a run exists; honest wording when a file could not be viewed.
Out: Hangul (stays on make_file), Mac team servers and the office Mac (no run with the libraries), installs without a
dev environment (stay on make_file, with a server-side page view on Linux), any per-document or per-sample tuning.

## Steps

1. Vendor the four skills with their licence, source, commit and our changes recorded.
2. Add the missing libraries to `scripts/system/packages.json`, with no install at run time.
3. Give every run the skills read-only, without adding anything to a team's folder or skill list.
4. One prompt rule: read the skill, build in the work folder, look, save with `save_work_file`.
5. LibreOffice in its own commit, so it can be dropped. The server draws saved Word and Excel pages with it, because a
   run cannot start it. Without it the AI says the result was not viewed.
6. Rerun the five earlier requests and five new ones with real AI.

## Risks

AI-written code builds documents: it runs only inside the srt run, with that run's folders and network. Vendored scripts
are read-only in a run. Disk grows on servers with a dev environment. No migration.

## Tests

`bun run typecheck`, `bun run check:docs`, `bun run check:prepush` on Bun 1.3.12, the system-packages, dev-env and prompt
unit tests, a real srt run in a container.

## Phase 1 (owner OK 2026-11-24)

1. Office exit check at every way out of a run, including direct writes in project and own folders.
2. Excel values by LibreOffice recalculation in the converters' isolation, only results copied back.
3. Decks through the same LibreOffice page view.
4. LibreOffice from apt on Debian 13 only, with the security floor, in a default group.
5. Measured at Starter size; 18 held-out requests, blind paired judging, time and tokens.

## Result

Built as planned, with one change: LibreOffice cannot start in a srt run, so the server draws saved Word and Excel pages
in its converter isolation. Details and the install-type table: docs/decisions/20261124-doc-skills.md.
