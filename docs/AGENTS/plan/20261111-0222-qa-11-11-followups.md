## Scope

1. **TC-016 (fail): the AI's delete of a project folder gives the skill-folder reason.** `TeamFiles.aiTrashRefusal`
   checks `holdsSkillRoot` first, which counts every `projects/<p>`, `groups/<g>` and `users/<id>` folder as holding
   skills, so "Delete the project folder projects/Acme Launch" is refused with "skills are not deleted from a chat … the
   Files screen or the Skills page". The block stays exactly as it is (every one of these stays out of the AI's reach,
   in `aiTrashRefusal` and in `remove()`'s own guard); only the reason changes, by what the folder is:
   - a project's folder, or one that holds one: the project is deleted on the Projects screen (where a team project's
     folder can go to the trash with it);
   - a group's folder, or one that holds one: deleted on the Files screen; deleting the group keeps its folder;
   - the person's own folder (`users/<id>`): never goes to the trash; what is in it can;
   - a rule folder, or one that holds one: deleted on the Files screen;
   - the skill reason only for a skill folder, something in one, or a folder that really holds one (a `skills` entry
     in it now);
   - a folder right in `projects/` or `groups/` that is none of these: deleted on the Files screen.
   What the folder is comes before what it holds. Who does it in general words: "the user" when they may (owner,
   admin; a project's creator), else "an admin" / "its creator or an admin"; never a person's name (docs/DECISIONS.md
   "Admins are never named"). One test per kind: the reason, that nothing moved, `remove()`'s guard.
2. **Doubled quote marks** in a shared answer. The room shows a shared answer's Markdown with the typography's quote
   marks on every `>` quote, so an answer that quotes `"…"` reads `“"…"”`; the chat it came from shows top-level quotes
   without them. The room drops them for shared answers and the room's own AI answers.
3. **Raw path in file-save steps.** The steps of saves a card's "이번만 허용" (or a room grant, a schedule's card, the own
   folder rule) let through end in " · <why>", so `stepPlace` took the why as the path. The four "why" words move to
   `shared/src/step-labels.ts`; `stepPlace` takes a known why off (in any language), says the path in words and puts
   the why back in the screen's language.
4. **TC-018 chip.** The answer's file summary counted a folder made by a move as a file and called moved files
   "Created". An empty folder the tool made is left out, and a moved file is marked (`moved: true`, an optional field:
   older apps keep showing "Created"); the chip says "Moved". A file this answer made and then moved stays "Created", at
   its new place. A folder that came with its files (moved or copied whole) stays one row, so its chip does not vanish.
5. **TC-070 count.** The share dialog counted the project's people but me (the server's `audience`); the footer and the
   copy-link toast count everyone who can see it, me included. The dialog now says the footer's number with the
   footer's words ("Share this chat? Then 3 people in the project can see it"). Only the dialog's own text and count:
   `shared.ts`, `projects.ts`, `read-rooms.ts` and the members dialog are another branch's (feat/project-members-only).

Out: the server's `audience` field of the share check (unchanged), any other refusal of the AI's delete.
