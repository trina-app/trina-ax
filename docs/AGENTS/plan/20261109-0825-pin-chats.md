- Version impact: minor, a new endpoint pair and an additive migration.

## Goal

The owner: "trina history more 버튼에서 상단 고정 pin 기능 만들자." A chat row's "…" in the sidebar's 트리나 기록 gets
**상단에 고정** / **고정 해제**. Pinned chats stay at the top of the list, for the person who pinned them only.

## Scope

In:
- Migration 277 (B): `chat_pins(user_id, chat_id, pinned_at)`, one row per person and chat, cascading with the chat and the
  person.
- `POST /api/chats/:id/pin` and `DELETE /api/chats/:id/pin` (chatFor 'view', not in the trash), both idempotent, answer
  the chat. `Chat.pinnedAt` for the viewer on every chat the API or `chat.updated` gives.
- `GET /api/chats` (no search, not the trash; also with `projectId`): the first page starts with my pinned chats there,
  the most recently pinned first; the pages after it leave them out.
- Clean-up: a pin goes when its chat goes to the trash or is purged (cascade), when the person is deleted, and when the
  person can no longer see the chat (dropped when their list is read).
- A pin or unpin tells only my own windows (`chat.updated` to me).
- Web: the row's "…" item (the shared row menu: right-click, long press, the phone sheet), a small pin icon on pinned
  rows, pinned first in the sidebar (at most 10 above the five latest; all of them in "모두 보기" and the phone drawer)
  and on a project's page. Five languages.

Out: drag to reorder, a "Pinned" header, pinning from the chat's title menu or from the project page rows, a pin limit
in the UI beyond the server's cap.

## Steps

1. Migration, `server/src/chat/pins.ts` (pin, unpin, pinnedAt, clean-up), routes, contract.
2. listChats pins-first, `chatView` / `publishChat` carry `pinnedAt`, delete / project delete / member delete clear pins.
3. Web: store keeps pinned rows in the list, Sidebar and Projects order and icon, row menu item, i18n.
4. Unit tests (b-chat-pins), web unit tests, e2e (sidebar pin, unpin, right-click), screenshots.
5. DECISIONS, CHANGELOG, `docs:api`.

## Risks

- Migration number: 275 is the highest on dev, 276 is taken by an open branch (side chat). Re-check before pushing.
- A shared chat: a pin is mine only; nobody else learns of it, and it never widens who sees the chat.
- The first page grows by the pins: the server caps pins per person (50).
