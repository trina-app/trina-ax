# Onboarding v6.3: what a new member sees first ("팀에 준비된 것" on Home)

- Date (UTC): 2026-11-08 17:34
- Branch: `feat/onb6-members`
- Status: in progress
- Where: trina-ax core (`shared/src/api/skills.ts`, `server/src/skills/examples.ts`, `server/src/routes/memories.ts`,
  `web/src/pages/Home.tsx`, `web/src/components/onboarding/`, i18n, tests). Why: Home, skills and the team folder are
  core onboarding (see docs/REPOSITORY-RULES.md).
- Version impact: minor. A new member endpoint (`GET /api/skills/examples`) and a visible change on a first-time Home
  and on the invite step.

## Goal

After onboarding v6 the owner invited a member and the member saw a bare Home: 할 일 정리 is gone, the invite lands on
Home, and nothing there names what the team prepared. A new member should see the team's skills (with an example and
a way to try each) and the team's files, and always one first useful thing to press. The owner, before inviting into
an empty team, hears once that members would find nothing.

## Scope

In:
- `GET /api/skills/examples` (`auth: 'user'`), read as the caller: the caller's team and group skills (the kept ones at
  their own pack path with their example and source, an owner's same-name skill without), the team group folder's file
  count (recursive, as the caller, capped at 100, without the brand folder, dot files and system files; null when the
  caller cannot read it), the landing skill only when the caller can open it, whether the caller ran a team skill,
  whether a company profile is saved. Nothing owner-only (no profile, nothing installable).
- Home: "팀에 준비된 것" in place of the first-time folder card and its three example boxes: up to 3 skill rows (예시,
  써 보기; 자연스러운 글 fills the box with "/humanizer 아래 글을 자연스럽게 다듬어 줘:"), "팀 스킬 N개 더 ›", a files row
  with 물어보기, and "이렇게 시작해 보세요" with one ready question when nothing is prepared. Skills stay until the person
  ran a team skill; files only while they have no chats. One filled button for members; none for owners and admins,
  who see "스킬 넣기 · 팀 파일 넣기" instead of the ready question. A member without AI gets the block read-only under
  the no-AI card; owners and admins get no block there.
- The invite step (5/5) and the goal card's invite: one line "지금 초대하면 팀원이 볼 게 없어요 · 스킬 넣기 · 팀 파일 넣기"
  when the team has no skills and no documents, hidden while "이 사람이 팀장이에요" is ticked. Never blocks.
- The Files screen's "폴더에서 회사 문서 추천받기" uses the same count (it counted one level only).
- i18n in the five languages (`home.prepared.*`, `teamLink.empty*`), DECISIONS "W6.3", the mock server, docs:api.

Out:
- Changing where an invite lands (a link with the owner's shared skill keeps its form).
- A "팀원에게 이렇게 보여요" preview label (optional in the review).

## Risks

- No migration (runs are already recorded in `turn_skill_runs`, migration 223).
- Permissions: everything is read as the caller through the file layer (`authorize`, the folder rules); the count is
  a number only, never names; the welcome state stays admin-only.
- The walk is capped (100 files, a bound on entries visited) so a large team folder costs little.
- Phone and computer layouts; the five app languages.
