# Share dialog for a non-owner, and what an access request's Share does

- Date (UTC): 2026-11-22 00:31
- Branch: `fix/shux-b`
- Status: in progress
- Where: web (Share dialog, Activity), server (files/shares.ts), shared (api). Why: two QA findings (TC-7230, TC-7231)
- Version impact: patch: wording and one small route over the existing access-request mechanics, no new permissions

## Goal

1. TC-7230: a project member who opens Share on another member's file reads only "Only the owner can share this
   file." and has no next step. They should read who to ask by name, and be able to ask the owner to share it with
   someone.
2. TC-7231: the owner's card for an access request is a bare Share / Decline. It should say what Share does: only this
   file, view only, for that person; and, when true, that the person is not in the project, so its other files stay
   hidden.

## Scope

In:
- Share dialog, someone who may not share a file that has an owner (sharing not off): "Only {owner} can share this
  file. Ask {owner} to share it." and a people picker (people only, no groups or Everyone) with "Ask {owner}".
- `POST /api/files/shared/:id/ask-for` over the existing `FileShares.requestFor` (the "Ask <owner>" step under an AI
  answer): same checks (can open it, may not share it, never a guest, the same request budget), one request row per
  person, the owner's existing Share / Decline answers it. Audited as `file.access_request` with `via: 'dialog'`.
- The request card in Activity: one line under the sentence, and the button reads "Share this file". The server adds
  `outside: 'project'` to the notice when the file is in a team project the person cannot open.

Out: groups or Everyone in the ask; a note in the ask; anything for folders.

## Steps

3. Tests: tests/unit (route + notice), web/test/unit (dialog + card).
