## Goal

Two places decide which AI answers on their own:

1. A scheduled run uses the team default engine and model (`rt.defaultEngine()`), not its owner's. Someone whose own
   default is Codex and who has only a ChatGPT connection gets every scheduled run on Claude Code, which fails with
   "no AI connection". Every other way of starting a chat goes through `newChatEngine`.
2. "A Claude Code chat answered by Codex when only Codex has a working connection" (and the other way) only happens on a
   server that holds the hosting service's trial key, in any state (`connectionRoute`). Clear the key, or move the team
   to its own server (the key is dropped there at start), and the same chats fail and Admin › Members shows "No AI",
   with no setting changed.

## Scope

In:
- Scheduled runs: the owner's engine and model at run time, through `newChatEngine` and `turnEngine` (as Slack does).
  Every run is a new chat, so there is no existing chat to keep.
- The existing switch `engines.limitFallback` becomes "다른 AI로 대신 답하기": it covers both "the chat's engine has
  no working connection of the person, the other of Claude Code / Codex has one" and "Claude hit its limit". Same key,
  same API fields; the trial key no longer gates the first case. The trial credit still answers only when nothing that
  may answer works.
- Default: off where it was off. On a hosted server it is written on once (while Codex is on), so hosted teams keep what
  they rely on, it shows in Team settings, it stays when the key goes, and it travels with the team's backup to its own
  server. Self-hosted servers stay off until an admin turns it on.
- `newMemberAi` (the invite link's AI line) counts the other engine while the switch is on, like `canUseAi`.
- Team settings: the same row, new label, description, hint and warning (5 languages). No new card or section.

Out: a Codex-limit fallback to Claude Code; the no-connection fallback on servers whose engines sign in on their own
(no per-person connections there).

## Risks

Hosted teams that saved Team settings had `engines.limitFallback: false` written (the save sends it); the one-time
hosted write turns it on regardless, which also turns on the Claude-limit half for them. No migration file.

## Result

Built as planned: scheduled runs resolve their owner's engine through `newChatEngine` / `turnEngine`; the switch
`engines.limitFallback` is "다른 AI로 대신 답하기" and alone lets the other engine answer a turn with no working
connection; hosted servers turn it on once at start (`settleHostedFallback`). Differences from the plan, from the
review: the trial credit never answers while the person has a connection on the other engine, the switch on or off
(as before this change); the invite line, the composer and Admin › Members use that same rule (including the
switch's Claude limit case); switching it sends `engine_choice_changed`. PR: see the branch `fix/engine-choice`.
