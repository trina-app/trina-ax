## Goal

The owner's rule: the AI should behave like Claude Code, and a limit Claude Code does not have is a bug unless it
keeps one person's data from another. Six such limits are still on dev (QA TC-4979 … TC-4984).

## Scope

In:

1. TC-4983 (N42): `rename_files`, many renames in one call: a list of `{path, new_name}`, or a find/replace on the
   names directly inside one folder (plain text, at the start, end or anywhere). Each item goes through rename_file's checks
   (access, skill folders, a taken name fails that item, versions, file events, the audit line). At most 500 per call;
   more matches: the first 500 are renamed and the answer says how many are left. Offered wherever rename_file is
   (shared chats, guests, sub-agents, the room card lists, step labels, key hiding).
2. TC-4984 (N18): `drive_read` gets `offset` (characters) and says where to go on when the text was cut.
3. TC-4979 (N33): skill and deferred-tool descriptions in the AI's list up to 400 characters (was 160) within the same
   8,000-character budgets; find_tools returns up to 25 (was 10).
4. TC-4980 (N34): the company profile the AI reads up to 8,000 characters (was 2,000); the long fields (products,
   customers, expressions to avoid) take more so a person can type it.
5. TC-4981 (N40): web_fetch and save_url ask sites for the person's language (else the team's), then English; was
   always Korean first.
6. TC-4982 (N41): 50 scheduled tasks per person (was 20).

Out: Drive OCR and copying Drive files (other items), other open audit items.
