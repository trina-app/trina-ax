# Fixes from the Windows (WSL2) QA of 0.20.2

- Date (UTC): 2026-11-28 10:12
- Branch: `fix/wsl-qa-0-20-2`
- Status: done
- Where: server/src (tools, files, mcp, system, integrations), web/src (admin pages, i18n), scripts/windows, docs. Why:
  bugs found on a WSL server, none Windows-only in code (see docs/REPOSITORY-RULES.md)
- Version impact: patch, bug fixes and wording only; no API, schema or setting changes

## Goal

The WSL QA run found: AI file saves that failed with a bare "internal error" and nothing in the server log; the AI then
sending the user to Admin › System › Storage on a disk 1% used; Admin › Connected apps listing the Google cards as On
while their pages said Not set up; a Windows-app button on a 127.0.0.1 page; two leftovers of the WSL setup script; and
Mac or office-network wording on a Linux/WSL server.

## Scope

In:
1. Every catch-all that turns an exception into "internal error" (mcp/protocol.ts, tools/registry.ts, files/service.ts,
   and the per-item reasons of copy/move, unzip, query_data, delete_files) logs the cause once (tool, turn, user, code,
   stack) with a short reference, and tells the AI the kind (temporary: EAGAIN/ENOMEM/EBUSY/EMFILE/SQLITE_BUSY; or
   unexpected), the reference, and to retry once. A converter start refused for want of memory or processes (EAGAIN,
   ENOMEM) is retried twice, and its temp folder is removed when it still fails.
2. The storage hint: that same text says what the team's storage is like only as measured (room: "not a storage
   problem, do not send the user to storage settings"; full: "may be the cause"; unmeasured: nothing).
3. Admin › Connected apps: the Google Drive status and the Google apps' list read the hosting service's answer fresh
   (brokerFresh, as the company's-app row already did), concurrent reads share the one check under way, and the page
   reads the Google statuses again when moving between the list and a card's page.
4. "Continue in the Windows app" on 127.0.0.1: checked against the 11-25 decision (invite-open-app-first).
5. install-wsl-server.ps1: the global WhatIf preference off while modules load (Dism's own Set-Alias read it); a sleep
   value powercfg did not show is saved as "unknown" and the uninstall skips it.
6. Wording: the Ollama preset says "on the server's computer" (not "this Mac"); a WSL server's relay check does not say
   "office network"; a sign-in that fails only because the team is open at a non-https address says the https address
   fixes it (oauth_needs_https). All six languages.

Out: a definite root cause for #1 (not reproduced; see Result).

## Steps

1. tools/internal-error.ts (log + AI text), wired at each catch-all; context.ts gives it the server log.
2. tools/isolate.ts spawnRetrying.
3. google-drive/oauth.ts brokerFresh shares the check under way; routes/drive.ts and routes/google-apps.ts call it;
   web admin Integrations.tsx reloads on navigation.
4. scripts/windows/install-wsl-server.ps1, docs/INSTALL-WINDOWS(.ko).md.
5. system/wsl.ts + messages-linux.ts wslMessages; connections oauth.ts needsHttpsAddress + text.ts; i18n.
6. Tests: tool-internal-error, c-drive-broker, c-integrations-approved-apps, g-linux-diag, windows-wsl-install,
   mcp-socket-parallel.

## Decisions

- No guessing in the AI's error text: only what was measured (storage) or known (the error code) is said.
- #4 is as designed: the decision covers any computer browser; the app's refusal of loopback links is noted for the owner.

## Result

- #1: no definite cause. The save paths share placeProduced/atomicWrite renames and, for Office files, an isolated
  converter start (Bun.spawn) whose EAGAIN/ENOMEM was not handled; the latter is the most plausible transient cause on a
  host with ~490 MB free and is now retried. The new log line (with its ref) will name the cause next time.
