# Dev environment on srt: the Preview button again (Linux)

- Date (UTC): 2026-11-12 14:13
- Branch: `feat/srt-preview`
- Status: done
- Where: trina-ax (native/cmd/mycel-sandbox, server/src/devenv, web chat steps). Why: the dev environment is part of
  this repo (docs/REPOSITORY-RULES.md).
- Version impact: minor. A new feature (the Preview button and the gateway come back for the srt runner).

## Goal

A person cannot see a web app that the AI built in the dev environment. The dev server of a run listens on 127.0.0.1
in the run's private network namespace, and nothing outside the run can reach it. The AI can only test it with curl in
one command. This change gives the person a Preview button on the chat step of a dev server, as the box runner did.
Linux only (on macOS the preview will use the shared localhost, a later change).

## Scope

In:

- `mycel-sandbox port-forward` (Go): it finds the network namespace of one run (from the run's scope cgroup, where the
  port listens), checks that its owner user namespace belongs to the server account, binds a unix socket, and enters
  the namespaces through util-linux `nsenter` (Go cannot setns into a user namespace: its runtime has many threads).
  The forwarder then copies each connection on the socket to `127.0.0.1:<port>` (or `[::1]:<port>`) in the run. Ports
  3128 and 1080 (srt's proxy relays) are refused.
- The server: `previewSocket` on the srt system seam (tests use a fake), the forwarders per run and port, stopped when
  the run ends. The preview gateway (`server/src/devenv/preview.ts`, removed in #579) comes back: links per run (row,
  run id, person), short tokens, a cookie per origin, and the checks on each request.
- A route `POST /api/dev-env/runs/:runId/preview` (the person who started the run only).
- box_shell: a `port` parameter for background=true. The tool text names the Preview button when the gateway is set up.
- The chat step of a dev server (`Step.devEnvRun` kind `server`, with its port) shows a Preview button while the run
  runs. Strings in five languages.
- Tests: Go unit tests, server tests with a fake system, the preview checks in the VM driver (S2, A26, the sandbox
  cannot open a preview socket, end to end through the gateway). A real run on a temporary Debian 13 VM.
- Docs: DECISIONS entry, `changes/srt-preview.md`, the design doc and the operator notes.

Out: WebSocket upgrades (Vite HMR falls back to a full reload), HTTP/2, macOS, Ubuntu 24.04 (another session), Docker
(`MYCEL_DEV_ENV_SRT_DIRECT=1` has no scope cgroup: no preview there).

## Steps

1. Go: `port-forward` and `port-forward-inner` in `native/cmd/mycel-sandbox/`, with unit tests.
2. Server: the system seam, the forwarders, `preview.ts`, the route, the gateway start, box_shell `port`, the tool text.
3. Web: the Preview button on the step, i18n, the mock server.
4. Tests: server unit tests, the permission matrix case, the VM checks.
5. Docs, then a VM run, then the PR.

## Risks

- Security: a link for run A must never reach run B (A26). The socket path and the run come from the DB row, never
  from the client. The forwarder checks the cgroup, the namespace owner and drops to no capabilities. The socket is in
  `<base>/devenv/run`, which the sandbox cannot see, and the sandbox has no AF_UNIX.
- S2: setns under NoNewPrivileges and the server unit's rules. Checked on the VM as the server account in the stand-in
  unit.
- No migration (the port is on the chat step and in the link). Five languages for the new strings.

## Tests

`bun run typecheck`, `bun run check:i18n`, `bun run check:docs`, `go test ./native/...`, the dev-env unit tests,
the permission matrix, the web unit tests for the step, and `scripts/dev-env/srt/spike-vm.sh` on a Debian 13 VM.

## Result

Built as planned. PR: https://github.com/trina-app/trina-ax/pull/621.

- Differs: no `DevEnvRunner` interface exists, so `previewSocket` goes through the runner's system seam
  (`SrtSystem.forward`). The netns setns goes through util-linux `nsenter` (Go cannot enter a user namespace). A link
  belongs only to the person who started the dev server.
- VM (Debian 13, t3a.medium, systemd 257, `--profile trina`, tag `trina-test=srt-preview`, `vm-check.sh REPO preview`):
  runs 4 and 5 passed all checks (S2, A26, the socket from the sandbox, the end of a run). Runs 1 to 3 found driver
  faults (pandoc missing, a shell `&` that put `cd` in a subshell, a check by count), fixed in the driver. In run 3 the
  second dev server had ended before its link, and the driver did not keep its log. Run 5 started that same two-port
  server 4 times (P2- and P5-1..3): it ran each time and its page opened. All 5 VMs are terminated; no volume or
  security group is left.
