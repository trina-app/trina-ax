# Hangul documents a person can send as they are, starting with official letters (공문)

- Date (UTC): 2026-11-24 13:16
- Branch: `fix/hwpx-quality`
- Status: in progress
- Where: server/src/files (the .hwpx writer), server/src/tools/make-file.ts, server/src/chat/prompt.ts. Why: the writer
  and the AI's instructions live there (see docs/REPOSITORY-RULES.md)
- Version impact: minor, because Hangul documents can hold more (centred and right-aligned blocks, sizes, boxes,
  merged and borderless tables, lines, outline labels) and the AI gets a Hangul writing guide

## Goal

QA on qa.trina.app (build dbf0fe0e8, real AI, TC-8596) asked for a 공문 in Hangul. The file was not sendable: the
header was a "구분/내용" table with an empty (경유) row, items 다/라 were bracket placeholders, the 기관명 and 발신명의
were left-aligned headings. Word, Excel and PDF from the same build were fine, because the AI reads Anthropic's
document skills for them and can design the page. Hangul has neither a guide nor a writer that can express a designed
page, and the AI never looks at the result.

Root causes (read in the code and in the QA answer: "이 방식으로는 칸 구분이 없는 표를 만들 수 없어서 … '구분 / 내용'
머리줄이 들어가 있습니다"):

1. The Markdown → .hwpx writer has no way to centre or right-align a paragraph, size text, draw a box or a line,
   merge cells or leave a table without borders, so a letterhead, a 발신명의 or a 결재/시행 block cannot be laid out.
2. Korean outline labels (1. 가. 1) 가) (1) (가), and □ ○ - · in 개조식 reports) are plain text with no indent; lines
   that start with them run into the paragraph above unless there is a blank line between.
3. The AI gets one line ("write Markdown and convert it with make_file") and no knowledge of how a Korean document
   is laid out, nor a rule on facts it lacks, so it leaves whole items as "[… 기재]".
4. Nothing tells it to look at the pages it made (hwp_render exists for that).

## Scope

In:
- Writer primitives, all in pandoc's own Markdown syntax so the AI needs nothing new to learn: fenced divs
  `::: {.center}` / `{.right}` / `{size=…}` / `{.box}` / `{.noborder}`, headerless tables (an empty header row), grid
  tables with merged cells, `---` as a line, underline and strikethrough, column widths from content when the
  Markdown gives none.
- Korean outline labels: a paragraph that starts with one gets the standard indent of its level and a hanging indent;
  a line in the source that starts with one starts a new paragraph (the same tree for the writer and the read-back).
- A Hangul writing guide for the AI (general conventions of Korean business and official documents: 공문/기안문
  layout, 보고서/계획서 개조식, 회의록, 안내문; numbering, dates, amounts, 붙임, 끝; how to treat missing facts) and a
  look step with hwp_render where it is offered.

Out: pictures in a new .hwpx (signatures and seals stay with edit_hwp), page numbers and headers/footers, a
docx/HTML → hwpx converter (considered: it would only help where a run exists and would need a second layout engine;
the writer reaches every install).

## Decisions

`docs/decisions/20261124-hwpx-quality.md`: the Hangul writer takes pandoc's attribute syntax; Korean outline labels
are laid out by level; the AI gets a Hangul guide in its instructions (not a vendored skill: there is none upstream).
Extends docs/decisions/20261124-doc-skills.md ("Hangul stays on make_file").

## Risks

No migration. The writer runs only in the office worker (unchanged isolation); new inputs are bounded like the old
ones (div depth, sizes clamped, spans checked against the table). The read-back check keeps refusing a file that does
not read back as the document. Prompt size grows only where Hangul writing is on.
