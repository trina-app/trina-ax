# Read on instead of a silent cut: connection answers, web pages, command output

- Date (UTC): 2026-11-18 17:10
- Branch: `fix/audit1-read-on`
- Status: done
- Where: Team AX core (`server/src/integrations/connections/`, `server/src/tools/web-fetch.ts`, `server/src/devenv/`). Why: the AI's tools are core.
- Version impact: patch (no new setting; one new tool in turns that have connection tools)

## Goal

Limits audit 1, items #13, #14 and #21. Three tools cut a long result and gave the AI no way to read the rest, where
Claude Code would page or keep the end: a connected service's answer (40,000 characters), a web page (40,000 by
default) and a shell command's output (only its first 32 KiB).

## Scope

In:
- #13: a connection answer over 40,000 characters is kept for the answer it came in; a new tool `connection_result
  { id, offset }` gives the next part. It calls no service. It checks again that the person may use the connection, and
  in a shared chat it asks with the same card as the call did.
- #14: `web_fetch` takes `offset`; its first line names the characters given and the next offset. Time limit 15 s → 30 s.
- #21: box_shell keeps the first and the last part of a long stdout or stderr (runner: 32 + 32 KiB of each; tool: 16 +
  16 KiB), with a line saying how much was left out.

Out: script-rendered pages for web_fetch (audit #14 "later"); saving connection answers as files.

## Steps

1. Kept results per tool build (`KeptResults`, a WeakMap on the build), `wrap` with parts, `connection_result`.
2. `textPart` / `fetchedLine` in web-fetch.ts, `offset` in `WebFetchInput`, the tool text.
3. `readEnds` in srt/runner.ts, `clip` in devenv/tool.ts, the tool text.
4. Tests: c-integrations-tools (read a 1 MB answer to its end), c-webfetch (offset, emoji at a cut, size cut),
   devenv-output-ends (readEnds, clip).
