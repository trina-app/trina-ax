# One card for many: cards of one kind from one answer show as one card; the skill card leads in plain words

- Date (UTC): 2026-11-23 03:39
- Branch: `fix/batch-cards` (stacked on #421, the ask registry)
- Status: done
- Where: shared/src/api (card field), server/src/chat (open questions, turn, tools), server/src/skills, web/src (card).
  Why: the owner asked for several skills at once and got one huge card per skill, stacked.
- Version impact: patch: card layout and wording; no new setting, no migration.

## Goal

"스킬 여러개 만들라고 하니깐 한번에 저렇게 다 띄워 버리네." When one answer raises several cards of the same kind (skills
to the team, shares, posts, deletes, a connector's writes), the person sees ONE card: what happens to how many, each
item on one line, one set of buttons. One press answers all of them, now or hours later (a waiting card, #412), and
"Always allow" on it covers them all. The skill card leads with plain words (each skill's name and description, one line
for who follows it); paths, name lists, the full SKILL.md and file sizes are behind "자세히".

## Scope

In:
- `AskUserRequest.batch` (optional): a group key, the group's question for one and for n, the item's name, a line about
  it, a warning line, the summary. Cards of one answer with the same key and the same choices show as one card.
- The server stamps a key on every server card raised inside a tool call that has none (`tool:<name>`), so every
  kind groups; such cards keep their whole question and details per item.
- `skill_files` (into a skill folder) and `move_skill` cards set a lean batch (plain lines first, the rest behind 자세히).
- A ticked box per item when there are two or more: an unticked item is answered with the card's "no".
- The press answers each card in order through the same POST /answer; the last one starts the next turn, which runs
  every call again (replayCalls). `sameCard` ignores `batch` (presentation only).
- The two skill tools' descriptions: several skills go in the same reply, so they land on one card.
- docs/ASKS.md rows for the skill cards and the grouping.

Out: the phone app's own card list (it shows each card as before); a server endpoint that answers many in one call.

## Risks

A press that fails midway leaves the rest open (they stay on the card; pressing again answers them). Ticks are per
item, so a no can never be taken for a yes: an unticked item is sent the card's own last option.
