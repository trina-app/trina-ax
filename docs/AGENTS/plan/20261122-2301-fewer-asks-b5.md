## Scope

In:
1. **No unasked share in a side chat.**
   - Prompt: `sideRoomSection` (chat/prompt.ts) told the AI, when the person asks to save something from the room into
     their own folder, to "then share the saved file with the room's other people … with share_with_person". That
     sentence is the cause. New words: save it in their own folder; share it only when the user asks to share or send
     it (then with share_with_person to the room's other people, named); never offer to share or post on your own.
   - Gate: in a side chat, `share_with_person` and `post_to_room` whose asker's own message (the asking turn's while a
     waiting call runs again) has no word about sharing, sending, showing or posting at all (a broad list in the six
     languages, wider than SHARE_ASK/POST_ASK, so it fails open: any such word keeps today's card) are refused before
     any card, with words for the AI: nothing shared, the user did not ask, do not offer it either. A scheduled run or
     Slack: unchanged.
2. **No card for the chat's own file in the person's own folder.**
   - `sharedSources` (chat/turn.ts): a `copy_files` (and `move_files`) whose every source is a chat place
     (chat:work/…, chat:files/…) weighs the files it would write in `to_folder` (`<to_folder>/<name of each source>`),
     not the folder itself: a new name there asks nothing, as for every other save. (Nothing of the folder is read: a
     work-folder or chat-file copy that meets a name there keeps a copy next to it, places-copy.ts workToTeam.)
   - A file that is there and that this chat made or handed over in the person's own folder, untouched since, counts
     as the chat's for a read and for a write target: `chatMadeOwnFile` also takes a file the chat handed over from its
     work folder (`handedOverInChat`), with every other check it has (bytes unchanged, the answers that wrote it ran
     while the chat was shared as now, none of them a k or x answer), and the write-target path gets the same check.
3. **File cards wait across turns.** `write`, `edit` and `make_file` join CARD_LATER_TOOLS for the main AI in a chat a
   person watches. Their cards (shared read/save, room-read change, skill write, wider audience) are all raised before
   the call changes anything; a late press runs the call again with every check made again, the earlier cards of the
   call answered from the saved answers (`prior`), as #412 does for its tools. Kept inside the call as before: a
   sub-agent's call, scheduled runs and Slack, a call whose arguments hold a stored secret, and a call whose saved
   arguments would be larger than 1 MB (a big write's text is not kept in the database).
4. **One source count.** While a turn runs, a post or share check of its own answer reads that answer's files from the
   turn's live source list (the list the end of the turn saves, files/sources.ts SourceLog), not "an answer that never
   ended: every scope place counts". After the turn the saved list is the same list, so the live card and the card of
   a late press count the same sources the same way (`useOf`, chat/answer-share.ts). A turn the server stopped mid-way
   stays as it is (its scope places count).

Out: a general "unasked share" gate outside side chats (the explicit-ask word lists are too narrow to refuse on);
edit_hwp, edit_pdf and the other produce tools (they may join later the same way); the wording of any card.

## Decisions
