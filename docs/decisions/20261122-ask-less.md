# The AI acts on a clear request and says what it assumed; a question is asked once, in one place

- Date: 2026-11-22
- Status: accepted
- Supersedes: none
- Branch: fix/ask-less (ask audit 11-22, QA TC-ask1-12..19, TC-cards-6/8)

- **Ask:** the ask audit found the AI asking before clear "make" requests (about 5 of 12), the same list again after
  an answer, a tool's fixed length sent as a question, one waiting card shown in five places, and several clicks for
  one decision. Claude Code makes the thing with defaults and says afterwards what it assumed.
- **Rule:** a request clear enough to act on is done at once with sensible defaults or a sample (length, layout,
  sections, sample rows); the answer says in one line what was assumed and any tool limit met. The AI asks first only
  when a choice cannot be undone, reaches other people, or has no reasonable default, and never asks the same question
  twice in a row. Defaults shape the work, never the facts: a price, date, name or figure nobody gave stays a visible
  blank (NO_INVENT_RULE, docs/AGENTS/plan/20261122-0024-ai-honesty-qa-1122.md). The rule is in every turn
  (chat/prompt.ts ACT_FIRST_RULE), next to ASK_USER_RULE, whose "decide yourself" part is unchanged.
- **Screens:** a waiting question shows on its card and as the chat row's mark only; a single-choice question is
  answered by one press on an option; a recoverable action on the person's own things (trash in My files, stopping a
  chat's sharing) asks nothing and offers Undo; notes that need no decision leave the Share dialog.
- **Broad searches in a shared chat** (QA TC-f1x S-005/S-012): grep, glob or list in a folder everyone in the chat can
  open leaves out the places below it some of them cannot open (`chat/turn.ts` sharedSearchLeftOut, run hidden as in
  docs/decisions/20261118-shared-hide-subfolder-names.md) instead of a read card; the result tells the AI that some
  places were left out (no names, no count, as the 11-18 decision keeps them out of the chat) and not to mention it
  unless something asked for was not found; naming one asks first. A path that is itself such a place, a read there, the
  person's own folder and a project chat's "/" keep the card; a check that fails keeps the card.
- **Cards name chat places in words** (QA re-smoke): every server card (`TurnExec.waitForPerson` → cardPlaceWords) shows
  `chat:files/<id>/…` and `chat:work/…` as "이 채팅 › name" / "작업 폴더 › …" (the step labels' chatPlaceWords), never
  a file id; text that goes out exactly as shown stays as written.
- **A copy that is already there** (QA S-018): copy_files into a folder that holds a file of the same name and sha256 that
  the person can read copies nothing, asks nothing, and says it is already there.
- **Why:** owner rules: Claude Code is the floor, lean screens, Always allow is final, users are not developers.
- **Left out:** the attach picker's clicks (a picker redesign), restoring a deleted shared chat's notice (TC-ask1-17).
- **Version impact:** patch.
