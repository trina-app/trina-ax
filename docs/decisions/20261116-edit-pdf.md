# PDFs editable by the AI: stamp_pdf, edit_pdf, merge_pdfs, split_pdf

- Date: 2026-11-16
- Status: accepted
- Supersedes: none
- Branch: feat/edit-pdf (the owner; QA TC-3565 to TC-3569 and the rows added with this branch)

Plan: docs/AGENTS/plan/20261116-0335-edit-pdf.md. The skill edits and plain refusals of the same report
are in `20261116-shared-chat-skill-edits.md` (PR #1057).

- **Ask:** the owner asked the team AI, in a shared project chat, to put the company seal on an existing quote PDF; no
  tool could change an existing PDF, and the AI said "no terminal, can't run Python". Then (owner, same day): "PDFs must
  be freely editable, not only stamped": remove, extract, split, merge, reorder, rotate, insert pages, stamp an image,
  add a line of text or a watermark, add page numbers.
- **Shape:** four tools rather than one. stamp_pdf (built first) stays for the most common ask; edit_pdf takes a list of
  operations on one PDF, applied in order (remove_pages, keep_pages = extract, reorder_pages, rotate_pages, insert_pdf,
  stamp_image, add_text, watermark, page_numbers); merge_pdfs takes many PDFs in, split_pdf gives many PDFs out. One
  input and one output per edit_pdf call keeps its permissions and its result the same as every other save.
- **Rules shared by all four:** the result is always a new file next to the original (a free name, "<name> (edited)",
  "(merged)", "(part 1)", "(stamped)" in the team's language); edit_pdf replaces the original only with `replace:
  true`, which the prompt says only when the person explicitly asks and which needs a read of it in this turn (a new
  version, the old one in its history); an `output` that names an existing file the AI did not read gets a conflict
  copy; never into a skill folder. Read access to every PDF and image named (also inside edit_pdf's operations and
  merge_pdfs' list), write access where each result goes (refused before any work, checked again when placed), the
  not-found answer for someone else's file, and the wider-audience check (confirmSources) for every result. In
  SHARED_TOOLS, ROOM_FILE_TOOLS, WRITE_TARGET_ARGS (output; split_pdf's output_folder), the confidential chat's local
  tools and the guest tools. A shared chat's read card weighs the files named inside lists through
  rooms/ai-tools.ts namedPaths (used by TurnExec.sharedSources and sharedStep instead of the top-level PATH_ARGS).
- **Pages** are written like "1,3-5,last", "2-last" or "all", in the order written, each once; an operation sees the
  pages as they are after the ones before it. Rotation is 90, 180, 270 or -90, added to the page's own. Scanned PDFs
  work like any other (these are page operations).
- **Locked and broken PDFs:** a PDF with an /Encrypt entry is refused as locked, one pdf-lib cannot open as damaged or
  not a PDF, each naming the file; nothing is saved. A digitally signed input is changed, and the AI is told to say the
  new file's signature no longer holds.
- **Text:** Helvetica for Latin text; other text (Korean) in the server's Pretendard (resources/fonts/pretendard, a Linux
  bundle's fonts/), embedded whole through @pdf-lib/fontkit 1.1.1 (MIT; its package has no licence file, so the project
  keeps the notice, resources/notices/pdf-lib-fontkit). Whole, about 1.2 MB a file: fontkit's subsetting left the glyphs
  empty (the text was searchable but drew nothing). Letters the font lacks, or no font on the server, are refused in
  plain words.
- **Where it runs:** pdf-lib parses untrusted PDFs, PNGs and the font only in the office worker (modes `pdf-stamp` and
  `pdf-pages`), never in the server process. Limits: 40 MB of input per call, 20 files, 30 operations, 50 parts, 3000
  pages. Every result is read back (same page count) before it is placed.
- **Checking:** for stamps, text, watermarks and page numbers the result tells the AI to look at the changed pages with
  `read` (pages, as_images: true), the existing page-image path.
- **Not added:** changing a PDF's own text or pictures, filling PDF forms, encrypting or unlocking PDFs.

## stamp_pdf

- **What:** an image (a seal, a signature, a logo; PNG with its transparency, or JPG) on one page of an existing PDF
  (a number or "last", the default), at a corner or the centre (margin 15 mm by default) or at x/y in mm from the
  top-left of the page as it is shown (CropBox, /Rotate applied), width in mm (30 by default, height from the
  image). Saved as a new file next to the original, "<name> (stamped).pdf" with the word in the team's language
  ("견적서 (날인).pdf") and a free name, so nothing is overwritten. An `output` that is the original needs a read of it
  in this turn (then a new version, the old one in its history, and the image still goes through the wider-audience
  check); any other existing `output` the AI did not read gets
  a conflict copy (placeProduced, as make_file). Never into a skill folder.
- **How:** pdf-lib 1.17.1 (MIT; notices in docs/THIRD-PARTY-NOTICES.md) in the office worker only (mode `pdf-stamp`,
  files/pdf-stamp.ts): it parses an untrusted PDF and decodes an untrusted PNG, so it runs under the worker's isolation
  and limits, never in the server process (the rule of files/office-parse.ts). The page's own drawing is wrapped in
  q … Q first, so a page that leaves its coordinates changed cannot move the image. Limits: PDF 40 MB (the result comes back under the worker's 64 MB output cap), image 10 MB and
  8000 px a side. The result is read back (same page count) before it is placed. A PDF with an /Encrypt entry is
  refused as locked ("locked with a password or protected against changes"), a file pdf-lib cannot open as damaged or
  not a PDF; a digitally signed PDF is stamped, and the AI is told to say the copy's signature no longer holds.
- **Permissions:** read access to the PDF and the image, write access where the result goes (refused before any work,
  checked again when placed), the not-found answer for someone else's file. In SHARED_TOOLS (the shared chat's read
  card asks first for a PDF or image some of its people cannot open; `output` is in WRITE_TARGET_ARGS, so it counts
  only when something is there), ROOM_FILE_TOOLS (after a room read, the room card), the confidential chat's local
  tools and the guest tools (a guest's folder rules apply). `image` joined PATH_ARGS (read scope, shared steps).
- **Checking the placement:** there was a page-preview path already: `read` with `pages` and `as_images: true` shows a
  page as an image (files/service.ts readPdf). The tool's result tells the AI to look at the stamped page that way
  before it answers, and to stamp again with `output` set to the stamped copy (which then gets a new version instead of
  another file) when it landed wrong.
- **Not added:** stamping several pages in one call, changing a PDF's text, a card before stamping (it only adds a new
  file the person can delete).
