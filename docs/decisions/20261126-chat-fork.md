# "Continue in a chat only you see" forks the shared chat: the conversation comes along, only for me

- Date: 2026-11-26
- Status: accepted
- Supersedes: the empty "Only me" chat with my last question in its box ([Team project chats shared by default](../DECISIONS.md))
- Branch: feat/chat-fork (the owner, 2026-11-26; plan [20261126-0813-chat-fork](../AGENTS/plan/20261126-0813-chat-fork.md))

- **Ask:** people ask whether a shared chat can be "forked". The shared chat's title menu item "나만 보는 채팅에서 이어
  하기" / "Continue in a chat only you see" opened an empty private chat with my last question typed in the box: nothing
  else came along, so the person explained everything again and the AI did its work again. The AI itself sends people
  there when they ask for something personal in a shared chat.
- **Owner's answers (all three recommendations):**
  1. **Entry point:** only that item, in shared chats. It forks from the end of my branch, like Claude Code's
     `/branch`. No item per answer, nothing new in private chats.
  2. **What is copied:** what I see now, as I see it: other people's names stay, an answer hidden from me is one line,
     another person's step notes only as far as the shared chat gives them to me today. Later edits or deletes in the
     original do not follow.
  3. **Personal tools in a fork that holds other people's copied words:** they ask with the normal card, and my own
     "Always allow" ends the asking, as in any chat of mine. Memory saving and the guards on outside addresses stay as
     they are (the copied `others_words` and taint marks).
- **Rule:**
  - `POST /api/chats/:id/fork` (server/src/chat/fork.ts) makes a 🔒 chat only I see, in the original's project (a chat
    shared with people: outside projects), named as the original. The original is not changed, nobody is told, and
    nobody else ever sees the fork. Audited (`chat.fork`).
  - The copy: the finished messages of the branch on screen, as `ChatStore.toMessage` shows them to me with the shared
    chat's view; a hidden answer as a row with `messages.withheld_copy = 1` and nothing of it (chat/shared-answers.ts
    keeps it hidden for good); a turns row per answer with its original runner and no usage; each answer's record with
    `left_out` mapped; the read scope and the marks as they are; another person's notes filtered by
    `othersNotesFor` (the file tools, paths everyone there may list; none for an answer some there may not see or from
    before the share). A chat file is a reference (`Attachment.fromChat`): it opens through the fork's own routes, by
    the shared chat's rule for me now, read-only; the AI's `chat:files/` sees it the same way.
  - The engine: after the commit my own Claude Code session of that branch (chat/shared.ts `ownSessionOn`) is copied
    into the fork's session folder and pointed at like any chat's, so every cleanup (an access change's reset, a new
    first message) covers it. The fork's first answer (`chats.fork_pending`) resumes it once with plain `--resume`,
    with the since-block of what others wrote after my last answer, a `<chat_copy>` line that says this is now my own
    chat and which tools are here, and my full skill list (recorded for the session). Its checks are for me alone (the
    leak check, what the session holds and what the chat read: may I still open it), never the original's audience:
    someone who joins the original does not drop my fork's session. Codex, the API engine, no session of mine, or a
    check that fails: a fresh start from the copied words (with the summary when they do not fit).
  - A guest gets the item only in their own project's chat and while they have AI; the route says `403 fork_guest`
    otherwise. Refused too: a chat of one person (`fork_not_shared`), safe operations (`safe_ops`), a side chat or a
    scheduled run (`fork_not_here`), and nothing finished on the branch yet (`fork_nothing`).
  - The fork shows one quiet line above its messages, "‘‹title›’에서 이어 왔어요" / "Continued from “‹title›”", a link while
    I may open the original (its title then), plain text otherwise. Questions show who asked (other people's are
    there). The box opens empty.
  - The AI's wording (chat/prompt.ts): the item "opens a chat only you see with this conversation so far", never "with
    the question already in the box".
- **Why:** a fork copies what the person already saw into a separate chat of theirs and leaves the original alone
  (Claude Code `/branch` and `--fork-session`, ChatGPT's shared-link continue and group-chat copy). The words are ones I
  see and could copy by hand; Claude Code is the floor and has no such limit; Rule A says the person's own Always is
  final.
- **Left out:** an item per answer ("Branch in new chat") and forks of private chats (decision 1; `--resume-session-at`
  stays an option); copying files (nobody does); pins, mute, threads, schedules, the people, open cards; the original
  showing that a fork exists.
- **Tests:** tests/unit/b-chat-fork.test.ts; web/test/e2e/chat-fork.spec.ts (1440 and 390, light and dark);
  web/test/e2e/shared-project-chats.spec.ts.
- **Version impact:** minor (a new user-visible feature, one new API route, one additive migration 457; older clients
  get 404 and keep the old box).
