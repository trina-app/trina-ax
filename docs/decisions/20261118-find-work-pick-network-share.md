# "Choose a folder…" takes a NAS or network share on Windows

- Date: 2026-11-18
- Status: accepted
- Supersedes: none. Narrows one rule of [Find work files on this computer, part 1](../DECISIONS.md#find-work-files-on-this-computer-part-1-the-desktop-app-looks-the-page-never-names-a-path-featfind-work-files-2026-11-15) (a Windows network path counted as the home folder)
- Branch: fix/find-work-pick-network-share (the manager, QA TC-4813)

- **Ask:** on Windows, "Choose a folder…" in find work files gave `cancelled` within milliseconds for `\\localhost\TrinaQAShare\Team` and for the mapped drive `Z:\Team`. `opensHome` (`desktop/src/common/folder-access.ts`) counted every network path as home, and Node's realpath turns a mapped drive into one, so the share code (one call at a time) was never reached. The manager: picking a NAS or network share folder must work; that is the point of the share path.
- **Rule:** `opensHome(path, sys, platform, { shares: true })` is used only for the person's own pick in "Choose a folder…" and that folder's walk (`desktop/src/main/work-files.ts` `pickFolder`, `look` with `picked`). There a network path goes through the same name and identity checks as a local one. Still refused, as written and after realpath, before anything else is asked (`refusedShare`): device paths (`\\?\…`, `\\.\…`), the admin shares `X$`, `ADMIN$`, `IPC$`, `PRINT$` (trailing dots and spaces ignored), WSL's `\\wsl$` and `\\wsl.localhost`, and a path with no share name. A home on a network path still refuses everything.
- **Shares under a name of their own** (`shareLeadsAside`, independent review): the server resolves its own links, so realpath keeps the share's names. The pick and every folder above it up to the share's top are compared by identity with Windows, System32, the program folders, ProgramData, the recycle bin and recovery folders, the person's AppData (and Roaming, Local, LocalLow), the system's own names for these (`FolderSystem.systemFolders`: `%SystemRoot%`, `%ProgramFiles%`, `%APPDATA%` …), and the folder that holds home (`C:\Users`: below it only the person's own folder or Public). A folder of the chain whose identity cannot be told (0, an error, too slow) refuses.
- **`pickRefused`** (`desktop/src/common/work-files.ts`) counts a share from below its share name, as a drive from below its letter, so a share of a drive's top keeps the Windows, Program Files and other people's Users rules; the server's name is not checked as a folder name.
- **Unchanged:** the team page's folder window (`FolderGrants`), the three folders' look, the wide look and "Choose it yourself" keep refusing every network path without asking the network (a path from a recent list could make the app sign in to someone else's server). macOS and Linux are unchanged. A share is walked one call at a time (`serial`: the real path starts with `\\` or is not on a fixed drive).
- **Links inside the walk (TC-4844, review follow-up):** the walk already never entered what lstat reads as a link or junction. libuv's lstat follows a reparse point it cannot read as one (a volume mounted in a folder, a OneDrive folder, an unknown tag, a junction whose data a share does not give) and calls it a folder. Such a folder (the listing marks it as a reparse point, lstat says folder) is never entered on a network share (`scanRoots`: the root's real path is a network path), and on a local drive only when its real path is its own path (a OneDrive folder; not a mounted volume or a junction written as a volume or GLOBALROOT target, under which a read is refused anyway) and its identity is none of `guardedIdentities` (`desktop/src/common/folder-access.ts`: home and every folder above it, the guarded system folders); when those cannot be told (no guard, a failed or late lookup, an identity of 0) it is not entered. On a share, every folder below its top is also asked its identity with links followed (`WorkFs.identity`, fs.stat) before it is read, and is entered only when that is none of `guardedIdentities` (a junction the server resolves itself may show as a plain folder); one that cannot be told is not entered, and one that does not answer in time ends the walk (cut). The identity is asked again after the listing, and a listing whose folder changed meanwhile is dropped. This costs two calls per folder on a share. Consequences (independent review): DFS links under a picked namespace root are reparse points and are not entered (a DFS link picked itself still works); a NAS that gives file number 0 gives only its top folder (reads refuse number 0 on Windows anyway); when home or a folder above it cannot be told, no OneDrive folder below a walked root is entered. Still left: a share hosted on this computer with a junction, resolved by the server, into a folder below home that is not guarded (inside AppData): its identity is no guarded one and its files keep the share's path, so they can be listed and read; refusing shares on this computer's own volumes would close it but also refuse `\\localhost` shares (QA TC-4813), so it is left to the owner.
- **Left out (accepted):** a junction on a share made to lead deeper into one of the guarded folders (`AppData\Roaming\Microsoft`) or into another person's profile is not caught; it takes the person's own setup, and Windows' permissions keep other profiles. The identity check over SMB was simulated in unit tests; a check on the Windows QA PC is in the QA row.
- **Main thread:** Windows' fixed drives (one PowerShell start) are kept for 5 minutes (`windowsFixedDrives`), so "Choose a folder…" no longer starts a process each time. The other PowerShell runs of the wide look (Windows Search, Office's list, OneDrive's roots) are asynchronous already; each start is still a process start on the main thread. Moving them to a utility process is left for later.
- **Tests:** `tests/unit/e-desktop-folder-window.test.ts` (shares allowed, mapped drive, admin shares, device paths, WSL, shares of the profile, Users, a drive's top and system folders under names of their own, junctions to home, nothing asked of the network for a refused path, TC-4846's other spellings, `guardedIdentities`), `tests/unit/e-desktop-work-files.test.ts` (`pickRefused` on shares, the bridge's source pins, TC-4844's reparse points in a share walk and a local one).
