# Auto mode: Trina approves its own safe cards and asks only on the floor

- Date: 2026-11-25
- Status: accepted
- Supersedes: none (it adds to [20261123-one-always-allow.md](20261123-one-always-allow.md) and
  [20261123-do-then-undo.md](20261123-do-then-undo.md); "Left out" of do-then-undo named auto mode as later work)
- Branch: feat/auto-mode (Dion, 2026-11-23: "auto mode", fewer permission cards with a mode switch as in Claude Code;
  accepted 2026-11-25). Plan: [20261123-0420-auto-mode.md](../AGENTS/plan/20261123-0420-auto-mode.md)

- **Ask:** Dion asked for an auto mode like Claude Code's: Trina approves its own safe permission cards, and the person
  sees a card only where it matters. Many cards train people to press "allow" without reading; fewer, sharper cards are
  safer.
- **Rule, what auto mode approves:** a card kind marked `auto` or `auto-if` in `AUTO_KINDS`
  (`shared/src/api/ai-allowances.ts`) and in the `auto` column of [ASKS.md](../ASKS.md) "Kinds".
  - `auto`: `big_download` (a file over 1 GB to the person's own disk) and `bulk_files` (keep many new files in the
    project folder; the card's own "move to work folder" is the undo).
  - `auto-if`: `save_wider` (only when every source is the person's own file in their own folder and nobody who can
    read the target is a guest), `move_files` (only the person's own files, nobody loses access, no guest at the
    target, no room read; a bulk rename only without a room read), `skill_files` (only skills in the person's own
    folder or personal level, where nobody gains, loses or may newly change one). The tool computes this floor once and
    passes it as `{ floorFree }`; a missing value shows the card.
  - An `auto-if` kind also needs a chat that read nothing of other people (other authors, rooms, quotes) and nothing
    from outside (`session_tainted`, `others_words`: a site, a connection, the browser, a file someone else wrote).
- **Rule, what always asks (the floor):** every other kind: sends and shares (`post_to_room`, `post_files`,
  `share_files`, `share_folder`), access (`folder_access`, `project_members`), costs (`video`), deletes
  (`delete_files`), sign-ins (`dev_login`), other people's AI (`skill_save`), memory after outside content
  (`remember`), rooms (`room_change`), shared chats (`shared_read`, `shared_save`); and every request or allowance
  card (web addresses, dev environment sites, connectors, connect cards, the office network). The registry test fails
  when a kind with an `irreversible` or `cost` entry is not `ask`, when a `sends-to-others` kind is plain `auto`, or
  when a non-`always:` kind is marked `auto` or `auto-if`.
- **Rule, where:** only in a turn the person watches from their own app (web, desktop, phone). Never in a scheduled
  run (D3: only the person's own Always holds there), a Slack turn, a draft or other restricted turn, a confidential
  chat, or a turn with a guest among the people. A shared chat with no guest follows the same rules (D5).
- **Rule, precedence:** the person's own Always first (Rule A), then auto mode, then the card. Auto mode never writes
  or reads `card_always_allow`. Turning it off brings every card back at once.
- **Rule, settings:** one person value (`users.auto_mode`: on, off, or the team default) and one team value
  (Admin › Team AI settings `autoMode`: `off`, `allowed`, `default`). **The team default is `off`** (D4), so nothing
  changes until an admin allows it. The team's "Always allow" switch off turns auto mode off too. A guest never has it.
  The composer shows an Ask / Auto pill while the person may use it; the first tap that turns it on shows one sheet
  (what it does, what always asks, undo). Settings › 트리나에게 허용한 것 has the switch and the last 50 approvals.
- **Rule, record:** one audit row per approved card (`ai.auto_allow` with kind, chat, turn, rule), per change of the
  person's value (`ai.auto_mode`) and per change of the team value (`admin.auto_mode`). Each approval leaves a step in
  the answer ("Done in auto mode: …") and the tool result tells the AI it ran under auto mode, so it never says the
  person approved.
- **Rule, pause:** after 20 approvals in one chat in 24 hours (counted from the audit rows), the cards come back in
  that chat with one step "Auto mode paused".
- **D1, delete to the trash: always asks.** The plan proposed auto for the person's own folder. The task brief says
  auto mode never approves an irreversible or destructive action, and the registry marks `files.delete` irreversible,
  so the stricter rule wins. The person's own Always for `delete_files` still works (Rule A).
- **Why not Claude Code's own auto mode:** Trina runs the engine with `--permission-mode dontAsk` and raises its own
  cards. Claude Code's auto mode does not know Trina's floor, adds a model call per tool call, and the Codex engine
  does not have it. Trina's auto mode works in Trina's tools, for every engine.
- **Left out (later, each needs its own review):** web addresses (`site.web`), dev environment sites (`dev.site`) and
  connector reads or own writes (`conn.read.unsure`, `conn.write.own`). The plan marked them `auto-if`, but each one
  can carry data out of the person's environment (a short query or path is enough), which the brief puts on the floor.
  They stay `ask` until a classifier (plan phase 5) or a fixed host list has its own security review. The "3 undone
  in a row" fallback is also left out: the server cannot tell reliably that a person undid an auto step. Only the
  20-a-day pause is built.
- **Tests:** `tests/unit/b-auto-mode.test.ts` (settings, places, floor kinds, precedence, audit, pause, API, real
  answers: a safe copy goes without its card and is audited, a floor card asks, the team value off brings the card
  back); `tests/unit/ask-registry.test.ts` (the `auto` column).
- **Version impact:** minor. One person setting, one team setting, three audit actions, one registry column; nothing
  is removed and the default changes nothing.
