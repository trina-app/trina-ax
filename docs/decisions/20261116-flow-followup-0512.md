# No loose-file note for a new file made beside a file of its kind the AI read there

- Date: 2026-11-16
- Status: accepted
- Supersedes: none (narrows the loose-file note further, after
  [20261116-flow-regressions-0512-no-unasked-moves.md](20261116-flow-regressions-0512-no-unasked-moves.md))
- Branch: fix/flow-followup-0512 (AI flow rerun on dev 552bcfd56, FL-15 always mode, QA TC-4412)

- **Ask:** after #1162, FL-15 in always mode still regrouped files: the AI read the team's deck in groups/마케팅/, made
  a new 3-slide deck next to it (content, no `source`), got the server's loose-file note, and in the next turn made a
  "발표자료" folder and moved the deck there; the PDF then followed into it. Nobody asked for a folder.
- **Why:** #1162 skipped the note only for make_file's `source`. A deck made from what the AI read has no `source`, so the
  note still fired, and the AI acted on it a turn later (the "move only this file" line did not stop that move).
- **Rule:** no note for a new file saved in the same folder as a file of the same kind (extension) that this turn read,
  other than files the turn itself made and still there: the new file follows the folder's own way. "Read" is a file
  whose content went to the AI (the answer's source list), not the hash an edit or a write leaves. Other kinds, and
  files saved where the turn read nothing of their kind, keep the note. A read for context alone counts too (reading
  shared/회의록.md, then writing shared/요약.md: no note), and so does a template the AI read there: the folder already
  keeps such files loose, which is what the note is about.
- **Left out:** a guard on move_files by the person's words. "일정 슬라이드를 2번째로 옮겨줘" (move a slide) has the same
  verb as moving a file, so a word check would let this move through and refuse real ones; removing the note that
  started it is cheaper and exact.
- **Tests:** tests/unit/b-chat-file-placement.test.ts ("a new file beside a file of the same kind the turn read there
  gets none"); tests/unit/b-side-chat.test.ts (the Everyone room saves in shared/).
- **Version impact:** patch.
