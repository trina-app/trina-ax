# The AI gets a short map of the app's screens, with the labels the person sees

- Date: 2026-11-16
- Status: accepted
- Supersedes: none
- Branch: feat/ai-app-map (AI scenario check, first run 2026-11-16, root cause #2)

Plan: docs/AGENTS/plan/20261116-0506-ai-app-map.md.

- **Ask:** asked "where do I …" or "can I …", the AI hedged ("if there is such a setting"), sent people to an admin, or
  said a feature did not exist: room apps, Always allow, the Trina AX MCP, guest AI, usage and limits, the activity
  log, the time zone, voice input, notifications, the apps and the version, System, chat rename and folders, handover,
  find work files, ready-made skills, bringing one's own skills, AI providers and the model, the dev environment
  (about 15 of 104 cases).
- **Rule:** every turn's instructions carry "Where things are in the app" (server/src/chat/app-map.ts), one line per
  place, about 19 lines. Places are named by the labels the person's app shows, in their language, from the web app's
  i18n keys; English sentences around them. No help tool: the whole map fits in the target (about 600 tokens in
  Korean), and a tool the AI has to think of calling would miss the hedging cases, which are exactly the ones where it
  does not know there is something to look up.
- **No drift:** the labels' words are generated from web/src/i18n into app-map-labels.ts (`bun
  scripts/app-map-labels.ts`); tests/unit/ai-app-map.test.ts fails when that file is not current, when a key is gone
  from a dictionary or no longer used by the app, and when a Settings tab, Admin page, Team settings group, System group
  or route the map names is gone or has another label.
- **Who gets which form:**
  - the owner or an admin, in their own chat: every Admin page line;
  - a member, in their own chat: one line, "the owner or an admin does this in Admin: …" (the situation block already
    says never to send a member to an Admin page);
  - a shared chat: the Admin lines headed "owners and admins only", the same for everyone, so the map says nothing
    about the asker's role (SHARED_PROMPT_SECTIONS `appMap: true`);
  - a guest: no map (none of the team's screens are theirs; the guest section says what they can do).
- **Install facts:** guest AI choices only where the AI runs on the team's AI connections (the same check as the guest
  gate in turn.ts); otherwise "Guest AI: none on this install". The dev environment line only where the server has it
  (MYCEL_DEV_ENV); otherwise "No dev environment on this install". The find-work-files line says "desktop app only".
  The phone's Me tab stays in the situation block.
- **Left out:** the no-jargon rule (#1057); the map is in the instructions only, not in the per-turn context, so a
  session started before this gets it at its next fresh start; screens inside a page beyond one level (each tab of
  Usage, each Plugins row).
- **Version impact:** patch (the AI's answers change; no screen, API or data change).
