# 기획: 에이전트 게이트웨이 — 맥 미니를 "권한을 아는 팀 자료 서버"로

상태: 초안 (2026-10-22). 아이디어는 플러스, 정리는 Claude. 결정이 필요한 것은 맨 아래 "정할 것".

## 한 줄

**맥 미니는 팀 자료를 지키는 서버가 되고, AI는 누구 것이든 밖에서 사람별 열쇠로 들어온다.** 서버는 그 사람이 볼 수 있는
만큼만 보여 주고, 쓸 수 있는 만큼만 쓰게 한다. AI 엔진을 맥 미니 안에서 돌리는 것은 기본이 아니라 선택이 된다.

## 1. 왜 바꾸나

지금 Team AX가 하는 일은 두 가지가 섞여 있다.

| | 하는 일 | 상태 |
|---|---|---|
| A. 팀 자료와 권한 | 파일, 폴더 규칙, 그룹·프로젝트, 버전, 휴지통, 검색(글자·의미), OCR, 감사 기록, 공유 범위 확인 | 단단함. 보안 시험 1166개, 공격 감사 4차 |
| B. AI 엔진 운영 | 맥 미니에서 Claude Code·Codex를 띄우고, 샌드박스·전용 계정·방화벽·모델 프록시·구독 토큰으로 가둠 | 계속 깨짐 |

진짜 목표는 A다: **"어떤 에이전트가 들어오면, 그 사람 권한만큼만 보게 한다."** B는 그걸 이루려고 택한 수단이었다.

B의 비용:
- 2026-10-22 staging 하루에 정식 설치 전용 버그 5개가 모두 B에서 나왔다(샌드박스 경로, Codex 로그인, 토큰 갱신, 기본 모델
  Sonnet, bootstrap 종료). Claude Code·Codex가 버전업할 때마다 잠금 회귀 시험을 다시 통과해야 한다.
- 맥 미니 한 대가 팀 전체 AI를 돌린다(동시 3턴, 16 GB). 사람이 늘면 바로 병목.
- owner 구독 하나를 팀 전체가 나눠 쓰는 구조는 약관상 회색 지대다(확인 필요, 아래 7절).
- 쓰는 AI가 Claude Code·Codex로 묶인다. 사람들은 이미 claude.ai, ChatGPT, Claude Desktop, 노트북의 Claude Code를 쓴다.

## 2. 무엇이 되나

```
 claude.ai · Claude Desktop · ChatGPT · 노트북 Claude Code · Codex · 사내 자동화 · (기존) Team AX 채팅 화면
        │ 사람별 열쇠 (OAuth / 개인 토큰)
        ▼
 ┌─────────── 에이전트 입구 (새로 만듦) ───────────┐
 │ 원격 MCP (Streamable HTTP)  ·  REST API  ·  CLI │
 └──────────────────────┬──────────────────────────┘
                        ▼
 ┌──────── 권한 함수 하나 (지금 그대로: server/src/policy) ────────┐
 │ 파일 · 폴더 규칙 · 그룹 · 프로젝트 · 버전 · 휴지통 · 검색 · OCR │
 │ 감사 기록 · 공유 범위 확인(read-scope) · 팀 스킬                │
 │ + 그래프 (새로: 문서·사람·프로젝트·고객 사이의 관계)              │
 └─────────────────────────────────────────────────────────────────┘
         맥 미니 (사무실 안, 자료는 밖으로 안 나감)
```

공개 주소는 이미 있는 relay(`https://<팀>.treesoop.com`) 또는 Cloudflare 터널을 쓴다. 포트를 열지 않는다.

## 3. 누가 어떻게 쓰나

| 사람 | 쓰는 것 | 예 |
|---|---|---|
| 파워유저(개발자, 기획자) | 자기 AI에 "팀 자료" 커넥터 추가 | claude.ai에서 "지난달 견적서 중 A사 것 비교해 줘" → 그 사람이 볼 수 있는 견적서만 |
| 일반 직원(치과 데스크 등) | 지금 Team AX 채팅 화면 (설치·설정 없음) | 그대로. 뒤에서 같은 입구를 씀 |
| 관리자 | 웹 관리 화면 | 누가 어떤 AI로 무엇을 읽고 썼는지, 열쇠 끊기, 폴더 규칙 |
| 자동화(서비스 계정) | 토큰 + REST/CLI | 매일 밤 매출 정리를 `reports/`에 쓰기. 사람 아닌 계정, 그룹처럼 권한을 줌 |

## 4. 구성 요소

### 4.1 에이전트 입구
- **원격 MCP 서버**: 지금 엔진에 주는 팀 도구(list, glob, grep, read, write, edit, search, make_file, share_file,
  remember …)를 그대로 HTTP로 연다. 지금은 엔진→bridge→gate→tools.sock 경로로만 들어온다(`server/src/mcp/`).
  같은 처리기(handler)와 같은 권한 함수를 쓰므로 권한 규칙을 새로 만들지 않는다.
- **REST API**: 이미 웹 화면이 쓰는 `/api/files/*` 등. 토큰 인증(`Authorization: Bearer`)도 이미 있다
  (`server/src/auth/service.ts`). 공개 문서와 버전 정책만 붙이면 된다.
- **CLI** (`ax`): `ax ls`, `ax cat`, `ax grep`, `ax put`, `ax search`. 노트북의 Claude Code·Codex가 셸에서 쓰기 좋다.
  REST를 감싼 얇은 프로그램.

### 4.2 신원: "누구로서" 들어오나
- **사람별 OAuth 2.1** (MCP 원격 서버의 표준 방식): claude.ai·ChatGPT에서 커넥터를 추가하면 팀 로그인 화면이 뜨고,
  로그인한 사람의 권한이 그 연결에 붙는다.
- **개인 접근 토큰**: CLI·스크립트용. 설정 화면에서 만들고, 이름("노트북 Claude Code"), 만료, 범위를 정한다.
- **범위 줄이기**: 토큰마다 "읽기만", "이 폴더만", "30일" 같은 제한을 둘 수 있다. 사람 권한보다 넓어지는 일은 없다
  (교집합).
- **서비스 계정**: 사람이 아닌 계정. 관리자가 그룹·폴더 규칙으로 권한을 준다.

### 4.3 안전장치 (지금 것을 입구로 옮김)
- **공유 범위가 넓어지는 쓰기**: 그룹 자료를 읽은 연결이 `shared/`에 쓰려 하면, 지금은 채팅 안 확인 카드로 묻는다.
  밖의 AI에는 카드를 띄울 수 없으므로, MCP는 "확인 필요"로 답하고 **사람이 웹·앱 알림에서 승인**한다(승인 링크).
  read-scope 계산(`server/src/chat/read-scope.ts`)은 채팅 대신 "연결(세션)" 단위로 바꾼다.
- **팀 스킬(`skills/`) 변경**: 지금처럼 사람 확인 + 관리자 알림.
- **감사 기록**: 어느 사람이, 어느 AI(연결 이름)로, 무엇을 읽고 썼는지. 관리자 화면에 연결별로.
- **열쇠 끊기**: 사람 퇴사·노트북 분실 때 관리자가 그 사람의 연결 전부를 즉시 끊는다.

### 4.4 그래프 (새 투자, 차별점)
구글 드라이브는 파일을 쌓기만 하고 파일 사이의 관계를 모른다. 우리는 안다.
- **노드**: 문서, 사람, 프로젝트, 고객(회사), 주제.
- **관계**: 링크·언급(문서 안의 경로, 사람 이름, 고객 이름), 파생("이 견적서는 저 계약서에서"), 같은 프로젝트,
  같은 고객, 버전.
- **처음(v1)은 자동 추출만**: 문서 안의 팀 경로 링크, 사람 이름, 프로젝트 폴더, 고객 이름 사전. 무거운 LLM 추출은 나중.
- **권한을 아는 그래프 질의**: "A사와 관련된 문서" → 그 사람이 볼 수 있는 노드만. 볼 수 없는 문서는 **관계도 안 보인다**
  (볼 수 없는 문서가 있다는 사실조차 새지 않게: 지금 "없음 = 권한 없음" 원칙 그대로).
- 도구: `related(path)`, `graph_search(entity)`, `timeline(project)`.

### 4.5 지금 채팅 화면
버리지 않는다. 같은 입구를 쓰는 **우리 클라이언트**가 된다. 맥 미니에서 엔진을 돌리는 방식(B)은
"구독 하나로 팀 전체" 옵션으로 남긴다. 다만 새 기능은 입구(A) 기준으로 만든다.

## 5. 지금 것 중 무엇을 쓰나

| 그대로 씀 | 바꿔서 씀 | 선택 사항이 됨 |
|---|---|---|
| 권한 함수, 파일 서비스, 버전·휴지통, 검색(grep·의미 검색), OCR, 문서 변환, 감사 기록, 사용자·그룹·프로젝트, 폴더 규칙 화면, relay·터널, 업데이트, 설치 | MCP 서버(소켓 → HTTP + OAuth), read-scope(채팅 → 연결), 확인 카드(채팅 안 → 승인 링크), 토큰(세션 → 이름 있는 개인 토큰) | 엔진 잠금, `_axagent`·샌드박스·방화벽, 모델 프록시, 구독 토큰, Codex 로그인, launcher |

대략 **70%는 그대로**, 입구와 신원이 새로 만들 부분, 그래프가 새 투자다.

## 6. 보안이 어떻게 달라지나

- **좋아지는 것**: 엔진이 맥 미니 안에서 도는 일이 없으면 "엔진이 도구를 우회하는" 위협 자체가 사라진다. 서버에 닿는 길은
  입구 하나이고, 권한 확인은 원래 거기서 한다.
- **새로 생기는 것**
  1. **바깥 AI가 자료를 다른 데로 옮김**: 그 사람이 볼 수 있는 자료가 그 AI의 다른 도구(웹, 메일)를 통해 나갈 수 있다.
     사람이 직접 복사하는 것과 같은 수준. 대응: 감사 기록, 토큰 범위 줄이기, 대량 읽기 경보.
  2. **토큰 도난**: 짧은 만료 + 갱신(OAuth), 개인 토큰은 해시만 저장(지금 세션과 같음), 연결별 끊기, 이상 접속 알림.
  3. **문서 속 숨은 지시(prompt injection)**: 지금은 엔진의 다른 도구를 우리가 껐지만, 바깥 AI는 우리가 못 끈다. 그래서
     "더 넓은 곳에 쓰기 = 사람 승인"이 더 중요해진다(4.3).
  4. **공개 주소**: relay/터널 뒤, 로그인 속도 제한(있음), 입구에도 속도 제한.
- 보안 시험(`tests/security`)을 입구에도 그대로 돌린다: 역할별로 MCP·REST·CLI를 두드리는 권한 시험.

## 7. 사업 측면

- **요금 구조가 바뀐다**: 지금은 "owner 구독 하나로 팀 전체". 새 방식에선 사람마다 자기 AI 구독이 필요하다(치과 데스크
  10명이면 큰 차이). 그래서 **두 가지를 같이** 판다:
  - 기본: 팀 자료 서버 + 우리 채팅 화면(엔진 포함, 지금처럼)
  - 추가: "어떤 AI든 연결" (파워유저, 개발 조직)
- **약관**: 구독 하나를 여러 사람이 나눠 쓰는 지금 방식이 Anthropic·OpenAI 약관에 맞는지 확인 필요. 새 방식은 각자 자기
  구독이라 이 문제가 없다.
- **경쟁**: Glean(권한을 아는 사내 검색·에이전트), Box AI, Notion AI·MCP, Google Drive·Microsoft 365 커넥터. 우리 차별점:
  1. **사무실 안 상자**: 자료가 클라우드에 안 올라간다(병원, 세무, 법무에 강점).
  2. **그래프**: 파일 사이 관계를 권한대로.
  3. **작은 팀용 설치**: 맥 미니 하나, 30분.

0단계는 결정 전에 해도 손해가 없다: 기존 구조를 건드리지 않고 입구만 하나 더 여는 실험이다.

## 9. 정할 것

1. **요금**: 두 가지를 같이 팔까, 새 방식으로 옮겨 갈까?
2. **엔진 호스팅(B)**: 유지(지금 고객용), 동결(버그만 고침), 정리(새 고객은 바깥 AI만) 중 무엇?
3. **첫 바깥 AI**: claude.ai 커넥터, Claude Code(CLI·MCP), ChatGPT 중 무엇부터? (제안: Claude Code → claude.ai → ChatGPT)
4. **그래프 범위**: v1에 "고객" 노드를 넣을까? (업종마다 고객 사전이 필요)
5. **공개 주소**: relay(우리 서버 경유, 트래픽 최소화 원칙과 충돌) vs 고객별 Cloudflare 터널.
6. **이름**: 제품 설명을 "팀 AI 작업 공간"에서 "팀 자료를 AI에게 안전하게"로 바꿀지.

### 제안 (Claude, 2026-10-22)

1. **요금: 둘 다 팔되, 기본은 지금 상품.** 비개발 소규모 팀(치과 등)은 우리 채팅 화면이 본체다. "어떤 AI든 연결"은 위 등급
   (파워유저·개발 조직)으로. 옮겨 가는 결정은 MVP 시범 뒤에.
2. **엔진 호스팅: 동결.** 버그만 고치고 새 기능은 넣지 않는다. 길게는 우리 채팅의 기본 엔진을 **API 엔진**
   (`server/src/engine/api-agent.ts`, 서버 안의 우리 루프, 같은 도구·같은 권한 함수)으로 바꾼다. Claude Code 프로세스가 없으니
   샌드박스·전용 계정·방화벽·구독 프록시가 필요 없고, 팀의 API 키로 쓰니 약관 문제도 없다. 대신 요금이 사용량 기준이 되므로
   시범 팀 하나에서 한 달 사용량으로 비용을 먼저 잰다. 구독 공유 방식은 지금 고객에게만 남긴다.
3. **첫 바깥 AI: Claude Code.** 우리가 매일 쓰고, HTTP MCP에 토큰 헤더만 붙이면 되어(OAuth 없이) 0단계 실험이 가장 빠르다.
   그다음 claude.ai(OAuth와 공개 주소 필요), 그다음 ChatGPT.
4. **그래프 v1: 고객은 빼고 문서·사람·프로젝트·그룹만.** 이미 DB에 구조로 있는 것(사용자, 그룹, 프로젝트 폴더)과 문서 안
   링크·이름 언급만으로 시작한다. 고객 노드는 v2에서, 관리자가 고치는 팀별 사전으로.
5. **공개 주소: 고객별 Cloudflare 터널이 기본**(트래픽이 우리 서버를 거치지 않음, 예시팀에서 이미 씀). 도메인이 없는 팀만 relay.
6. **이름: 지금은 바꾸지 않는다.** MVP 시범 반응을 보고 정한다. 소개 문구 둘째 줄로 "팀 자료를 AI에게 안전하게"를 시험해 본다.

**바로 할 순서**: ① 0단계 실험(Claude Code + 개인 토큰 + staging 권한 시험) ② 약관 확인(구독 공유, 커넥터 조건) ③ 시범 팀
1곳 고르기(치과 말고, 파워유저 2명 이상 있는 곳) ④ API 엔진으로 우리 채팅 한 달 비용 재기.
