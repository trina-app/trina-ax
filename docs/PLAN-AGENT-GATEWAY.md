# 기획: 에이전트 게이트웨이 — 맥 미니를 "권한을 아는 팀 자료 서버"로

상태: 초안 2판 (2026-10-22). 아이디어는 플러스, 정리는 Claude. 경쟁 조사:
`~/src/research/reports/AI 에이전트 자료 서버 경쟁사.md`, 셸 조사: 같은 폴더 `research_notes/…/permissioned_shell.md`.

## 한 줄

**맥 미니는 팀 자료를 지키는 서버가 되고, AI는 누구 것이든 밖에서 사람별 열쇠로 들어온다. 들어온 AI는 Claude Code가 터미널에서
하던 그대로(`ls`, `grep`, `cat`, 파이프, `sed`…) 팀 자료를 다루지만, 그 사람이 볼 수 있는 파일만 존재한다.**

구글 드라이브·Box·노션도 권한은 있다. 하지만 AI에게 주는 것은 "검색"과 "파일 하나 읽기"뿐이다. Claude가 일 잘하는 방식(폴더를
훑고, grep으로 좁히고, 여러 파일을 엮어 고치는 것)은 못 한다. 그걸 권한대로 해 주는 제품은 2026-10 조사에서 찾지 못했다.

## 1. 왜 바꾸나

지금 Team AX가 하는 일은 두 가지가 섞여 있다.

| | 하는 일 | 상태 |
|---|---|---|
| A. 팀 자료와 권한 | 파일, 폴더 규칙, 그룹·프로젝트, 버전, 휴지통, 검색(글자·의미), OCR, 감사 기록, 공유 범위 확인 | 단단함. 보안 시험 1166개, 공격 감사 4차 |
| B. AI 엔진 운영 | 맥 미니에서 Claude Code·Codex를 띄우고, 샌드박스·전용 계정·방화벽·모델 프록시·구독 토큰으로 가둠 | 계속 깨짐 |

진짜 목표는 A다: **"어떤 에이전트가 들어오면, 그 사람 권한만큼만 보고 쓰게 한다."** B는 그걸 이루려고 택한 수단이었다.

B의 비용:
- 2026-10-22 staging 하루에 정식 설치 전용 버그 5개가 모두 B에서 나왔다(샌드박스 경로, Codex 로그인, 토큰 갱신, 기본 모델
  Sonnet, bootstrap 종료). Claude Code·Codex가 버전업할 때마다 잠금 회귀 시험을 다시 통과해야 한다.
- 맥 미니 한 대가 팀 전체 AI를 돌린다(동시 3턴, 16 GB). 사람이 늘면 바로 병목.
- owner 구독 하나를 팀 전체가 나눠 쓰는 구조는 약관상 회색 지대다(확인 필요, 7절).
- 쓰는 AI가 Claude Code·Codex로 묶인다. 사람들은 이미 claude.ai, ChatGPT, 노트북의 Claude Code를 쓴다.

## 2. 시장에서 이미 흔한 것과 비어 있는 것 (2026-10 조사)

**이미 흔하다 (차별점 아님, 하지만 없으면 안 됨)**
- 원격 MCP + 사람별 OAuth: Glean, Box, Dropbox Dash, Google Workspace, Microsoft Work IQ, Notion, Egnyte, Onyx 모두 있음.
- "AI는 그 사람이 볼 수 있는 것만": 모두 기본.
- 로그인·게이트웨이 부품: Auth0, WorkOS, Stytch, Keycloak, Pomerium, Cloudflare. **신원 시스템을 깊게 직접 만들지 않는다.**

**비어 있다 (우리 차별점)**
1. **권한 걸린 셸.** 팀 자료 위에서 사람별로 걸러진 `ls/grep/cat/파이프`를 어떤 AI에서나. 가장 가까운 것: Mintlify(자기
   문서 어시스턴트 안의 읽기 전용 가상 파일시스템, 판매 안 함), Glean Agent Sandbox(대기업용, 자료가 파일로 깔리지 않음),
   각자 노트북에 드라이브 동기화(용량·구글 문서·PDF/HWP grep 불가·웹 AI에서 못 씀).
2. **자료를 직접 가진다.** 경쟁사 대부분은 남의 SaaS 권한을 복사해 오는 색인이다. 우리는 파일이 여기 있고 권한도 여기서 정한다.
3. **공유 범위가 넓어지는 쓰기를 사람이 승인.** 문서로 확인되는 제품 없음(같은 사용자의 "확인" 클릭이나 일반 "민감한 쓰기"
   승인뿐). 단, 따라 하기 쉬움.
4. **관계 하나하나까지 사람별로 거르는 그래프를 바깥 AI에.** Glean만 있음(100석 이상, 사용자당 월 $45–75 추정). 오픈소스
   그래프는 사람별 권한이 사실상 없음.
5. **IT 담당자 없는 5–50명 사무실용 상자.** 한국 온프렘 업체(올거나이즈, 솔트룩스, 코난, 삼성SDS)는 대기업·금융·공공용.
   작은 사무실·병원용 상품은 못 찾음.

## 4. 구성 요소

### 4.1 권한 걸린 셸 — 핵심
- **사람별 가상 파일시스템**: 그 사람이 읽을 수 있는 파일만 있는 트리. 권한 없는 폴더는 이름도 없다(지금 "없음 = 권한 없음"
  원칙 그대로). 트리는 요청마다 권한 함수로 만든다(규칙이 바뀌면 바로 반영).
- **가상 bash**: Vercel `just-bash`(TypeScript, Apache-2.0)처럼 서버 안에서 흉내 내는 셸. `ls, cat, head, tail, grep/rg, find,
  wc, sort, uniq, sed, awk, jq, diff, 파이프, 리다이렉트`. 진짜 프로세스를 띄우지 않으므로 샌드박스·전용 계정이 필요 없다.
  우리 서버(Bun)에 바로 붙는다.
- **문서도 글자로**: `cat 계약서.pdf`, `grep -r 견적 고객사/`가 PDF·Word·Excel·PowerPoint·HWP 본문에 닿는다(이미 있는 텍스트
  캐시). 원본 바이트가 필요하면 `cat --raw`.
- **쓰기는 서버를 거친다**: `>`, `sed -i`, `cp`, `mv`, `rm`은 파일 서비스로 가서 권한 확인, 버전 기록, 휴지통, 공유 범위 확인을
  그대로 탄다. 한 명령이 여러 파일을 바꾸면 한 번에 묶어 기록한다.
- **어디서나 같은 셸**: 셸이 서버에서 돌기 때문에 claude.ai·ChatGPT(자기 클라우드에서 부름)도, 노트북 Claude Code도 MCP의
  `bash` 도구 하나로 똑같이 쓴다. CLI에서는 `ax sh`.
- **Python 등 진짜 실행은 2단계**: 필요하면 WASM Python(just-bash 옵션) 또는 그 사람 범위만 복사한 격리 실행. v1은 셸 명령까지.
- 조사에서 나온 원칙: **권한은 도구가 아니라 파일시스템 단계에서 거른다.** 도구마다 규칙을 거는 방식은 셸을 열면 우회된다
  (LangChain deepagents 사례).

### 4.2 나머지 입구
- **파일 도구**: 지금의 list, glob, grep, read, write, edit, search, make_file, share_file … 을 그대로 MCP로(셸이 어려운 AI용).
- **REST API**: 웹 화면이 쓰는 `/api/files/*`. 토큰 인증(`Authorization: Bearer`)은 이미 있다. 공개 문서와 버전 정책만.
- **`ax` CLI**: `ax ls/cat/grep/put/search/sh`. REST를 감싼 얇은 프로그램.

### 4.3 신원
- **사람별 OAuth 2.1**: claude.ai(Team/Enterprise는 owner가 커넥터를 추가하고 각 멤버가 자기 계정으로 로그인)와
  ChatGPT(Business 이상, 관리자가 developer mode를 켬)에 필요한 유일한 방식. MCP 스펙 2026-07-28 기준: 세션 없음, 클라이언트
  ID 메타데이터 문서 우선 + 자동 등록은 예비. 직접 다 만들지 말고 검증된 부품을 쓴다.
- **개인 접근 토큰**: Claude Code(`claude mcp add --transport http … --header "Authorization: Bearer …"`), Codex, CLI용.
  이름, 만료, 범위.
- **범위 줄이기**: 토큰마다 "읽기만", "이 폴더만", "30일". 사람 권한보다 넓어지지 않는다(교집합).
- **서비스 계정**: 사람이 아닌 자동화. 관리자가 그룹·폴더 규칙으로 권한을 준다.

### 4.4 안전장치
- **공유 범위가 넓어지는 쓰기 = 사람 승인**: 밖의 AI에는 채팅 카드를 못 띄우므로, MCP는 "확인 필요"로 답하고 사람이 웹·앱
  알림에서 승인한다(MCP 2026-07-28의 `input_required` 흐름을 지원하는 클라이언트는 그 안에서). read-scope는 채팅 대신 연결
  단위로.
- **폴더별 "바깥 AI 금지" / "로컬 모델만"**: 아래 6절의 정직한 약속을 위해.
- **감사 기록**: 누가, 어느 AI(연결 이름)로, 무엇을 읽고 썼는지. 셸 명령은 명령 줄과 닿은 파일 목록으로.
- **열쇠 끊기**: 퇴사·노트북 분실 때 그 사람 연결 전부 즉시.
- **대량 읽기 경보**: 짧은 시간에 평소보다 많은 파일을 읽는 연결.

### 4.5 그래프 (차별점, 2단계)
- 노드: 문서, 사람, 프로젝트, 그룹(고객은 v2, 팀별 사전으로).
- **v1은 구조로만 만든다**(LLM 추출 없음): 문서 안 팀 경로 링크, 사람 이름 언급, 같은 프로젝트·폴더, 버전·파생. Glean도
  주로 구조로 만들고, Microsoft LazyGraphRAG는 색인 비용을 일반 벡터 검색 수준으로 낮췄다. LLM 추출은 나중에 선택.
- **권한은 관계(엣지)에**: 각 관계는 근거 문서를 기록하고, 근거를 하나도 못 보는 사람에게는 그 관계가 없다. 검색 결과를
  나중에 거르지 않고 **탐색 한 걸음마다** 거른다. 여러 문서에서 추론된 사실("X 프로젝트를 누가 하나")이 새는 것도 주의.
- 그래프는 검색을 대신하지 않는다: 단순 사실 찾기는 그래프와 글 조각 검색이 비슷하고, 복잡한 추론·요약에서 그래프가 낫다
  (GraphRAG-Bench, ICLR 2026). 섞어서 쓴다.
- 셸에서도: `ax related 계약서.pdf`, MCP `related(path)`, `graph_search(name)`.

### 4.6 지금 채팅 화면
버리지 않는다. 같은 입구(셸 포함)를 쓰는 **우리 클라이언트**가 된다. 비개발 직원(치과 데스크 등)에게는 이게 제품이다.

## 6. 보안과 "자료가 사무실 안에" 약속

- **좋아지는 것**: 엔진이 맥 미니 안에서 돌지 않으면 "엔진이 도구를 우회하는" 위협이 사라진다. 가상 셸은 진짜 프로세스가
  아니라서 탈출할 OS가 없다. 서버에 닿는 길은 입구 하나.
- **정직하게 말할 것**: claude.ai·ChatGPT는 자기 클라우드에서 접속하므로 상자는 인터넷에서 닿아야 하고(Cloudflare 터널),
  **에이전트가 읽은 내용은 그 AI 회사로 간다.** 그래서 문구는 "저장·권한 판단·기록은 사무실에. 에이전트가 읽은 내용은 그 AI
  회사로." 민감한 폴더는 "바깥 AI 금지" 또는 "로컬 모델만"(맥 미니 안의 모델)으로 묶는다.
- **새로 생기는 위협과 대응**
  1. 바깥 AI가 자료를 다른 데로 옮김(그 AI의 웹·메일 도구): 감사, 토큰 범위, 대량 읽기 경보, 폴더별 바깥 AI 금지.
  2. 토큰 도난: 짧은 만료 + 갱신, 해시만 저장, 연결별 끊기, 새 장소 접속 알림.
  3. 문서 속 숨은 지시: 바깥 AI의 다른 도구는 우리가 못 끈다 → "더 넓은 곳에 쓰기 = 사람 승인"이 더 중요.
  4. 공개 주소: 터널 뒤, 입구 속도 제한, 보안 시험(`tests/security`)을 MCP·REST·CLI·셸 모두에.
  5. 셸 특유: 경로 장난(`..`, 링크, 유니코드)은 지금 경로 퍼저를 셸 경로에도 돌린다. 무거운 명령(`grep -r` 전체)은 시간·출력
     한도.

## 7. 사업 측면

- **요금**: 지금 상품("owner 구독 하나로 팀 전체", 우리 채팅)과 새 상품("어떤 AI든 연결", 사람마다 자기 AI 구독)을 같이.
- **약관**: 구독 나눠 쓰기의 Anthropic·OpenAI 약관 확인 필요. 새 방식은 각자 자기 구독이라 문제없다.
- **경쟁 위험**: MS·Google이 이미 내는 좌석 요금에 에이전트 연결을 끼워 준다. 설치형 대안 Onyx를 Zoom이 인수(2026-09).
  승인 기능은 따라 하기 쉽다. → 셸 + 상자 + 그래프의 조합과 작은 사무실 설치 경험으로 승부.
- **한국**:
  - 온프렘을 법이 강제하지는 않는다(인증 클라우드 EMR 있음). 대신 2026-12-10부터 의료기록은 열람만 해도 기록을 남겨야 함
    (시행규칙 개정안, 작은 의원 예외 여부 확인 필요) → 우리 감사 기록이 맞는 판매 포인트.
  - 건강 정보는 개인정보보호법상 민감정보.
  - **AI 바우처**(도입비 최대 80% 지원) 공급기업 등록을 검토. 작은 사무실은 총판·바우처로 산다.
  - 치과의 핵심인 환자 기록은 EMR 업체에 있다. 상자에 담기는 건 그 밖의 문서(규정, 계약, 인사, 마케팅). EMR 연동은 별도 과제.
  - HWP는 기본으로 기대된다(이미 지원).

## 8. 단계

| 단계 | 기간(추정) | 내용 | 끝났다는 기준 |
|---|---|---|---|
| 0. 실험 | 3–5일 | ① 지금 팀 도구를 원격 MCP(HTTP) + 개인 토큰으로 ② 사람별 가상 파일시스템 + just-bash로 `bash` 도구(읽기 전용) ③ staging에서 노트북 Claude Code로 연결 | 2026-10-22에 한 kim/경영 권한 시험이 `bash`로도 통과(`grep -r SECRET` 0건, `ls groups/` 에 경영 없음), 큰 폴더 `grep -r` 응답 시간 측정 |
| 1. MVP | 3–4주 | 셸 쓰기(서버 경유), OAuth(claude.ai·ChatGPT 커넥터), 개인 토큰 화면, 연결별 감사·끊기, 승인 링크, 폴더별 바깥 AI 금지, `ax` CLI, 입구·셸 보안 시험, 안내서 | 치과가 아닌 시범 팀 1곳의 파워유저 2명이 1주일 자기 AI로 씀 |

| 3. 운영 | 계속 | 서비스 계정, 토큰 범위, 변경 알림, 대량 읽기 경보, Python 실행, 요금, AI 바우처 등록 | — |
