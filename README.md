## Set up once. Your whole team gets it.

**One AI account for the whole team.** Connect one Claude or OpenAI API key, or a plan whose terms allow it, and everyone asks with it, with token limits per person, group or team.

One person sets things up on the team server. Everyone's AI has it from their first question, in the browser or the apps. Nobody else installs Claude Code or copies skills; at most they sign in to their own accounts.

## What everyone does with it

**Pick up where a teammate left off.** Open a teammate's AI session in a team project and keep going: the whole conversation and every answer so far are there, and each new answer runs with the access of the person who asked. Share any other session with people or groups, like a file in Google Drive.

<img src="docs/images/readme/v4/shared-sessions.gif" width="100%" alt="Mina opens Sam's project session and keeps editing the card news; her turns run with her access.">

**Ask beside any room, send in one click.** A side chat only you see; one click sends Trina's answer into the room.

<img src="docs/images/readme/v4/room-share.gif" width="100%" alt="In the Expo booth crew room, Mina asks Trina in a side chat only she sees to turn the exhibitor rules into a checklist, then sends it to the room.">

**Each person's AI sees only what they may open.** Mina can't open Finance, so neither can her AI. [How permissions work](docs/PERMISSIONS.md)

<img src="docs/images/readme/v4/folder-access.gif" width="100%" alt="An admin changes who can open the Sales folder, then checks what Mina can open: Finance is not on her list.">

**Files found by what they are.** Every night the team's AI reads new and changed files in shared, group and project folders and keeps one line per file saying what it is, so a scan named `temp.pdf` or a photo named `IMG_2031.jpg` is found by its content. It uses the team's AI account and never reads personal folders. In a test with 2,238 made-up files, Claude Code found the right file for 181 of 184 questions with these lines, and for 172 without them.

- **Every change is kept.** By a person or their AI; bring back any version.
- **In-app browser.** In the desktop app, Trina opens websites in a pane beside your chat, reads them, clicks and fills in forms while you watch; Stop ends it. It asks before a new site unless you allow all websites.
- **Your AI apps, in your own browser.** Link your Chrome, Edge or Brave profiles to Trina once; then Trina's AI, Claude Code, Codex and Claude can all work in them, signed in as you. Pick the account for each step, run several sessions side by side (each in its own window), and approve a new site once for every app. [How](docs/site/agents/mcp-connector.md#your-browser-profiles)
- **Apps post into rooms.** Sentry, GitHub, Stripe, Jira and HubSpot updates arrive as cards.
- **Find work files.** The desktop app finds recent work files on your computer and adds the ones you pick.
- **Documents.** Reads Hangul (HWP/HWPX) text; previews PDF and PowerPoint.
- **Every device.** Mac, Windows, Linux, iPhone, Android and any browser, in six languages.

## Get started

- **Try it in your browser:** nothing to install; a fictional team with the AI off. [Open the demo](https://ax.trina.app/demo/)
- **Trina hosting:** no server to run. 14-day free trial, then a monthly plan. [Pricing](https://ax.trina.app/pricing)
- **Apps:** [Mac, Windows, Linux, iPhone, Android](https://ax.trina.app/download), or any browser.
- **Self-host:** your own Linux server, a Windows PC, Docker or an office Mac. Free. [Linux](docs/INSTALL-LINUX.en.md) · [Windows PC](docs/INSTALL-WINDOWS.md) · [Docker](docs/INSTALL-DOCKER.md) · [Office Mac](docs/OFFICE.en.md) · [Install with your AI agent](docs/INSTALL-LINUX.en.md#install-with-your-ai-agent)

<b>Self-host with Docker</b> (Linux, or a Mac with OrbStack)

```sh
git clone https://github.com/trina-app/trina-ax.git && cd trina-ax/docker
cp env.example .env && docker compose up -d --build
docker compose exec trina-ax trina-ax-setup-link   # open the link and create the owner
```

Newer and less tested than the Linux install; an Ubuntu 24.04 server needs one host setting first. [Docker guide](docs/INSTALL-DOCKER.md)

<b>Try it on your computer in 10 minutes</b> (fictional team, AI off)

```sh
git clone https://github.com/trina-app/trina-ax.git && cd trina-ax
bun install --frozen-lockfile && bun run demo   # → http://127.0.0.1:19760 · alice / teamax-demo-1
```

Needs Bun 1.3.12 and Go 1.27+. Not a production install. [Walkthrough](docs/QUICKSTART.md)

## How it works

One server runs Claude Code and Codex as the engine. Every file request, from a person or their AI, goes through one permission check on the server. On a Linux server the engine runs as its own account inside a bubblewrap, Landlock and seccomp sandbox, with its shell and built-in file tools turned off: it reaches files only through Trina's tools. [Security and permissions](docs/security-and-permissions.md)

Trina provides the workspace, not the AI: connect Claude or OpenAI accounts and plans authorized for your use. AI usage is billed by the account you connect.

<details>
<summary><b>Data, limits and what we don't promise</b></summary>

### What we don't promise

- Self-hosting is not offline: the context a request needs goes to the AI provider you connect, and configured integrations receive their requests. Each Codex web search sends the conversation so far to OpenAI's search service. With OpenRouter for speech, allowed by an admin, the sound of video and audio files goes to OpenRouter. The server asks `updates.trina.app` for its own public address every 30 minutes (`MYCEL_EXIT_ADDRESS_CHECK=off` turns that off). [Details](docs/security-and-permissions.md)
- Server operators can read stored files and chats, including Trina operators for hosting. App admins don't get a browser for everyone's private conversations.
- Removing folder access does not erase earlier answers. The wider-sharing check is not universal data-loss prevention.
- No security certification, perfect answers, guaranteed savings or automatic legal, financial or HR decisions. Review outputs and deployment boundaries.
- Linux servers run no OCR: the AI sees photos and scanned pages as images, but they are not text-searchable. Office Macs cannot read video yet.
- HWP/HWPX text works for every team; [previews and making Hangul documents](resources/hwp/README.md) need the optional HWP Preview plugin (macOS, or Linux with glibc 2.39+; not Debian 12).
- Connections: a person's own eligible connection comes first, then one assigned to the person, a group, then the whole team. On fresh Trina teams, one company connection can serve the whole team by default; existing saved choices persist. **This software setting does not grant permission under Anthropic's or OpenAI's terms.** [Connection details](docs/FAQ.md)
- Linux self-hosting needs Debian 12/13 or Ubuntu 24.04, systemd with cgroup v2, amd64 or arm64, 4 GB RAM and 20 GB disk. Your IT team installs, updates and restores backups.

</details>
