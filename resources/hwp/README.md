# HWP preview runtime

**HWP preview is the HWP Preview plugin** (`app.trina.hwp-preview`, [docs/PLUGINS.md](../../docs/PLUGINS.md)). This folder holds the pins core enforces (`manifest.json`: rhwp archive and executable SHA-256 per target, font identity) and the third-party bytes the plugin build packs: the font and the notices. Core keeps the `rhwp-v1` adapter, preflight, limits and isolation (`server/src/files/hwp-*.ts`); a package whose executable or font differs from these pins is refused.

**Cleared 2026-10-30 by the founder (`clearance.json`, docs/DECISIONS.md "HWP Preview cleared").** All four targets may be redistributed as the HWP Preview plugin. The font-width tables compiled into rhwp have unknown provenance for most entries; the founder accepts that as a known risk while the question is open upstream (edwardkim/rhwp#8387). Server, office and desktop bundles still never include the rhwp executable, this font or any plugin package: the official list (`resources/plugins/catalog.json`) pins each target's package digest and download address on the release feed, and a server downloads the package only when an admin installs it from Admin > Plugins (`scripts/plugins/release-hwp.ts` builds the four packages and writes the pins). At runtime the plugin turned on is the only switch; the old `MYCEL_HWP_PREVIEW` gate is gone. Isolation, preflight, limits and these pins apply as before; the plaintext write/edit protection and HWP text reading are always on. Not yet run end to end on real hardware: Linux amd64 with the converter cgroup, and an Intel Mac.

Development: `bun run prepare:hwp` installs only the pinned CLI for the current OS/CPU into ignored `native/bin/hwp`. `bun run plugin:hwp` packs it with this font and notices into a test-signed `.trinaplugin` (developer test key outside the repository). A server downloads software only when an admin installs the plugin from the official list, and only the pinned build.

The upstream Linux 0.8.7 executables require **glibc >= 2.39** (Ubuntu 24.04 / Debian 13). Debian 12 ships glibc 2.36: **BLOCKED for previews** pending a reproducible native-skia build against that baseline, new executable checksums and smoke tests. The rest of Trina and original downloads remain available; startup verification fails closed. Do not claim Debian 12 preview support or change the product-wide OS floor to hide this limitation.

Pin updates require archive and executable hashes for every target, internal font identity checks, fixture/corruption/security/visual tests and new notices. After any change to the executable, font, notices or the HWP entry's texts in the official list, run `bun scripts/plugins/release-hwp.ts` and commit the new pins (a unit test fails until the pins match this checkout's build), then publish the new files. The CLI archive alone does not contain its third-party notices.

## Notices

`notices/` holds what the package ships for exactly the pinned executable (index: `notices/THIRD_PARTY_NOTICES.md`; provenance and the open font-metric question: `notices/SOURCE-OFFER.txt`). On a pin update:

1. Find the upstream workflow run that built the release archives and confirm its source commit, cargo features and archive hashes (the v0.8.7 archives come from a later run than the tag push).
2. With a Rust toolchain and the rhwp source at the pinned commit: `bun scripts/plugins/hwp-notices.ts --rhwp <checkout>` regenerates `rust-crates.txt` and `rust-crates.json` (`--check` verifies them).
3. If skia-bindings changed: take the third-party revisions from its Skia tag's `DEPS`, list the objects in the matching skia-binaries archives, then check which of them the linker kept in each pinned executable (`nm -a`: symbols and source-file entries; the static libraries hold more than the executables, e.g. ICU is built but not linked in 0.8.7). Refresh `native-libraries.txt` and the C/C++ entries in `HWP_COMPONENTS` (`scripts/plugins/build-hwp.ts`). Copy the Rust toolchain's `share/doc/rust/COPYRIGHT-library.html` when the Rust version changes.
4. Read the NOTICE/COPYRIGHT files that `rust-crates.txt` reproduces: a crate's declared licence can omit parts under another licence (svg2pdf's NOTICE puts part of `draw_path` under MPL-2.0). The test refuses copyleft text that `HWP_COMPONENTS` does not declare.
5. `bun test tests/unit/hwp-notices.test.ts`.

Limits and stable diagnostics: shared/src/hwp.ts. One active preview per server; requests over the limit receive busy and can retry. A fresh bounded process runs each preflight/info/page stage. Linux production requires its existing delegated converter cgroup and bwrap. macOS uses sandbox-exec plus RSS/work-directory watchdogs; those polling limits are not hard OS quotas.
